Use Playwright Test for browser components, Hooks, layout, and interactions; use `bun:test` for standalone logic, SSR, and Bun
runtime checks. Keep tests beside their source, with `.spec.ts` and
`.test.ts` extensions respectively, instead of a dedicated test directory.

## Step 1: Prepare the environment

Install dependencies and browsers from the repository root:

```bash
bun install
bunx playwright install chromium webkit
```

Playwright Test runs in Node.js. Bun handles package management, non-browser tests, and building
and serving test pages. The installed Playwright version manages browser versions.

## Step 2: Understand file responsibilities

Existing `@momots/design` tests use this structure:

| File | Responsibility |
| --- | --- |
| `playwright.config.ts` | Root configuration: collects `*.spec.ts`, configures Chromium, WebKit, and the page server |
| `packages/design/playwright.server.ts` | Uses Bun to build browser entries, compile styles, prepare SSR HTML, and serve HTTP |
| `packages/design/playwright.fixture.ts` | Extends the official `test`, loads a page for each test, and waits for the entry to be ready |
| `packages/design/src/components.fixture.tsx` | Shared browser entry importing real components and exposing mounting operations |
| `packages/design/src/components/alert.spec.ts` | Alert browser behavior tests |
| `packages/design/src/components/alert.test.ts` | Alert non-browser tests |

When a component or Hook needs its own entry, place `*.fixture.tsx` beside its source too. The entry is
compiled into a browser module by `Bun.build`, then loaded over HTTP by the test page. Package builds exclude test
files and these browser entries.

Keep `momo.config.ts` for build configuration; browser tests use the official Playwright configuration directly.

## Step 3: Use the page fixture

Existing browser tests import `test` and `expect` from the package's `playwright.fixture.ts` and receive
`page` through test arguments. Playwright creates a separate BrowserContext
and Page for each test by default; the Bun page server and compiled assets are shared for the run.

Components mount in the browser entry. Tests can use `page.locator()` to operate on elements and
`page.evaluate()` to read the DOM, call entry operations, or collect layout data, then assert
the results. Test functions themselves run in Node.js and cannot access `document` directly.

Non-browser tests import APIs from `bun:test`. The root `bunfig.toml` excludes `*.spec.ts`,
so each runner collects only its own tests; `typecheck:spec` separately checks type contracts.

## Step 4: Run existing tests

Run each design check from the repository root:

```bash
bun run --filter './packages/design' typecheck:spec
bun run --filter './packages/design' test:unit
bun run --filter './packages/design' test:browser
```

Run all design checks:

```bash
bun run --filter './packages/design' test
```

Run a single browser test file or engine:

```bash
bunx playwright test packages/design/src/components/alert.spec.ts
bunx playwright test packages/design/src/components/alert.spec.ts --project=chromium
```

The root configuration retains traces and screenshots on failure. View the HTML report with:

```bash
bunx playwright show-report
```
