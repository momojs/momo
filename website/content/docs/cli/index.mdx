`@momots/cli` provides `momo build`, unifying declaration generation and the `Bun.build` workflow for MomoTS packages.

Use `momo doctor` to check build configuration and local artifacts. Its `--json` output makes diagnostics easy to consume in CI.

In a workspace, `momo topology --filter './packages/*'` builds packages sequentially in dependency order; `--dry-run` only displays the build plan.

Keep tests beside source files: use `bun:test` and `*.test.ts` for non-browser tests, and [Playwright Test](https://playwright.dev/docs/intro) with `*.spec.ts` for browser tests. `momo` handles builds; test configuration lives in a separate `playwright.config.ts`.

## Prerequisites

- Bun 1.3.12 or later.
- `momo build` uses `Bun.build`, so the CLI supports Bun only.

## Installation

```bash
bun add -d @momots/cli
```

## Three steps to get started

### 1. Create `momo.config.ts`

```ts
import { defineConfig } from '@momots/cli';

export default defineConfig({
  build: {
    target: 'browser',
  },
});
```

### 2. Add scripts

```json
{
  "scripts": {
    "build": "momo build",
    "typecheck": "tsc --noEmit",
    "types": "tsc --emitDeclarationOnly"
  }
}
```

### 3. Build

```bash
bun run build
```

The default workflow cleans `dist`, runs `typecheck` and `types`, then builds TypeScript entries from `src` into `dist`.

Continue with the [browser testing tutorial](/docs/cli/tutorial) or the [CLI guide](/docs/cli/guide).
