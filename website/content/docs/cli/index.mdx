`@momots/cli` 提供 `momo build`，统一 MomoTS 包的类型生成与 `Bun.build` 流程。

使用 `momo doctor` 检查构建配置和本地产物，使用 `momo tarball` 验证实际发布包。doctor 支持 `--json` 输出，便于在 CI 中读取诊断结果。

在 workspace 中使用 `momo topology --filter './packages/*'`，可以按包之间的依赖顺序串行构建；`--dry-run` 只显示构建计划。

需要真实 DOM、布局、滚动或浏览器全局对象的测试由 [`bunwright`](https://bunwright.jonasperusquia.com/guides/getting-started/) 驱动，不再由 `momo` 提供测试命令。

## 前置条件

- Bun 1.3.12 或更高版本。
- `momo build` 使用 `Bun.build`，因此 CLI 仅支持 Bun。

## 安装

```bash
bun add -d @momots/cli
```

## 三步上手

### 1. 写配置 `momo.config.ts`

```ts
import { defineConfig } from '@momots/cli';

export default defineConfig({
  build: {
    target: 'browser',
  },
});
```

### 2. 添加脚本

```json
{
  "scripts": {
    "build": "momo build",
    "typecheck": "tsc --noEmit",
    "types": "tsc --emitDeclarationOnly"
  }
}
```

### 3. 构建

```bash
bun run build
```

默认流程会清理 `dist`、运行 `typecheck` 与 `types`，再把 `src` 下的 TypeScript 入口构建到 `dist`。

继续阅读 [浏览器测试教程](/docs/cli/tutorial) 或查阅 [CLI 向导](/docs/cli/guide)。
