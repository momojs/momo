## CLI 命令

| 命令 | 说明 | 退出码 |
| --- | --- | --- |
| `momo build` | 读取最近的 `momo.config.*` 并构建当前包 | 成功 `0` / 出错 `1` |
| `momo help` / `-h` / `--help` | 显示帮助 | `0` |
| *(无命令)* | 显示帮助 | `1` |

`momo build` 接受 `-c, --config <path>` 显式指定配置文件；未指定时会从当前目录向上查找 `momo.config.ts`、`momo.config.mts`、`momo.config.js` 或 `momo.config.mjs`。

```bash
momo build
momo build -c packages/host/momo.config.ts
momo --help
```

## 配置

`defineConfig` 原样返回配置，并提供类型推导与自动补全：

```ts
import { defineConfig } from '@momots/cli';

export default defineConfig({
  build: {
    src: 'src',
    outdir: 'dist',
    format: 'esm',
    target: 'browser',
    packages: 'external',
    splitting: false,
    scripts: ['typecheck', 'types'],
    assets: {
      'assets/tailwind.css': 'tailwind.css',
    },
    executables: [],
  },
});
```

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `src` | `src` | 源码目录 |
| `outdir` | `dist` | 产物目录 |
| `format` | `esm` | `esm`、`cjs` 或 `iife` |
| `target` | `browser` | `browser`、`bun` 或 `node` |
| `packages` | `external` | 外部化或打包依赖 |
| `splitting` | `false` | 为多个 ESM 入口提取共享 chunk，保留跨入口引用身份 |
| `banner` | — | 添加到每个 JavaScript 产物顶部的文本，例如 `'use client';` |
| `scripts` | `['typecheck', 'types']` | 构建前执行的 package scripts |
| `assets` | `{}` | 构建后复制的静态文件；键相对包根目录，值相对 `outdir` |
| `executables` | `[]` | 构建后设置为可执行文件的相对路径 |

构建器递归收集 `src` 中的 `.ts` 与 `.tsx` 文件，忽略声明文件和 spec，并保持目录结构输出。

## 浏览器测试

CLI 不提供测试运行器。普通测试使用 `bun:test`；需要浏览器的用例使用 `bun:test` 管理测试生命周期，并用 bunwright 创建页面。完整示例见 [浏览器测试教程](/docs/cli/tutorial)。
