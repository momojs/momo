## CLI 命令

| 命令 | 说明 | 退出码 |
| --- | --- | --- |
| `momo build` | 读取最近的 `momo.config.*` 并构建当前包 | 成功 `0` / 出错 `1` |
| `momo doctor` | 只读检查构建配置、依赖规则与本地产物 | 无错误 `0` / 有错误 `1` |
| `momo tarball` | 打包当前包，并在干净消费项目中验证发布产物 | 成功 `0` / 出错 `1` |
| `momo topology` | 按 workspace 依赖顺序串行执行各包的 build 脚本 | 成功 `0` / 图或参数错误 `1` / 构建失败透传退出码 |
| `momo help` / `-h` / `--help` | 显示帮助 | `0` |
| *(无命令)* | 显示帮助 | `1` |

`momo build`、`momo doctor` 和 `momo tarball` 接受 `-c, --config <path>` 显式指定配置文件；相对配置路径以当前工作目录为基准。未指定时会从当前目录向上查找 `momo.config.ts`、`momo.config.mts`、`momo.config.js` 或 `momo.config.mjs`。构建配置中的路径以配置文件所在目录为基准。

```bash
momo build
momo build -c packages/host/momo.config.ts
momo doctor
momo doctor --json -c packages/host/momo.config.ts
momo tarball
momo tarball --keep
momo tarball --destination ./artifacts
momo topology --filter './packages/*'
momo topology --filter '@momots/drive' --dry-run
momo --help
```

## 配置

`defineConfig` 原样返回配置，并提供类型推导与自动补全：

```ts
import { defineConfig } from '@momots/cli';

export default defineConfig({
  build: {
    src: 'src',
    outdir: 'dist',
    format: 'esm',
    target: 'browser',
    packages: 'external',
    splitting: false,
    scripts: ['typecheck', 'types'],
    assets: {
      'assets/tailwind.css': 'tailwind.css',
    },
    executables: [],
  },
  tarball: {
    imports: ['.', './subpath'],
    forbidImports: ['@momots/internal-package'],
    identities: [
      { export: 'example', from: ['.', './subpath'] },
    ],
  },
});
```

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `src` | `src` | 源码目录 |
| `outdir` | `dist` | 产物目录 |
| `format` | `esm` | `esm`、`cjs` 或 `iife` |
| `target` | `browser` | `browser`、`bun` 或 `node` |
| `packages` | `external` | 外部化或打包依赖 |
| `bundle` | `[]` | 内联进产物的包名；设置后会打包这些包，并把其余声明依赖标为 external |
| `external` | `[]` | 额外保持外部化的包名 |
| `splitting` | `false` | 为多个 ESM 入口提取共享 chunk，保留跨入口引用身份 |
| `banner` | — | 添加到每个 JavaScript 产物顶部的文本，例如 `'use client';` |
| `scripts` | `['typecheck', 'types']` | 构建前执行的 package scripts |
| `assets` | `{}` | 构建后复制的静态文件；键相对包根目录，值相对 `outdir` |
| `executables` | `[]` | 构建后设置为可执行文件的相对路径 |

构建器递归收集 `src` 中的 `.ts` 与 `.tsx` 文件，忽略声明文件和 spec，并保持目录结构输出。

## Workspace 拓扑构建

拓扑顺序指依赖包先于使用它的包构建。`momo topology` 从当前目录向上查找声明 `workspaces` 的 `package.json`，收集 workspace 成员后，按依赖顺序串行执行各包已有的 `bun run build`。包级构建行为仍由自己的 `scripts.build` 决定。

```bash
# 构建所有 workspace 成员
momo topology

# 只选择库包及其上游依赖
momo topology --filter './packages/*'

# 从任意子目录选择一个包；自动包含它的上游依赖
momo topology --filter '@momots/drive'

# 只显示顺序，不执行脚本
momo topology --filter './packages/*' --dry-run
```

`--filter`（`-f`）按包名或相对 workspace 根目录的路径 glob 匹配，可重复指定，结果取并集。应给 glob 加引号，防止 shell 提前展开。筛选后会递归加入所有本地上游依赖，因此依赖包可以位于筛选范围之外；每个包只执行一次。未匹配任何包的 filter 会报错。命令行 filter 不支持 `!` 排除表达式。

依赖图读取 `dependencies`、`devDependencies`、`peerDependencies` 和 `optionalDependencies`。只要依赖名与 workspace 包名相同，就建立构建顺序约束，不要求使用 `workspace:*`；例如 `host` 对 `core` 的普通版本范围 peer 也需要先构建 `core`。此命令按名称建立本地构建关系，不进行版本解析或依赖安装。

workspace 声明支持路径数组和 `{ "packages": [...] }`，也支持 `!` 路径排除规则。仓库根包不作为成员构建，避免再次调用根构建脚本。没有 build 脚本的包参与依赖排序、显示为跳过；它的上游依赖仍然会被处理。

执行前会检查重复包名、无效 manifest、所选依赖图中的循环和缺失的显式 `workspace:` 依赖。循环错误包含完整的闭环路径。检查通过后才执行脚本；首个构建失败立即停止，返回该脚本的退出码。构建脚本内递归执行 `momo topology` 会报错，避免无限调用。

当前仓库根目录的 `build` 脚本为：

```json
{
  "scripts": {
    "build": "bun run ./packages/cli/src/bin.ts topology --filter './packages/*'"
  }
}
```

从 CLI 源码启动允许在尚无 `dist` 时开始构建。当前依赖图自动得到 `cli → core → host → design → drive` 的顺序；新增包或调整依赖时无需手动改写构建链。根构建仍限定库包，不主动选择 examples 或 website。所有包串行执行，避免下游在上游清理 `dist` 时读取到缺失的声明文件。

## 本地诊断

`momo doctor` 检查当前包能否按配置构建，以及已有产物是否与配置一致。它不调用 build、package scripts 或 `tarball.check`，不安装依赖，也不创建、清理或修复文件。与其他命令一样，它会执行配置模块的顶层代码，因此应使用可信且没有顶层副作用的配置；使用 `--json` 时也应避免配置向标准输出打印内容。

检查范围包括：

- `build` 字段的运行时类型和值；未知顶层字段和构建字段给出警告；
- 构建脚本是否在 `package.json#scripts` 中声明；未配置时检查 `typecheck` 与 `types`；
- `bundle` 和 `external` 是否冲突，包括 external 通配符与包子路径；未声明的 bundle 包给出警告，`devDependencies` 中声明的包也被认可；
- 源码目录及构建入口是否存在；
- outdir 是否与包根或源码重叠，资源目标与可执行文件是否越出 outdir；路径检查会解析现有符号链接；
- 资源来源是否为文件、是否会在构建清理时被删除；
- 已有产物中的可执行文件及其权限；
- package exports 中的文件目标是否存在，包括嵌套条件和数组内声明的目标；通配符目标至少应匹配一个文件。

尚不存在 outdir 时只给出一次警告，并暂缓检查该目录内的 exports 和可执行产物。运行 `momo build` 后再次诊断即可检查这些文件。outdir 已存在时，缺失的导出或可执行文件视为错误；包外 outdir 则给出清理范围警告。`scripts: []` 且未设置非空 `bundle` 的构建允许没有 `package.json`。

有错误时退出码为 `1`；没有错误（即使有警告）时退出码为 `0`。`momo doctor --help` 显示命令帮助，`--json` 在标准输出提供结构化报告：

```json
{
  "root": "/workspace/packages/example",
  "config": "/workspace/packages/example/momo.config.ts",
  "ok": true,
  "summary": { "errors": 0, "warnings": 1 },
  "diagnostics": [
    {
      "severity": "warning",
      "code": "output.missing",
      "message": "尚无输出目录；请运行 momo build 后再检查产物。",
      "path": "/workspace/packages/example/dist"
    }
  ]
}
```

每条诊断包含 `severity`、`code`、`message`，以及可选的 `path`（相关文件或配置字段）。`ok` 表示没有错误；未找到配置时 `config` 为 `null`。配置加载失败、无效命令参数等错误也使用同一报告结构。CI 可以根据退出码判断成功与否，或按 `code` 处理特定问题。

doctor 只检查本地配置与文件，不验证发布文件清单、依赖安装或运行时导入。发布前继续使用 `momo tarball` 检查实际打包后的消费行为。

## Tarball 校验

`momo tarball` 使用 `bun pm pack --ignore-scripts` 创建 tarball，随后将它解压到临时消费项目。命令默认执行以下检查：

- 发布后的 `package.json` 不含 `workspace:` 依赖；
- 每个非通配符 export 指向的文件真实存在；
- 配置的禁止依赖没有残留在 JavaScript 或声明文件中；
- 包可以从干净消费项目导入；
- 配置的跨入口导出保持引用身份。

默认校验完成后会删除 tarball 和临时消费项目。`--destination <dir>` 永久保存 tarball；`--keep` 同时保留临时目录，适合排查失败。

| `tarball` 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `imports` | 所有静态 exports | 在临时消费项目中动态导入的子路径 |
| `identities` | `[]` | 比较同一导出在多个入口之间的引用身份 |
| `forbidImports` | `[]` | 不得残留在 `dist` JavaScript 或声明文件中的包名 |
| `check` | — | 接收 tarball、解压包和消费项目路径的包级扩展校验 |

`tarball.check` 适合 Tailwind 编译、框架渲染或额外 TypeScript consumer 等包特有断言。通用 pack、解压和清理逻辑应留给 CLI。命令不会隐式执行 build，因此通常先构建，再运行校验：

```json
{
  "scripts": {
    "test:tarball": "bun run build && momo tarball",
    "prepack": "bun run test && bun run test:tarball"
  }
}
```

CLI 内部使用 `--ignore-scripts`，因此从 `prepack` 调用不会递归触发生命周期脚本。

## 浏览器测试

CLI 不提供测试运行器。普通测试使用 `bun:test`；需要浏览器的用例使用 `bun:test` 管理测试生命周期，并用 bunwright 创建页面。完整示例见 [浏览器测试教程](/docs/cli/tutorial)。
