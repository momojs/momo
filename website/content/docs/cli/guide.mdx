## CLI 命令

| 命令 | 说明 | 退出码 |
| --- | --- | --- |
| `momo build` | 读取最近的 `momo.config.*` 并构建当前包 | 成功 `0` / 出错 `1` |
| `momo tarball` | 打包当前包，并在干净消费项目中验证发布产物 | 成功 `0` / 出错 `1` |
| `momo help` / `-h` / `--help` | 显示帮助 | `0` |
| *(无命令)* | 显示帮助 | `1` |

`momo build` 和 `momo tarball` 都接受 `-c, --config <path>` 显式指定配置文件；未指定时会从当前目录向上查找 `momo.config.ts`、`momo.config.mts`、`momo.config.js` 或 `momo.config.mjs`。

```bash
momo build
momo build -c packages/host/momo.config.ts
momo tarball
momo tarball --keep
momo tarball --destination ./artifacts
momo --help
```

## 配置

`defineConfig` 原样返回配置，并提供类型推导与自动补全：

```ts
import { defineConfig } from '@momots/cli';

export default defineConfig({
  build: {
    src: 'src',
    outdir: 'dist',
    format: 'esm',
    target: 'browser',
    packages: 'external',
    splitting: false,
    scripts: ['typecheck', 'types'],
    assets: {
      'assets/tailwind.css': 'tailwind.css',
    },
    executables: [],
  },
  tarball: {
    imports: ['.', './subpath'],
    forbidImports: ['@momots/internal-package'],
    identities: [
      { export: 'example', from: ['.', './subpath'] },
    ],
  },
});
```

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `src` | `src` | 源码目录 |
| `outdir` | `dist` | 产物目录 |
| `format` | `esm` | `esm`、`cjs` 或 `iife` |
| `target` | `browser` | `browser`、`bun` 或 `node` |
| `packages` | `external` | 外部化或打包依赖 |
| `bundle` | `[]` | 内联进产物的包名；设置后会打包这些包，并把其余声明依赖标为 external |
| `external` | `[]` | 额外保持外部化的包名 |
| `splitting` | `false` | 为多个 ESM 入口提取共享 chunk，保留跨入口引用身份 |
| `banner` | — | 添加到每个 JavaScript 产物顶部的文本，例如 `'use client';` |
| `scripts` | `['typecheck', 'types']` | 构建前执行的 package scripts |
| `assets` | `{}` | 构建后复制的静态文件；键相对包根目录，值相对 `outdir` |
| `executables` | `[]` | 构建后设置为可执行文件的相对路径 |

构建器递归收集 `src` 中的 `.ts` 与 `.tsx` 文件，忽略声明文件和 spec，并保持目录结构输出。

## Tarball 校验

`momo tarball` 使用 `bun pm pack --ignore-scripts` 创建 tarball，随后将它解压到临时消费项目。命令默认执行以下检查：

- 发布后的 `package.json` 不含 `workspace:` 依赖；
- 每个非通配符 export 指向的文件真实存在；
- 配置的禁止依赖没有残留在 JavaScript 或声明文件中；
- 包可以从干净消费项目导入；
- 配置的跨入口导出保持引用身份。

默认校验完成后会删除 tarball 和临时消费项目。`--destination <dir>` 永久保存 tarball；`--keep` 同时保留临时目录，适合排查失败。

| `tarball` 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `imports` | 所有静态 exports | 在临时消费项目中动态导入的子路径 |
| `identities` | `[]` | 比较同一导出在多个入口之间的引用身份 |
| `forbidImports` | `[]` | 不得残留在 `dist` JavaScript 或声明文件中的包名 |
| `check` | — | 接收 tarball、解压包和消费项目路径的包级扩展校验 |

`tarball.check` 适合 Tailwind 编译、框架渲染或额外 TypeScript consumer 等包特有断言。通用 pack、解压和清理逻辑应留给 CLI。命令不会隐式执行 build，因此通常先构建，再运行校验：

```json
{
  "scripts": {
    "test:tarball": "bun run build && momo tarball",
    "prepack": "bun run test && bun run test:tarball"
  }
}
```

CLI 内部使用 `--ignore-scripts`，因此从 `prepack` 调用不会递归触发生命周期脚本。

## 浏览器测试

CLI 不提供测试运行器。普通测试使用 `bun:test`；需要浏览器的用例使用 `bun:test` 管理测试生命周期，并用 bunwright 创建页面。完整示例见 [浏览器测试教程](/docs/cli/tutorial)。
