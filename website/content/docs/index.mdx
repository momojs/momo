**momo** is pronounced mo-mo.

## Introduction

React projects contain plenty of code outside components: type guards, data transformations, URL and Storage access, DOM / CSS / Blob handling, request middleware, and package build configuration. This code is often scattered across feature directories, making it difficult to reuse across projects and difficult for bundlers to remove unused parts.

momo organizes these capabilities into independently installable packages:

<Cards>
  <Card title="@momots/core" href="/docs/core">
    Pure data utilities: case conversion, tree operations, guards, singletons,
    and lazy evaluation, without host APIs such as DOM or Fetch.
  </Card>
  <Card title="@momots/host" href="/docs/host">
    Browser / runtime tools: environment guards, storage wrappers, URLs, binary data, CSS
    colors, fingerprints, and fetch-to-cURL conversion.
  </Card>
  <Card title="@momots/drive" href="/docs/drive">
    A Fetch-based HTTP
    client with onion middleware, path-matched middleware, request encoding, and response parsing.
  </Card>
  <Card title="@momots/design" href="/docs/design">
    A React 19.2+ component library combining Base UI interaction primitives, motion animations, and Tailwind CSS styles.
  </Card>
  <Card title="@momots/cli" href="/docs/cli">
    The momo CLI unifies declaration generation and the Bun.build package build process.
  </Card>
</Cards>
