`@momots/refine` provides number checksums and Chinese citizen ID parsing. The current version is
`0.1.0-alpha.0`; APIs may change during alpha. Releases contain ESM and TypeScript
declarations for Bun, Node.js, and browser bundlers.

## Installation

```bash
bun add @momots/refine@alpha
```

The only runtime dependency, `date-fns`, is installed automatically with refine.

## Entry points

| Subpath | API | Purpose |
| --- | --- | --- |
| Root entry | `luhn`, `iso7064`, `fromChinaIdCard`, `isValidChinaIdCard` | Common utilities |
| `luhn` | `luhn` | Luhn algorithm collection |
| `luhn/mod10` | `mod10` | Luhn (MOD 10) validation |
| `iso7064` | `iso7064` | ISO 7064 check-character system collection |
| `iso7064/mod11-2` | `mod11_2` | ISO 7064 MOD 11-2 validation |
| `cn/idcard` | `fromChinaIdCard`, `isValidChinaIdCard`, `ChinaIdCard`, `ChinaIdCardInfo` types | 18-character Chinese citizen IDs |

`luhn` and `iso7064` form the algorithm layer and validate only checksums; `cn/idcard` is the ID layer, handling format,
dates, and field parsing while calling the algorithm layer internally.

## Luhn validation

```ts
import { mod10 } from '@momots/refine/luhn/mod10';

mod10('79927398713'); // true
mod10('79927398714'); // false
mod10('059'); // true
mod10('4111 1111 1111 1111'); // false
```

Complete input includes the check digit and requires at least two ASCII digits. Nonnegative safe integers are also supported, but use strings for leading zeros
or long numbers. Whitespace, separators, decimals, and other input return `false`.

Luhn checks only the checksum, not the issuer, account length, or actual allocation; `00` also satisfies
the checksum. The [IBM documentation](https://www.ibm.com/docs/en/gdp/11.4.0?topic=policies-special-pattern-tests)
explains the difference between Luhn and number-format checks.

## ISO 7064 MOD 11-2 validation

```ts
import { iso7064 } from '@momots/refine/iso7064';

iso7064.mod11_2('11010519491231002X'); // true
iso7064.mod11_2('11010519491231002x'); // true
iso7064.mod11_2('0000000218250097'); // true, ORCID / ISNI
```

The body must contain only ASCII digits, followed by a check character from `0`–`9` or case-insensitive `X`.
Weights and check characters are fixed by ISO 7064, matching the weight table for GB 11643 citizen IDs.
Only the checksum is checked, not the number length; invalid input returns `false`.

## Chinese citizen IDs

```ts
import {
  fromChinaIdCard,
  isValidChinaIdCard,
} from '@momots/refine/cn/idcard';

const referenceDate = new Date(2026, 0, 1);
isValidChinaIdCard('11010519491231002x', referenceDate); // true
fromChinaIdCard('11010519491231002X', referenceDate);
// { region: '110105', birthDate: '1949-12-31', age: 76, gender: 'F' }
```

An 18-character ID contains an address code, birth date code, sequence code, and checksum; see the
[Beijing Municipal Public Security Bureau explanation](https://gaj.beijing.gov.cn/hudong/rddf/202003/t20200331_1771804.html).
This package checks format, check digit, and birth date. Legacy 15-digit IDs are unsupported.

- `isValidChinaIdCard(code: unknown, referenceDate?: Date)`: returns `false` for invalid input and accepts a final `x/X`; the true branch narrows to `ChinaIdCard`, while the false branch retains the original type.
- `fromChinaIdCard(code: string, referenceDate?: Date)`: returns parsed fields after validation; throws `RangeError` for invalid input.
- The birth date must exist, with a year of at least 1800 and no later than the reference date; invalid reference dates are also rejected.
- The reference date defaults to now. Age uses the runtime's local calendar; pass an explicit date for repeatable results.
- The address code remains the original six-character string, age is in completed years, and the sex code follows the sequence code's parity.
- Whitespace is not trimmed automatically. Administrative-region validity, actual issuance, and identity authenticity are not verified.
