This page explains API inputs, return values, and limitations by purpose. New users can start with the common scenarios in
[Getting started](/docs/core), then consult individual entries here.

Common APIs are available from the root, and every public API has a corresponding subpath. APIs available only through
subpaths are marked individually:

```ts
import { eliminate } from '@momots/core';
import { unflat } from '@momots/core/tree/unflat';
```

For several tools combined in business code, see [examples](/docs/core/examples).

## Arrays

Subpath: `as/array`、`compact`

### asArray

Normalize a single value or array into an array. Existing arrays retain their reference; other values are wrapped with `Array.of`.
Strings, Iterables, and array-like objects are not expanded. `readonly` in the return type restricts TypeScript writes only;
the function does not freeze the array.

```ts
const asArray = <T>(value: MaybeArray<T>): readonly T[];
```

| Parameter | Type | Description |
| --- | --- | --- |
| `value` | `MaybeArray<T>` | Single value, mutable array, or readonly array |

| Return | Description |
| --- | --- |
| `readonly T[]` | Normalized readonly array |

```ts
import { asArray } from '@momots/core/as/array';

asArray('momo');          // => ['momo']
asArray(['momo', 'kit']); // => Original array reference
```

### compact

Remove `false` and values Remeda's `isEmptyish` considers empty, such as `null`, `undefined`, empty strings,
empty arrays, and empty plain objects. Preserve `0` and `NaN`; return a new array without changing the original.

```ts
function compact<T>(source: ReadonlyArray<T>): NonFalseish<T>[];
```

| Parameter | Type | Description |
| --- | --- | --- |
| `source` | `ReadonlyArray<T>` | Array to clean |

| Return | Description |
| --- | --- |
| `NonFalseish<T>[]` | New array without false or empty items |

```ts
import { compact } from '@momots/core/compact';

compact([0, 1, false, '', 'momo', null, undefined, [], {}, [1], { a: 1 }]);
// => [0, 1, 'momo', [1], { a: 1 }]
```

## Collection cardinality

Subpath: `cardinality`

### cardinality

Return array/string `length`, `Map`/`Set` `size`, or the number of own enumerable string keys in a plain object.
These counts are collectively called cardinality. Strings use JavaScript `length`, not user-perceived character counts.
Unsupported values return `0`, including `Blob`, `ArrayBuffer`, and TypedArray.

```ts
const cardinality = (data: unknown): number;
```

| Parameter | Type | Description |
| --- | --- | --- |
| `data` | `unknown` | Value whose length, member count, or key count is needed |

| Return | Description |
| --- | --- |
| `number` | Collection size, or `0` for unsupported values |

```ts
import { cardinality } from '@momots/core/cardinality';

cardinality([1, 2, 3]);            // => 3
cardinality('momo');               // => 4
cardinality(new Set(['a', 'b']));  // => 2
cardinality(null);                 // => 0
```

## Property-name casing

Root: `@momots/core`; aggregate subpath: `@momots/core/casing`; individual subpaths: `casing/*`

Except for `toCamelCasedPropertiesDeep`, these converters process only plain objects'
**top-level own keys**, retaining value references. Symbol keys are unchanged; arrays and functions follow TypeFest's
type semantics and pass through unchanged.

### toCamelCasedProperties

Convert a plain object's **top-level own string keys** to camelCase, without recursion and while retaining value references. Consecutive uppercase characters normalize by default, matching TypeFest's `CamelCasedProperties`.

```ts
const toCamelCasedProperties = <T extends object>(data: T): CamelCasedProperties<T>;
```

| Parameter | Type | Description |
| --- | --- | --- |
| `data` | `T extends object` | Object whose keys should be converted |

| Return | Description |
| --- | --- |
| `CamelCasedProperties<T>` | New object with camelCase keys |

```ts
import { toCamelCasedProperties } from '@momots/core/casing/toCamelCasedProperties';

toCamelCasedProperties({ user_name: 'John', user_age: 30 });
// => { userName: 'John', userAge: 30 }
```

### toCamelCasedPropertiesDeep

Recursively convert string keys in plain objects, array elements, and `Set` members. Circular references are supported;
symbol keys and nonrecursive values defined by TypeFest, such as functions, `Date`, `RegExp`, and
`Promise`, remain unchanged.

```ts
const toCamelCasedPropertiesDeep = <T>(
  data: T,
): CamelCasedPropertiesDeep<T>;
```

```ts
import { toCamelCasedPropertiesDeep } from '@momots/core/casing/toCamelCasedPropertiesDeep';

toCamelCasedPropertiesDeep({
  user_profile: { first_name: 'John' },
  friend_list: [{ user_id: 1 }],
});
// => {
//   userProfile: { firstName: 'John' },
//   friendList: [{ userId: 1 }],
// }
```

### toPascalCase

Convert a **string itself** to PascalCase by applying Remeda's `toCamelCase`, then capitalizing the first character.

```ts
const toPascalCase = <
  T extends string,
  const Options extends PascalCaseOptions = PascalCaseOptions,
>(
  str: T,
  options?: Options,
): PascalCase<T, Options>;
```

| Parameter | Type | Description |
| --- | --- | --- |
| `str` | `T extends string` | String to convert |
| `options` | `PascalCaseOptions` | Preserve consecutive uppercase characters (optional, default `false`) |

| Return | Description |
| --- | --- |
| `PascalCase<T, Options>` | PascalCase string with inference matching TypeFest options |

```ts
import { toPascalCase } from '@momots/core/casing/toPascalCase';

toPascalCase('hello world'); // => 'HelloWorld'
toPascalCase('momo-kit');    // => 'MomoKit'
toPascalCase('fooBAR');      // => 'FooBar'
toPascalCase('fooBAR', { preserveConsecutiveUppercase: true }); // => 'FooBAR'
```

## Value substitution

Subpath: `eliminate`

### eliminate

When `Object.is(source, sentinel)` is true, replace `source` with `otherwise` (default `undefined`); otherwise return it unchanged. The default sentinel is `false`, useful for `cond && value` results. `Object.is` distinguishes `-0` from `0` and recognizes `NaN`.

```ts
function eliminate<const T>(
  source: T,
): T extends false ? Exclude<T, false> | undefined : T;
function eliminate<const T, const P, D = undefined>(
  source: T,
  sentinel: P,
  otherwise?: D,
): T extends P ? Exclude<T, P> | D : T;
```

| Parameter | Type | Description |
| --- | --- | --- |
| `source` | `T` | Input to check |
| `sentinel` | `P` | Sentinel to replace, default `false` |
| `otherwise` | `D` | Replacement on a match, default `undefined` |

| Return | Description |
| --- | --- |
| `Exclude<T, P> \| D \| T` | `otherwise` on a sentinel match, otherwise `source` |

```ts
import { eliminate } from '@momots/core/eliminate';

eliminate(false, false);                   // => undefined
eliminate(false, false, 'fallback');       // => 'fallback'
eliminate(Number.NaN, Number.NaN, 'nan');  // => 'nan'
```

For example, generate analytics parameters only when a module is visible, more data exists, and the sequence ID is nonempty.
Express conditions as booleans first, then turn the failed result from `false` into `undefined` with `eliminate`:

```ts
function createTrackPayload(
  moduleVisible: boolean,
  hasMore: boolean,
  flowID: string,
  pageSize: number,
) {
  const canTrack = moduleVisible && hasMore && flowID.length > 0;
  return eliminate(canTrack && { flowID, pageSize });
}

createTrackPayload(true, true, 'flow-1', 20);
// => { flowID: 'flow-1', pageSize: 20 }
createTrackPayload(true, true, '', 20); // => undefined
```

`&&` returns its first falsy operand, which is not necessarily `false`. Default `eliminate` replaces only `false`,
preserving `0`, empty strings, `null`, and `undefined`; pass an explicit `sentinel` to replace another value.

## Error messages and summaries

Subpath: `error`、`error/toErrorMessage`、`error/toErrorSummary`

Errors may come from `Error`, API responses, or validation results. These functions normalize different error shapes into text:

| Need | Function |
| --- | --- |
| One error message, such as a UI notification | `toErrorMessage` |
| Diagnostic text with error name, code, and cause | `toErrorSummary` |

Both may return `undefined`; use `??` for fallback text. Neither redacts nor truncates results,
so apply any domain-specific processing before displaying them to users.

### toErrorMessage

Extract the first nonblank error message, preserving its original text and surrounding whitespace. Other values are not coerced into strings.

String input is itself the message. Error objects are searched in this order, stopping at the first message:

1. Messages in the `issues` array.
2. Message fields in order: `message`, `errMsg`, `codeMsg`, `msg`, `error_description`, `detail`.
3. Messages in the `errors` array.
4. Nested errors in `error`, `reason`, and `cause`.

```ts
function toErrorMessage(error: unknown): string | undefined;
```

| Parameter | Type | Description |
| --- | --- | --- |
| `error` | `unknown` | Error object, rejection reason, or message string |

| Return | Description |
| --- | --- |
| `string \| undefined` | First valid message, or `undefined` |

```ts
import { toErrorMessage } from '@momots/core/error/toErrorMessage';

toErrorMessage(new TypeError('Request failed')); // => 'Request failed'
toErrorMessage('  Request failed  ');           // => '  Request failed  '
toErrorMessage({ errMsg: 'Request timed out' }); // => 'Request timed out'
toErrorMessage({
  message: 'Validation failed',
  issues: [{ message: 'Enter your name' }],
}); // => 'Enter your name'
toErrorMessage({ cause: new Error('Connection lost') }); // => 'Connection lost'
toErrorMessage(undefined); // => undefined
```

### toErrorSummary

Format an unknown error as a multiline diagnostic summary preserving names, codes, validation paths, child errors, and causes. Message priority matches `toErrorMessage`; codes prefer `code`, then a valid `errCode`. Circular references use `[Circular]`.

```ts
function toErrorSummary(error: unknown): string | undefined;
```

| Parameter | Type | Description |
| --- | --- | --- |
| `error` | `unknown` | Error object, rejection reason, or message string |

| Return | Description |
| --- | --- |
| `string \| undefined` | Summary of available error context, or `undefined` when nothing is describable |

```ts
import { toErrorSummary } from '@momots/core/error/toErrorSummary';

toErrorSummary(new TypeError('Request failed')); // => 'TypeError: Request failed'
toErrorSummary({ code: 401, message: 'Unauthorized' }); // => '[401]: Unauthorized'
toErrorSummary({
  issues: [{ path: ['user', 'name'], message: 'Enter your name' }],
}); // => 'issues:\n  [0] user.name: Enter your name'
toErrorSummary(new Error('Submission failed', {
  cause: new Error('Connection lost'),
})); // => 'Error: Submission failed\ncause: Error: Connection lost'
toErrorSummary(undefined); // => undefined
```

#### Error-reading scope

Both functions read only conventional error fields, not `stack`, `body`, or `data`, and do not serialize the entire input.
Field access invokes getters; exceptions from getters propagate.

Traversal starts at depth `0` and limits nested errors to depth `5` and `100` visited values,
counting arrays and their elements separately. Validation paths read at most `100` segments.
For circular references, `toErrorMessage` skips the reference and `toErrorSummary` inserts `[Circular]`.

## Lazy evaluation

Subpath: `realize`

### realize

Configuration can provide a value directly or compute one with a function. `realize` handles both:
functions are invoked with subsequent `args`, returning their result; other inputs pass through unchanged.

Every call executes the supplied function again without caching. If the function itself is your business value,
passing it directly still invokes it; wrap it in `() => callback` to retain it.

```ts
const realize = <T, Args extends unknown[]>(
  realizable: Realizable<T, Args>,
  ...args: Args
): T;
```

| Parameter | Type | Description |
| --- | --- | --- |
| `realizable` | `Realizable<T, Args>` | A value or a function returning one |
| `...args` | `Args` | Arguments when `realizable` is a function |

| Return | Description |
| --- | --- |
| `T` | Input value or result of invoking the input function |

```ts
import { realize } from '@momots/core/realize';

realize('momo');                            // => 'momo'
realize((a, b) => `${a}-${b}`, 'a', 'b');   // => 'a-b'
```

## Type guards

Subpath: `guard/*`

### hasOwn

Check for an own property without traversing the prototype chain. Optionally provide a type guard to validate and narrow its value.

```ts
import type { IsLiteral, IsUnion } from 'type-fest';

type SingleKey<K extends PropertyKey> =
  IsLiteral<K> extends true ? (IsUnion<K> extends false ? K : never) : never;

function hasOwn<
  T extends object = object,
  K extends PropertyKey = PropertyKey,
  D = unknown,
>(
  o: T,
  k: K & SingleKey<K>,
  guard: (data: unknown) => data is D,
): o is T & Record<K, D>;
function hasOwn<
  T extends object = object,
  K extends PropertyKey = PropertyKey,
>(
  o: T,
  k: K & SingleKey<K>,
  guard?: (data: unknown) => data is unknown,
): o is T & Record<K, unknown>;
function hasOwn<
  T extends object = object,
  K extends PropertyKey = PropertyKey,
  D = unknown,
>(o: T, k: K, guard?: (data: unknown) => data is D): boolean;
```

Without `guard`, only existence is checked and no value is read; own properties containing `undefined` still return `true`. A guard runs only after the own property exists. If the guard itself may be `undefined`, the added property's type remains `unknown`.

One literal key narrows the corresponding property. Union keys, `string`, `number`, `symbol`, and infinite-domain template literal keys return only `boolean` without narrowing, since one check cannot establish multiple keys or a whole index range. `SingleKey` is an internal signature helper and is not separately exported.

```ts
import { hasOwn } from '@momots/core/guard/hasOwn';
import { isString } from 'remeda';

const data: object = { name: 'momo' };

if (hasOwn(data, 'name')) {
  data.name; // unknown
}

if (hasOwn(data, 'name', isString)) {
  data.name.toUpperCase(); // string
}
```

### isFinite

Check for a finite numeric primitive with `Number.isFinite` semantics and no coercion.
Accept integers, decimals, `0`, and `-0`, without requiring safe integers; reject `NaN`, positive/negative infinity, and
nonnumeric values. Import from the root or `@momots/core/guard/isFinite`.

```ts
function isFinite(data: unknown): data is FiniteNumber;
```

| Parameter | Type | Description |
| --- | --- | --- |
| `data` | `unknown` | Value to check |

| Return | Description |
| --- | --- |
| `data is FiniteNumber` | `true` for finite numeric primitives, narrowing to `FiniteNumber`; otherwise `false` |

`FiniteNumber` intersects `number` with a private `unique symbol` brand; import its type from this subpath or
the root. A `false` result does not exclude all numbers, since the value may still be `NaN`
or infinity. Use `toFinite` to parse decimal strings.

```ts
import { isFinite } from '@momots/core/guard/isFinite';
import type { FiniteNumber } from '@momots/core/guard/isFinite';

isFinite(1.5); // => true
isFinite(-0); // => true
isFinite(Number.MAX_VALUE); // => true
isFinite(Number.MAX_SAFE_INTEGER + 1); // => true
isFinite(NaN); // => false
isFinite(Infinity); // => false
isFinite(-Infinity); // => false
isFinite('1.5'); // => false
isFinite(null); // => false
isFinite(new Number(1)); // => false

const values: unknown[] = [1.5, '2', NaN, Infinity, 0];
const numbers: FiniteNumber[] = values.filter(isFinite); // => [1.5, 0]
```

### isNonEmptyString

Check for a string primitive containing non-whitespace characters using its trimmed length,
without coercing or changing the original string. Import from the root or `@momots/core/guard/isNonEmptyString`.

```ts
function isNonEmptyString(data: unknown): data is NonEmptyString;
```

| Parameter | Type | Description |
| --- | --- | --- |
| `data` | `unknown` | Value to check |

| Return | Description |
| --- | --- |
| `data is NonEmptyString` | `true` for string primitives with `trim().length > 0`, narrowing to `NonEmptyString`; otherwise `false` |

`NonEmptyString` intersects `string` with a private `unique symbol` brand; import its type from this subpath or
the root. `false` does not exclude all strings: the value may be empty or whitespace-only.
Whitespace follows ECMAScript `trim()`; nonbreaking and ideographic spaces are removed, but zero-width space `\u200B` is not.

```ts
import { isNonEmptyString } from '@momots/core/guard/isNonEmptyString';
import type { NonEmptyString } from '@momots/core/guard/isNonEmptyString';

isNonEmptyString('momo'); // => true
isNonEmptyString(''); // => false
isNonEmptyString(' '); // => false
isNonEmptyString('\n'); // => false
isNonEmptyString(' momo '); // => true; the original retains surrounding spaces
isNonEmptyString(new String('momo')); // => false
isNonEmptyString(123); // => false
isNonEmptyString(null); // => false

const values: unknown[] = ['momo', '', ' ', 123];
const names: NonEmptyString[] = values.filter(isNonEmptyString);
```

### isSafeInteger

Check for a safe integer within an inclusive interval. Accept numeric primitives only, using
`Number.isSafeInteger` without coercion; both `0` and `-0` are valid safe integers.
Import from the root or `@momots/core/guard/isSafeInteger`.

```ts
function isSafeInteger(data: unknown): data is SafeInteger;
function isSafeInteger(data: unknown, options: undefined): data is SafeInteger;
function isSafeInteger(
  data: unknown,
  options: { min?: number; max?: number } | undefined,
): boolean;
```

| Parameter | Type | Description |
| --- | --- | --- |
| `data` | `unknown` | Value to check |
| `options.min` | `number` | Inclusive lower bound, default `Number.MIN_SAFE_INTEGER` |
| `options.max` | `number` | Inclusive upper bound, default `Number.MAX_SAFE_INTEGER` |

| Return | Description |
| --- | --- |
| `data is SafeInteger` | Success narrows to `SafeInteger` when `options` is omitted or explicitly `undefined` |
| `boolean` | With a bounds object or an object/undefined union, returns the safe-integer and interval check without type narrowing |

`SafeInteger` intersects `number` with a private `unique symbol` brand; import its type from this subpath or
the root. `false` does not exclude all numbers: the value may be fractional or unsafe.

Bounds may be fractional or infinite, but cannot widen the safe-integer range. If either bound is `NaN` or `min > max`,
return `false`.

```ts
import { isSafeInteger } from '@momots/core/guard/isSafeInteger';
import type { SafeInteger } from '@momots/core/guard/isSafeInteger';

isSafeInteger(2, { min: 1, max: 2 }); // => true
isSafeInteger(-0); // => true
isSafeInteger(2, { min: 1.5, max: 2.5 }); // => true
isSafeInteger(Number.MAX_SAFE_INTEGER + 1, { max: Infinity }); // => false
isSafeInteger('2'); // => false
isSafeInteger(2n); // => false
isSafeInteger(new Number(2)); // => false
isSafeInteger(2.5); // => false
isSafeInteger(NaN); // => false
isSafeInteger(Infinity); // => false
isSafeInteger(2, { min: NaN }); // => false
isSafeInteger(2, { min: 3, max: 1 }); // => false

function printNonNegativeInteger(value: unknown) {
  if (isSafeInteger(value) && isSafeInteger(value, { min: 0 })) {
    const integer: SafeInteger = value;
    console.log(integer);
  }
}
```

## Singleton caching

Subpath: `singleton`

### singleton

Look up `key` on the given object `scope`, defaulting to `globalThis`. Return an existing own property's value;
otherwise run `factory`, store its result in `scope[key]`, and return it.

If `factory` throws, nothing is cached and a later call retries creation.

This lets multiple copies of module code in one runtime share an instance. The cache lives with `scope`;
deleting or rewriting the property affects later calls. Truthy `pass` bypasses caching and runs `factory` directly each time.

On servers, the default `globalThis` is shared by requests in one process. Do not cache
request-specific state such as tokens or current users in that default scope.

```ts
interface SingletonOptions {
  pass?: boolean | (() => boolean);
  scope?: Record<PropertyKey, unknown>;
}

const singleton = <T>(
  key: PropertyKey,
  factory: () => T,
  options?: SingletonOptions,
): T;
```

| Parameter | Type | Description |
| --- | --- | --- |
| `key` | `PropertyKey` | Globally unique key; prefer `Symbol.for("@scope/name")` |
| `factory` | `() => T` | Runs when the key is absent or caching is bypassed; stores the result in scope unless bypassed |
| `options.pass` | `boolean \| (() => boolean)` | Truthy bypasses caching and invokes `factory` directly |
| `options.scope` | `Record<PropertyKey, unknown>` | Cache scope, default `globalThis` |

| Return | Description |
| --- | --- |
| `T` | Cached or newly created instance |

```ts
import { singleton } from '@momots/core/singleton';

const scope: Record<PropertyKey, unknown> = {};
const key = Symbol('momo');

singleton(key, () => ({ count: 1 }), { scope }); // => { count: 1 }
singleton(key, () => ({ count: 2 }), { scope }); // => Still { count: 1 }
```

## Concurrent call deduplication

Subpath: `singleflight`

### Singleflight

While a task is unfinished, subsequent calls can wait for its existing result instead of starting another task.
`Singleflight` returns the same Promise for these calls on one instance; only the first `call` arguments reach
the execution function. After success or failure, the next call creates a new Promise and runs again.

Arguments are not compared. Even with different user IDs, calls sharing an instance while the first task is pending
receive the first result. Maintain separate instances per ID to deduplicate by user.

```ts
class Singleflight<TRes, TArgs extends unknown[] = []> {
  constructor(fn: (...args: TArgs) => Promise<TRes>);
  call(...args: TArgs): Promise<TRes>;
  forget(): void;
}
```

| Member | Description |
| --- | --- |
| `constructor(fn)` | Set the asynchronous function used to start tasks |
| `call(...args)` | Return the ongoing Promise, or start a task with these arguments when none is active |
| `forget()` | Clear the current Promise reference so the next call starts anew; does not cancel the existing task |

```ts
import { Singleflight } from '@momots/core/singleflight';

const profileFlight = new Singleflight(async (id: string) => {
  const response = await fetch(`/api/profiles/${id}`);
  return response.json();
});

const first = profileFlight.call('momo');
const second = profileFlight.call('ignored-while-pending');

first === second; // => true
await first;

// After the previous task finishes, start a new task with 'kit'
await profileFlight.call('kit');
```

`Singleflight` neither caches completed results nor cancels requests. After `forget()`, callers already waiting for the old Promise
still receive its result, while new calls may start another task concurrently.

## Waiting timeouts

Subpath: `timeout` (`timeout` and `TimeoutError` are also exported from the root)

### timeout

Set a waiting deadline for an existing Promise. If it settles first, preserve its value or error
and cancel the timer; if the deadline wins, reject the returned Promise with `TimeoutError`.

```ts
function timeout<T>(
  promise: Promise<T>,
  milliseconds: number,
  timer: Timer,
): Promise<T>;
```

| Parameter | Type | Description |
| --- | --- | --- |
| `promise` | `Promise<T>` | Source Promise to await |
| `milliseconds` | `number` | Nonnegative finite milliseconds, including `0`, fractions, and values above `2 ** 31 - 1` |
| `timer` | `Timer` | Explicitly supplied one-shot timing capability; import its type from `@momots/core/types` or the root |

| Return | Description |
| --- | --- |
| `Promise<T>` | Source result when it settles first; `TimeoutError` when the deadline wins |

Callers adapt `Timer` to their runtime; `timeout` uses no global timer or host types.
The adapter owns precision, supported durations, and host timer limits. This example uses `setTimeout`:

```ts
import { timeout, TimeoutError } from '@momots/core/timeout';
import type { Timer } from '@momots/core/types';

const timer: Timer = {
  schedule(callback, milliseconds) {
    const handle = setTimeout(callback, milliseconds);
    return () => clearTimeout(handle);
  },
};

const profile = fetch('/api/profile').then(response => response.json());

try {
  const result = await timeout(profile, 1000, timer);
  console.log(result);
} catch (error) {
  if (error instanceof TimeoutError) {
    console.log(`Wait exceeded ${error.milliseconds}ms`);
  } else {
    throw error;
  }
}
```

A timeout ends only this wait, not the source task. The source Promise may still settle later, and late rejection is received by
an internal handler. `Timer` callbacks must run asynchronously, so already-settled native Promises preserve their result before a
`0`-millisecond callback.

`TimeoutError` extends `Error`, has name `'TimeoutError'`, and stores the deadline in readonly `milliseconds: number`.
Invalid duration types reject with `TypeError`; negative values, `NaN`, and infinities reject with `RangeError`,
without calling `timer.schedule`. Invalid `Timer`, thrown `schedule` errors, and non-function cancellation results
also reject the returned Promise; these errors do not throw synchronously from `timeout()`.

During cleanup, if the source succeeded but cancellation throws, the returned Promise rejects with that cleanup error.
If a source rejection or `TimeoutError` already exists, it is retained rather than replaced by cleanup failure.

## Delivery queues

Subpath: `delivery-queue` (`DeliveryQueue` and related types are also exported from the root)

### DeliveryQueue

`DeliveryQueue` retains entries in memory in FIFO order, handing batches to
`request` when `flush()` is called. It suits collecting events, logs, or pending records and letting the caller choose when to send.
`enqueue()` only accepts entries synchronously; construction and `configure()` only bind a sender. None sends automatically.

```ts
type DeliveryRequest<T> = (items: readonly T[]) => Promise<unknown>;
type DeliveryPartition<T> = (candidates: readonly T[]) => number;

interface DeliveryQueueOptions<T> {
  capacity?: number;
  request?: DeliveryRequest<T>;
  partition?: DeliveryPartition<T>;
}

class DeliveryQueue<T> {
  constructor(options?: DeliveryQueueOptions<T>);
  get size(): number;
  get full(): boolean;
  get configured(): boolean;
  get reporting(): boolean;
  enqueue(item: T): boolean;
  configure(request: DeliveryRequest<T>): void;
  flush(): Promise<void>;
}
```

| Parameter | Type | Description |
| --- | --- | --- |
| `options.capacity` | `number` | Capacity, default `Infinity`; explicit values must be `Infinity` or positive safe integers; others fail without coercion |
| `options.request` | `DeliveryRequest<T>` | Sender bound on construction, or later through `configure()` |
| `options.partition` | `DeliveryPartition<T>` | Number of leading entries to send per batch; defaults to all candidates |

#### Methods

| Method | Return | Description |
| --- | --- | --- |
| `constructor(options?)` | `DeliveryQueue<T>` | Create an in-memory queue with capacity, sender, and partition rules |
| `enqueue(item)` | `boolean` | Append and return `true` if capacity remains; otherwise reject admission with `false` |
| `configure(request)` | `void` | Assign or replace the sender directly, without runtime function validation or duplicate-binding checks |
| `flush()` | `Promise<void>` | Wait for all entries present at this call to be acknowledged; reject on send failure; an empty queue completes immediately |

Callers must supply a valid `request` and avoid replacing it during sending.

#### Properties

| Property | Type | Description |
| --- | --- | --- |
| `size` | `number` | Unacknowledged entries, including in-flight batches |
| `full` | `boolean` | Whether `size` has reached capacity; in-flight entries still count |
| `configured` | `boolean` | Whether a sender is bound |
| `reporting` | `boolean` | Whether any `flush()` acknowledgment target remains, including queued microtasks, partitioning, and sending |

All are readonly getters. The queue retains original item references; `partition` and `request` receive independent,
frozen readonly array snapshots, but elements retain their original references and are neither deep-cloned nor frozen.

```ts
import { DeliveryQueue } from '@momots/core/delivery-queue';

interface EventRecord {
  name: string;
  createdAt: number;
}

const queue = new DeliveryQueue<EventRecord>({
  capacity: 100,
  partition: candidates => Math.min(20, candidates.length),
});

queue.enqueue({ name: 'opened', createdAt: Date.now() }); // => true
queue.configured; // => false

queue.configure(async items => {
  const response = await fetch('/api/events', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(items),
  });
  if (!response.ok) throw new Error(`Send failed: ${response.status}`);
});

// configure does not send; flush starts delivery
await queue.flush();
queue.size; // => 0
```

#### Acknowledgment boundaries and batching

Each `flush()` fixes the current queue tail as its acknowledgment target. Later enqueues do not extend that wait;
later `flush()` calls may include them. One instance runs a single sending pipeline, with all batches sent
sequentially; each call's Promise settles after its own target is acknowledged. Batches never cross the earliest pending
target, so earlier calls need not wait for later additions.

```ts
queue.enqueue({ name: 'first', createdAt: Date.now() });
const first = queue.flush();

queue.enqueue({ name: 'second', createdAt: Date.now() });
const second = queue.flush();

await first; // Wait only for the first entry's acknowledgment
await second; // Also wait for the second entry's acknowledgment
```

`partition(candidates)` runs before each batch. Candidates are nonempty and span the queue head to the earliest waiting
target; return an integer from `1` to `candidates.length` specifying the consecutive prefix length.
`0` or other invalid values fail the send; `0` does not pause it. The example above caps batches at 20 entries;
you can also choose a consecutive group based on the first entry's context:

```ts
const queue = new DeliveryQueue<{ context: string; value: string }>({
  partition: candidates => {
    const context = candidates[0]!.context;
    const end = candidates.findIndex(item => item.context !== context);
    return end === -1 ? candidates.length : end;
  },
  request: async items => {
    // All entries share a context; dispatch to the corresponding sender here
    console.log(items);
  },
});
```

#### Sending results and retries

When `request`'s Promise fulfills, the whole batch is acknowledged and removed; its return value is ignored.
If business responses require a success check, perform it in the callback and throw on failure.

A rejected or synchronously throwing `request`, or a throwing/invalid `partition`, rejects all currently pending
`flush()` calls and retains unacknowledged entries. Previously successful batches are not rolled back, and the queue does not retry automatically;
after handling failure, call `flush()` again to explicitly retry remaining entries.

An empty queue's `flush()` completes even without a sender; a nonempty unconfigured queue rejects while retaining
entries and can be flushed again after binding `request`. The queue handles in-memory admission, batching, and acknowledgment only; persistence and
interruption belong to external adapters.

### substitute

Replace `{{name}}` and `{{name|fallback}}` placeholders in a string template. Values serialize through `.toString()`; missing keys use fallback, or retain the original field name when none is supplied.

```ts
function substitute(
```

## Text masking

Subpath: `veil`

### veil

Retain a specified number of leading/trailing graphemes (user-perceived characters) and replace each middle grapheme with `mask`. Uses `Intl.Segmenter` without splitting emoji or combining characters; the runtime must support it.

```ts
interface VeilParams {
  fore: number;
  tail: number;
  mask?: string;
}

function veil(value: string, params?: VeilParams): string;
```

| Parameter | Type | Description |
| --- | --- | --- |
| `value` | `string` | String to mask |
| `params` | `VeilParams` | Defaults to `{ fore: 0, tail: 0, mask: '*' }`, masking all graphemes |
| `params.fore` | `number` | Leading graphemes to retain; nonnegative integer |
| `params.tail` | `number` | Trailing graphemes to retain; nonnegative integer |
| `params.mask` | `string` | Replacement per masked grapheme, default `'*'`; allows empty strings, multiple characters, or emoji |

Invalid `fore` or `tail` values throw `RangeError` even when `value` is empty.

| Return | Description |
| --- | --- |
| `string` | Masked string; returns the original when retained ranges cover/overlap, and an empty string for empty input |

```ts
import { veil } from '@momots/core/veil';

veil('abcdefghij', { fore: 2, tail: 3 }); // => 'ab*****hij'
veil('张三丰', { fore: 1, tail: 0 }); // => '张**'
veil('A👨‍👩‍👧‍👦B', { fore: 1, tail: 1, mask: '•' }); // => 'A•B'
veil('abc'); // => '***'
veil('abc', { fore: 2, tail: 2 }); // => 'abc'
veil(''); // => ''
```

## Numeric conversion

Subpath: `toFinite` (also exported from the root)

### toFinite

Normalize a finite number or complete decimal numeric string to `number`, returning `undefined` if conversion fails.
Finite numeric primitives remain unchanged, including `0` and `-0`; other types are not coerced, and object conversion
hooks are not called.

```ts
function toFinite(value: unknown): number | undefined;
```

| Parameter | Type | Description |
| --- | --- | --- |
| `value` | `unknown` | Finite numeric primitive or decimal string to convert |

| Return | Description |
| --- | --- |
| `number` | Original finite number or finite conversion of a valid string |
| `undefined` | Invalid type/format, `NaN`, infinity, or conversion overflow |

Strings trim surrounding ECMAScript whitespace and must then match a complete decimal format.
Optional `+` / `-`, leading zeros, integers, and decimals are accepted; at least one side of a decimal point needs ASCII digits,
so `.5`, `-.5`, and `12.` are valid. An `e` / `E` exponent may follow the mantissa, with an optional sign,
but requires at least one ASCII digit and an integer value, as in `1.e3` and `2.5e-2`.

Empty strings, internal whitespace, hex/binary/octal prefixes, numeric separators, thousands separators, percent signs,
units, and incomplete numbers are rejected. Booleans, nullish values, `bigint`, arrays, objects, boxed primitives, and functions
also return `undefined`.

```ts
import { toFinite } from '@momots/core/toFinite';

toFinite(42); // => 42
toFinite(' +0012.5e2 '); // => 1250
toFinite('.5'); // => 0.5
toFinite('12.'); // => 12
toFinite('1.e3'); // => 1000
toFinite('0x10'); // => undefined
toFinite('12px'); // => undefined
toFinite('1e+'); // => undefined
toFinite('1e309'); // => undefined
toFinite(true); // => undefined
toFinite(new Number(1)); // => undefined
```

String conversion follows `Number` rounding and underflow rules without guaranteeing safe integers or decimal precision. For safe-integer
results, check the converted value with `isSafeInteger`.

```ts
import { isSafeInteger } from '@momots/core/guard/isSafeInteger';

toFinite('9007199254740993'); // => 9007199254740992
toFinite('1e-400'); // => 0
Object.is(toFinite('-1e-400'), -0); // => true

isSafeInteger(toFinite('42')); // => true
isSafeInteger(toFinite('1.5')); // => false
```

## Digit sums

Subpath: `sumdig`

### sumdig

Convert input to a string, convert each character with `Number`, and sum them. Intended for digits in strings or numbers;
does not implement a check-digit algorithm or validate input format.

Unconvertible characters produce `NaN`. Empty strings return `0`, and whitespace contributes `0`;
negative, fractional, or scientific-notation numbers produce `NaN` because of their signs, decimal points, or letters.

```ts
const sumdig = (digits: string | number): number;
```

| Parameter | Type | Description |
| --- | --- | --- |
| `digits` | `string \| number` | Number or digit string to sum |

| Return | Description |
| --- | --- |
| `number` | Sum of per-character numeric conversions, or `NaN` |

```ts
import { sumdig } from '@momots/core/sumdig';

sumdig(1234);  // => 10
sumdig('909'); // => 18
sumdig('12x'); // => NaN
sumdig('1 2'); // => 3; the space contributes 0
sumdig('');    // => 0
```

## Property paths

Subpath: `property-path` (`PropertyPath` and related types are also exported from the root)

### PropertyPath

`PropertyPath` records the location of an object property or array item. For example, `users[0].name` selects `users`,
then its first array element, then that element's `name` property.

Paths contain string or numeric segments: strings are object property names, numbers are array indices.
Instances only record locations; to read data, pass both data and path to static `read`:

```ts
import { PropertyPath } from '@momots/core/property-path';

const path = PropertyPath.from('users[0].name');
path.segments; // => ['users', 0, 'name']
path.name; // => 'name'
path.parent?.toString(); // => 'users[0]'

const data = { users: [{ name: 'Mango' }] };
PropertyPath.read(data, path); // => { exists: true, value: 'Mango' }
```

Path instances are immutable. Construction copies and freezes the segment array; operations such as `append` return new paths.
Constructing a path neither requires data to exist nor creates properties.

#### Path expressions

Common expressions and their parsed results:

| Expression | Segments | Meaning |
| --- | --- | --- |
| `users[0].name` | `['users', 0, 'name']` | First user's name property |
| `records.0` | `['records', '0']` | Property named `'0'` on the records object |
| `records[0]` | `['records', 0]` | Index `0` in the records array |
| `["a.b"]` | `['a.b']` | One property with a dot in its name |
| `[""]` | `['']` | Property with an empty name |
| Empty string | `[]` | Root path representing all data |

For names containing dots, brackets, whitespace, quotes, or backslashes, use JSON double-quoted bracket syntax.
Alternatively pass a segment array, such as `PropertyPath.from(['a.b'])`; strings in arrays are not parsed again.
Unquoted `a[foo]` is a compatible form equivalent to `a.foo`.

Numeric indices must be integers from `0` to `2 ** 32 - 2`. Expression indices use decimal notation without leading zeros:
`[0]` and `[12]` are valid; `[01]`, `[1.0]`, and `[1e2]` are invalid. Exact `[-0]` is also accepted and normalized to `[0]`.

#### Methods

| Method | Return | Description |
| --- | --- | --- |
| `from(source)` | `PropertyPath` | Static constructor; see its entry below |
| `read(source, path)` | `PropertyPathRead` | Static own-property reader, distinguishing absence from `undefined`; see below |
| `toSegment(value)` | `PropertyPathSegment` | Static validation/normalization of one segment; see below |
| `toSegments(values)` | `readonly PropertyPathSegment[]` | Static validation returning a new frozen segment array; see below |
| `append(segment)` | `PropertyPath` | Append one complete segment to a new path; strings are not expressions and invalid segments follow `toSegment` errors |
| `resolve(expression)` | `PropertyPath` | Resolve an expression; relative forms start at the current path; see Relative paths below |
| `isPrefixOf(other)` | `boolean` | Compare complete segments for prefix/equality; root prefixes every path |
| `overlaps(other)` | `boolean` | `true` for equal or ancestor-related paths; distinct siblings do not overlap |
| `toString()` | `string` | Canonical parseable expression; root returns `''`; original expression spelling is not retained |

#### Properties

| Property | Type | Description |
| --- | --- | --- |
| `root` | `PropertyPath` | Static root path with an empty segment sequence |
| `segments` | `readonly PropertyPathSegment[]` | Frozen complete segment array, copied at construction so later source-array changes do not affect the path |
| `key` | `PropertyPathKey` | Stable JSON-array encoding; equal paths share keys, while string and numeric segments differ; use for path equality |
| `name` | `string` | Display name of the final segment; numbers become strings and root returns `''`; does not include the full path |
| `parent` | `PropertyPath \| undefined` | Parent path; a single segment's parent is `root`, whose parent is `undefined` |

```ts
import { PropertyPath } from '@momots/core/property-path';

PropertyPath.from('user.name').name; // => 'name'
PropertyPath.from('company.name').name; // => 'name'

PropertyPath.from('records.0').key; // => '["records","0"]'
PropertyPath.from('records[0]').key; // => '["records",0]'
PropertyPath.root.append('a.b').toString(); // => '["a.b"]'
```

`name` does not uniquely identify a full path. Compare `key` instead; it also distinguishes string property names from numeric indices.
`append` always adds one complete segment without parsing dots or brackets within strings.

#### Relative paths

`from` accepts only absolute paths. Use instance `resolve` to work relative to an existing path:

| Form | Resolution starting point |
| --- | --- |
| `.` or `./` | Return the current path itself |
| `./x` | Append x to the current path |
| `../x` | Append x to the parent; each additional `../` moves up another level |
| No relative prefix, such as `users[0]` | Start at root |

```ts
import { PropertyPath } from '@momots/core/property-path';

const city = PropertyPath.from('address.city');
city.resolve('./code').toString(); // => 'address.city.code'
city.resolve('../province').toString(); // => 'address.province'
city.resolve('../../name').toString(); // => 'name'
city.resolve('users[0]').toString(); // => 'users[0]'
city.resolve('../../../name'); // Throws RangeError
```

Going above root throws `RangeError`; invalid syntax throws `SyntaxError`; invalid numeric indices throw `RangeError`.

#### Comparing path relationships

`isPrefixOf` checks ancestry or equality; `overlaps` checks whether either path is equal to or an ancestor of the other.
Both compare complete segments, so distinct siblings do not overlap:

```ts
import { PropertyPath } from '@momots/core/property-path';

const user = PropertyPath.from('users[0]');
const path = PropertyPath.from('users[0].name');
user.isPrefixOf(path); // => true
user.isPrefixOf(user); // => true
path.overlaps(user); // => true
path.overlaps(PropertyPath.from('users[0].age')); // => false
```

### PropertyPath.from

Construct a path from any of these inputs:

| Input | Handling |
| --- | --- |
| String | Parse with the grammar above; relative expressions such as `./` and `../` are rejected |
| Segment array | Retain strings as full property names and numbers as array indices; copy and freeze the array |
| Existing `PropertyPath` | Return the same instance unchanged |

Empty strings and empty arrays return `PropertyPath.root`. Array entries containing `null`, `undefined`,
or holes are not skipped; they fail validation with `TypeError`.

```ts
static from(
  source: PropertyPath | string | readonly PropertyPathSegment[],
): PropertyPath;
```

| Parameter | Type | Description |
| --- | --- | --- |
| `source` | `PropertyPath \| string \| readonly PropertyPathSegment[]` | Existing path, absolute expression, or segment array |

| Return | Description |
| --- | --- |
| `PropertyPath` | Frozen instance; existing instances return themselves, while `''` and `[]` return `PropertyPath.root` |

Common failures:

| Cause | Exception |
| --- | --- |
| Invalid expression syntax or a relative expression | `SyntaxError` |
| Invalid input/segment type or a sparse segment array | `TypeError` |
| Numeric segment is not a valid array index | `RangeError` |

```ts
import { PropertyPath } from '@momots/core/property-path';

const path = PropertyPath.from('users[0].name');
path.segments; // => ['users', 0, 'name']
PropertyPath.from(path) === path; // => true
PropertyPath.from('') === PropertyPath.root; // => true
PropertyPath.from([]) === PropertyPath.root; // => true
PropertyPath.from(['a.b']).toString(); // => '["a.b"]'
PropertyPath.from('a[foo]').toString(); // => 'a.foo'
PropertyPath.from('../name'); // Throws SyntaxError
PropertyPath.from(new Array(1)); // Throws TypeError
PropertyPath.from(['users', -1]); // Throws RangeError
```

### PropertyPath.read

Read a path from data and report both whether the target exists and its value. This distinguishes
missing properties from existing properties containing `undefined`:

```ts
import { PropertyPath } from '@momots/core/property-path';

PropertyPath.read({ name: undefined }, 'name');
// => { exists: true, value: undefined }
PropertyPath.read({}, 'name'); // => { exists: false }
```

Paths validate through `from` before reading, throwing the corresponding error for invalid input. Empty strings, empty arrays, and
`PropertyPath.root` select the entire `source`; even an `undefined` source counts as existing.

```ts
export type PropertyPathRead =
  | { readonly exists: true; readonly value: unknown }
  | { readonly exists: false };

static read(
  source: unknown,
  path: PropertyPath | string | readonly PropertyPathSegment[],
): PropertyPathRead;
```

| Parameter | Type | Description |
| --- | --- | --- |
| `source` | `unknown` | Data to read; root accepts any source value |
| `path` | `PropertyPath \| string \| readonly PropertyPathSegment[]` | Existing path, absolute expression, or segment array; same validation as `from` |

| Return | Description |
| --- | --- |
| `PropertyPathRead` | With `exists: true`, includes `value: unknown`; with `exists: false`, has no `value` field |

```ts
import { PropertyPath } from '@momots/core/property-path';

PropertyPath.read({ user: { name: 'Mango' } }, 'user.name');
// => { exists: true, value: 'Mango' }
PropertyPath.read(undefined, ''); // => { exists: true, value: undefined }
```

#### Property names and array indices

Reading does not convert between string `'0'` and numeric `0`:

| Segment | Traversable value | Readable locations |
| --- | --- | --- |
| String, such as `'name'` or `'0'` | Plain objects, including null-prototype objects | Own properties only, without prototype traversal |
| Number, such as `0` | Arrays | Own indices, excluding holes |

Arrays are recognized first, then other values are checked for plain objects. Arrays accept only numeric segments even with modified prototypes.

```ts
import { PropertyPath } from '@momots/core/property-path';

PropertyPath.read({ records: ['Mango'] }, 'records[0]');
// => { exists: true, value: 'Mango' }
PropertyPath.read({ records: ['Mango'] }, 'records.0'); // => { exists: false }
PropertyPath.read({ records: { '0': 'Mango' } }, 'records.0');
// => { exists: true, value: 'Mango' }
PropertyPath.read({ records: { '0': 'Mango' } }, 'records[0]');
// => { exists: false }
```

Missing properties, array holes, or incompatible intermediate structures return `{ exists: false }`.
`Date`, `Map`, `Set`, class instances, and functions may be final values, but their internal properties are not traversed.

Reading does not mutate, clone, or freeze the source; returned `value` retains the original value and reference.
Property access may invoke getters or Proxy traps, whose exceptions propagate to the caller.

### PropertyPath.toSegment

Validate and normalize one unknown segment. Strings remain unchanged, including `''`, `'0'`, and `'a.b'`; numbers must be integers from `0` to `2 ** 32 - 2`, with `-0` normalized to `0`. No coercion or expression parsing occurs.

```ts
static toSegment(value: unknown): PropertyPathSegment;
```

| Parameter | Type | Description |
| --- | --- | --- |
| `value` | `unknown` | Segment to validate; `null`, `undefined`, and other non-string/non-number values throw `TypeError`; invalid numbers throw `RangeError` |

| Return | Description |
| --- | --- |
| `PropertyPathSegment` | Original string or normalized valid numeric index |

```ts
PropertyPath.toSegment('a.b'); // => 'a.b'
PropertyPath.toSegment('0'); // => '0'
PropertyPath.toSegment(-0); // => 0
PropertyPath.toSegment(null); // Throws TypeError
PropertyPath.toSegment(1.5); // Throws RangeError
```

### PropertyPath.toSegments

Validate each segment in order and return a new frozen array without mutating input. Accepts arrays only and does not parse expressions. `from` performs the same checks for segment-array input, so calling this first is unnecessary.

```ts
static toSegments(values: readonly unknown[]): readonly PropertyPathSegment[];
```

| Parameter | Type | Description |
| --- | --- | --- |
| `values` | `readonly unknown[]` | Array to validate; rejects nonarrays, nullish entries, and holes; numbers follow `toSegment`. Element errors preserve `TypeError` / `RangeError` with a zero-based index in the message |

| Return | Description |
| --- | --- |
| `readonly PropertyPathSegment[]` | New frozen array retaining order and length; empty input still produces a new array |

```ts
const source = ['users', -0, 'name'];
const segments = PropertyPath.toSegments(source);
segments; // => ['users', 0, 'name']
segments === source; // => false
Object.isFrozen(segments); // => true
PropertyPath.toSegments(['users', undefined]); // TypeError, index 1
PropertyPath.toSegments(['users', -1]); // RangeError, index 1
PropertyPath.toSegments(new Array(1)); // TypeError, index 0
```

## Trees

Subpath: `tree/*`

Trees are arrays of nodes, each storing the next level in `children`. `id` identifies a node,
and `parent` stores its parent's ID. Every function supports custom field names through `params.names`.

The corresponding type is `TreeNode<T, C> = T & Record<C, TreeNode<T, C>[]>`:
`T` contains business fields and `C` names the child field, defaulting to `'children'`.

### unflat

Reconstruct a tree from a flat list with `id` / `parent` relationships. Nodes with `null` or `undefined` parents become roots;
`0` and empty strings remain valid parent IDs. For missing parents, `orphan` determines whether to promote the node to root,
discard it, or throw.

Inputs should have unique IDs and acyclic parent relationships. `orphan: 'throw'` checks only parent existence,
not cycles.

```ts
function unflat<
  T extends PlainObject,
  const C extends string = 'children',
>(
  data: T[],
  params?: {
    names?: Names<T, C>;
    orphan?: OrphanStrategy;
  },
): TreeNode<T, C>[];
```

| Parameter | Type | Description |
| --- | --- | --- |
| `data` | `T[]` | Flat node list to reconstruct |
| `params.names` | `Names<T, C>` | Custom `id`, `parent`, and `children` names |
| `params.orphan` | `'root' \| 'throw' \| 'discard'` | Orphan policy, default `'root'` (promote to root) |

| Return | Description |
| --- | --- |
| `TreeNode<T, C>[]` | Reconstructed tree/forest |

```ts
import { unflat } from '@momots/core/tree/unflat';

const tree = unflat([
  { id: 'root', parent: null },
  { id: 'a', parent: 'root' },
]);
// => [{ id: 'root', parent: null, children: [{ id: 'a', parent: 'root', children: [] }] }]
```

### flat

Flatten a tree into a list. Output entries omit `children` and add `parent` pointing to the parent's ID; roots have `parent: undefined`.

```ts
function flat<
  T extends PlainObject,
  const C extends string = 'children',
  P extends string = 'parent',
>(
  tree: TreeNode<T, C>[],
  params?: { names?: Names<T, C, P> },
): (T & { [K in P]?: PropertyKey })[];
```

| Parameter | Type | Description |
| --- | --- | --- |
| `tree` | `TreeNode<T, C>[]` | Tree to flatten |
| `params.names` | `Names<T, C, P>` | Custom field names |

| Return | Description |
| --- | --- |
| Flat node array | Each item has `parent` and no `children` |

```ts
import { flat, unflat } from '@momots/core';

const tree = unflat([
  { id: 'root', parent: null },
  { id: 'a', parent: 'root' },
]);

flat(tree);
// => [
//   { id: 'root', parent: undefined },
//   { id: 'a', parent: 'root' },
// ]
```

### visit

Traverse the entire tree breadth-first. The callback receives node, depth (root is `0`), and parent. Return the maximum depth encountered.

```ts
function visit<
  T extends PlainObject,
  const C extends string = 'children',
  P extends string = 'parent',
>(
  tree: TreeNode<T, C>[],
  callback?: (
    item: TreeNode<T, C>,
    depth: number,
    parent?: TreeNode<T, C>,
  ) => void,
  params?: { names?: Names<T, C, P> },
): number;
```

| Parameter | Type | Description |
| --- | --- | --- |
| `tree` | `TreeNode<T, C>[]` | Tree to traverse |
| `callback` | Visitor callback | Optional; called once per node |
| `params.names` | `Names<T, C, P>` | Custom field names |

| Return | Description |
| --- | --- |
| `number` | Maximum depth |

```ts
import { visit, unflat } from '@momots/core';

const tree = unflat([
  { id: 'root', parent: null },
  { id: 'a', parent: 'root' },
]);

visit(tree, (node, depth) => {
  console.log(node.id, depth);
});
// root 0, a 1
```

### height

Return maximum tree depth. Root depth is `0`; an empty tree returns `0`.

```ts
function height<
  T extends PlainObject,
  const C extends string = 'children',
  P extends string = 'parent',
>(
  tree: TreeNode<T, C>[],
  params?: { names?: Names<T, C, P> },
): number;
```

| Parameter | Type | Description |
| --- | --- | --- |
| `tree` | `TreeNode<T, C>[]` | Tree whose depth is needed |
| `params.names` | `Names<T, C, P>` | Custom field names |

| Return | Description |
| --- | --- |
| `number` | Deepest node's depth |

```ts
import { height, unflat } from '@momots/core';

height(unflat([
  { id: 'root', parent: null },
  { id: 'a', parent: 'root' },
])); // => 1
```

### leaves

Collect all leaf nodes breadth-first. Nodes without `children`, or whose `children` is emptyish, count as leaves.

```ts
function leaves<
  T extends PlainObject,
  const C extends string = 'children',
  P extends string = 'parent',
>(
  tree: TreeNode<T, C>[],
  params?: { names?: Names<T, C, P> },
): TreeNode<T, C>[];
```

| Parameter | Type | Description |
| --- | --- | --- |
| `tree` | `TreeNode<T, C>[]` | Tree to find leaves in |
| `params.names` | `Names<T, C, P>` | Custom field names |

| Return | Description |
| --- | --- |
| `TreeNode<T, C>[]` | Leaves in BFS order |

```ts
import { leaves, unflat } from '@momots/core';

leaves(unflat([
  { id: 'root', parent: null },
  { id: 'a', parent: 'root' },
])).map((n) => n.id);
// => ['a']
```

### cascade

Select one cascading path through tree levels. At each level, choose the **first** sibling for which `predicate` is truthy, append it without `children`, then descend into its children.

```ts
function cascade<
  T extends PlainObject,
  const C extends string = 'children',
  P extends string = 'parent',
>(
  tree: TreeNode<T, C>[],
  predicate: (
    curr: TreeNode<T, C>,
    index: number,
    depth: number,
    parent?: TreeNode<T, C>,
  ) => unknown,
  params?: { names?: Names<T, C, P> },
): Omit<TreeNode<T, C>, C>[];
```

| Parameter | Type | Description |
| --- | --- | --- |
| `tree` | `TreeNode<T, C>[]` | Tree to search |
| `predicate` | Predicate function | Select each level's node; receives node, index, depth, and parent |
| `params.names` | `Names<T, C, P>` | Custom field names |

| Return | Description |
| --- | --- |
| Path array | Root through the last matching node, with `children` omitted |

```ts
import { cascade, unflat } from '@momots/core';

cascade(
  unflat([
    { id: 'root', parent: null },
    { id: 'a', parent: 'root' },
    { id: 'b', parent: 'root' },
  ]),
  (node) => node.id === 'a' || node.id === 'root',
);
// => [{ id: 'root', parent: null }, { id: 'a', parent: 'root' }]
```

### prune

Prune bottom-up. Process children recursively first; keep parents with surviving children, otherwise let `predicate` decide. Clone input first, **without mutating** the original tree.

```ts
function prune<
  T extends PlainObject,
  const C extends string = 'children',
>(
  tree: TreeNode<T, C>[],
  predicate: (val: TreeNode<T, C>, parent?: TreeNode<T, C>) => unknown,
  params?: { names?: Names<T, C>; parent?: TreeNode<T, C> },
): TreeNode<T, C>[];
```

| Parameter | Type | Description |
| --- | --- | --- |
| `tree` | `TreeNode<T, C>[]` | Tree to prune |
| `predicate` | Predicate function | Decide whether to keep leaves or empty parents |
| `params.names` | `Names<T, C>` | Custom field names |
| `params.parent` | `TreeNode<T, C>` | Internal recursion state; normally omitted by callers |

| Return | Description |
| --- | --- |
| `TreeNode<T, C>[]` | New pruned tree |

```ts
import { prune, unflat } from '@momots/core';

const tree = unflat([
  { id: 'root', parent: null },
  { id: 'a', parent: 'root' },
  { id: 'b', parent: 'root' },
]);

prune(tree, (node) => node.id === 'a');
// root does not match the predicate but remains as a's ancestor.
// => [{ id: 'root', parent: null, children: [
//   { id: 'a', parent: 'root', children: [] },
// ] }]
```

## Type utilities

Subpath: `types`

Import these types from `@momots/core/types` or the root. They are compile-time utilities without runtime overhead.

### Nil

```ts
type Nil = undefined | null;
```

Nullish values: `null` or `undefined`.

### Cast

```ts
type Cast<A, B> = A extends B ? A : B;
```

Retain `A` if assignable to `B`; otherwise fall back to `B`.

### PartialPick

```ts
type PartialPick<T, K extends keyof T> = { [P in K]?: T[P] };
```

Make selected object keys optional.

### RequiredPick

```ts
type RequiredPick<T, K extends keyof T> = { [P in K]-?: T[P] };
```

Make selected object keys required.

### PartialRecord

```ts
type PartialRecord<K extends PropertyKey, T> = { [P in K]?: T };
```

A `Record` with all keys optional.

### PlainObject

```ts
type PlainObject<T = unknown> = Record<PropertyKey, T>;
```

An object key/value type used as the base constraint for tree utilities. It does not check plain-object input at runtime.

### OmitOf

```ts
type OmitOf<T, K extends keyof T> = Pick<T, Exclude<keyof T, K>>;
```

Exclude selected keys from an object type.

### Realizable

```ts
type Realizable<T, Args extends unknown[] = []> = T | ((...args: Args) => T);
```

A value or a function returning it, for `realize`. `Args` describes function arguments.

### Updater

```ts
type Updater<T, Args extends unknown[] = []> =
  | T
  | ((prev?: T, ...args: Args) => T);
```

A state update: either a new value or a function deriving it from the previous value. `prev` may be `undefined` for uninitialized state; `Args` describes additional computation arguments.

`Updater` describes the argument accepted by a setter, not the setter itself. A setter can be `(updater: Updater<T>) => void`.

```ts
import type { Updater } from '@momots/core/types';

const direct: Updater<number> = 1;
const increment: Updater<number> = (prev = 0) => prev + 1;

type SetCount = (updater: Updater<number>) => void;
```

### MaybeArray

```ts
type MaybeArray<Type> = Type | Type[] | readonly Type[];
```

A single value or array, for `asArray`.

### Emptyish

```ts
type Emptyish<T> = /* Inferred using Remeda emptyish semantics */;
```

Empty-value types inferred from Remeda's emptyish semantics.

### NonEmptyish

```ts
type NonEmptyish<T> = Exclude<T, Emptyish<T>>;
```

Exclude emptyish members, for utilities such as `compact`.

### NonFalseish

```ts
type NonFalseish<T> = Exclude<T, false | Emptyish<T>>;
```

Exclude `false` and emptyish members.

### Stringifiable

```ts
type Stringifiable = { toString(): string };
```

Values with `toString()`, for `substitute` interpolation.

### Timer

```ts
interface Timer {
  schedule(callback: () => void, milliseconds: number): () => void;
}
```

A caller-provided one-shot timing capability. `schedule` arranges an asynchronous `callback` after the given milliseconds,
at most once per scheduling; even `milliseconds: 0` must not invoke the callback synchronously.
The returned cancellation function must be idempotent and prevent pending callbacks from executing.

`Timer` is a type declaration only, without a default implementation or host-type dependency. Adapt it to the runtime,
for example with `setTimeout`:

```ts
import type { Timer } from '@momots/core/types';

const timer: Timer = {
  schedule(callback, milliseconds) {
    const handle = setTimeout(callback, milliseconds);
    return () => clearTimeout(handle);
  },
};

const cancel = timer.schedule(() => console.log('done'), 1000);
cancel();
```

### Callable

```ts
type Callable = (...args: never[]) => unknown;
```

Base callable-function constraint for internal type inference.

```ts
import type {
  MaybeArray,
  NonEmptyish,
  Realizable,
  Updater,
} from '@momots/core/types';

type Names = MaybeArray<string>;                    // string | string[] | readonly string[]
type Thunk = Realizable<number, [string]>;           // number | ((s: string) => number)
type Clean = NonEmptyish<string | '' | null>;       // string
type Update = Updater<string>;                       // string | ((prev?: string) => string)
type SetValue = (updater: Updater<string>) => void;  // setter
```

## Type assertions

Subpath: `cast/*`

These functions affect only TypeScript types and neither copy nor mutate input at runtime.

### writable

Remove readonly restrictions in TypeScript while returning the same value. Mutating the returned object also mutates the source,
so callers must ensure writes are safe. Only `readonly` is removed; property literal types are not widened,
and runtime freezing from `Object.freeze` remains intact.

Available only by subpath, not re-exported from the root.

```ts
const writable = <T>(value: T): Writable<T>;
```

| Parameter | Type | Description |
| --- | --- | --- |
| `value` | `T` | Value whose readonly constraint should be removed |

| Return | Description |
| --- | --- |
| `Writable<T>` | The same value with a writable type |

```ts
import { writable } from '@momots/core/cast/writable';

const source: Readonly<{ name: string }> = { name: 'momo' };
const draft = writable(source);
draft.name = 'kit';

draft === source; // => true
source.name; // => 'kit'
```
