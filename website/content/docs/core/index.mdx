`@momots/core` provides data utilities for arrays, objects, strings, and trees. For example, wrap a single value in an array, convert object keys in bulk, turn a list with parent-child relationships into a tree, or read nested properties by path.

The package also includes type guards, TypeScript utility types, singleton caching, asynchronous call deduplication, and an in-memory delivery queue. These features do not depend on host APIs such as DOM, Fetch, or Storage. When using caches and callbacks, you still need to understand their state and execution behavior.

## Installation

```bash
bun add @momots/core@beta remeda type-fest
```

The current release channel is `beta`. `remeda` and `type-fest` are peer dependencies and must be installed alongside the package.

## Start with inputs and outputs

```ts
import { asArray, PropertyPath, toCamelCasedProperties } from '@momots/core';

asArray('momo'); // => ['momo']
toCamelCasedProperties({ user_name: 'Momo' }); // => { userName: 'Momo' }
PropertyPath.read({ user: { name: 'Momo' } }, 'user.name');
// => { exists: true, value: 'Momo' }
```

`asArray` returns the original reference for array inputs. `toCamelCasedProperties` converts only top-level keys and preserves value references. `PropertyPath.read` uses `exists` to distinguish a missing property from a property whose value is `undefined`. See the [guide](/docs/core/guide) for each function's rules and exceptions.

## Two ways to import

Common functions can be imported from the root entry point; all public APIs are available from their corresponding subpaths. Subpaths make module dependencies explicit. APIs marked “subpath only” are not re-exported from the root:

```ts
// Import from the root entry point
import { eliminate, unflat, toCamelCasedProperties } from "@momots/core";

// Import by subpath
import { eliminate } from "@momots/core/eliminate";
import { unflat } from "@momots/core/tree/unflat";
import { toCamelCasedProperties } from "@momots/core/casing";
```

## State and callback behavior

Most data transformation functions return results directly from their inputs. The following APIs also retain state or execute caller-provided functions:

- `singleton` stores the created value in the specified scope, which defaults to `globalThis`. Subsequent calls with the same key and scope reuse that value; set `pass` to bypass the cache. Do not store user-specific or request-specific state in the default scope.
- `Singleflight` retains an in-flight Promise on the instance. Overlapping calls on the same instance share it even when their arguments differ. After completion or failure, the next call executes again.
- `timeout` schedules and cancels timers through a caller-provided `Timer`. If the deadline arrives first, it stops waiting, but the source task continues to run.
- `DeliveryQueue` retains unacknowledged entries and their references on the instance. `enqueue()` only accepts entries; `flush()` sends them in order. After a failure, unacknowledged entries remain available for an explicit retry through another `flush()` call.
- `realize` immediately calls function inputs with the supplied arguments; otherwise, it returns the input value. Callbacks may have side effects. If a function itself is the business value you need to preserve, do not pass it directly to `realize`.

`sideEffects: false` in `package.json` lets bundlers remove unused modules. It does not mean every API call is free of side effects. Consult each API's documentation to determine whether it changes state, calls callbacks, or retains references.

## Choose an API for your task

| Task | APIs to consider | Check before using |
| --- | --- | --- |
| Accept a single value or an array | `asArray` | Array inputs retain their original reference |
| Convert keys in API objects | `toCamelCasedProperties`, `toCamelCasedPropertiesDeep` | The former converts only the top level; the latter works recursively |
| Build a tree from a list with `id` and `parent` | `unflat` | How missing parents are handled, and whether the input has cycles |
| Read nested properties and distinguish missing values from `undefined` | `PropertyPath.read` | String segments access plain objects; numeric segments access arrays |
| Extract a message or diagnostic summary from an error | `toErrorMessage`, `toErrorSummary` | Neither redacts data nor truncates output |
| Reuse instances or merge overlapping asynchronous calls | `singleton`, `Singleflight` | The scope of shared state, and whether different arguments may share a result |
| Set a deadline for waiting on an existing Promise | `timeout` | Supply a `Timer` explicitly; timeout does not cancel the source task |
| Collect entries and deliver batches in order | `DeliveryQueue` | Capacity includes in-flight entries; each `flush()` waits only for entries present when it was called |

Continue using your existing utility library for general collection transformations, and import these APIs as needed. For DOM, Fetch, or storage capabilities, see [`@momots/host`](/docs/host). For request middleware and response parsing, see [`@momots/drive`](/docs/drive).
