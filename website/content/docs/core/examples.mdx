These examples cover optional parameters, configuration reads, data transformation, and shared caches.
Each snippet includes inputs and results, so you can focus on the task at hand.

## Optional payloads with multiple conditions

Generate analytics parameters only when the module is visible, more data is available, and the flow ID is nonempty; otherwise return
`undefined`. Express the three conditions as boolean checks, then use `eliminate` to handle a failed check:

```ts
import { eliminate } from '@momots/core/eliminate';

function createTrackPayload(
  moduleVisible: boolean,
  hasMore: boolean,
  flowID: string,
  pageSize: number,
) {
  return eliminate(
    moduleVisible && hasMore && flowID !== '' && { flowID, pageSize },
  );
}

createTrackPayload(true, true, 'flow-42', 20);
// => { flowID: 'flow-42', pageSize: 20 }
createTrackPayload(false, true, 'flow-42', 20); // => undefined
createTrackPayload(true, true, '', 20); // => undefined
```

All conditions in this example are booleans, so `&&` returns `false` on failure, and `eliminate` converts it to
`undefined`. A general `&&` expression can also return `0`, an empty string, or other values. By default, `eliminate`
replaces only `false`; it does not remove every falsy value.

## Compute a default for an unset port

Suppose a configuration reader uses `-1` to indicate an unset port. Convert this sentinel to
`undefined` with `eliminate`, then compute the default port only when needed:

```ts
import { eliminate } from '@momots/core/eliminate';
import { realize } from '@momots/core/realize';

function readPort(raw: number, fallback: () => number = () => 3000) {
  return eliminate(raw, -1) ?? realize(fallback);
}

readPort(8080); // => 8080
readPort(-1);   // => 3000
```

`??` ensures that `fallback` is called only for a missing value; `realize` executes the function and returns its result.
This code handles only the `-1` convention. It does not validate the port range.

## Apply defaults only to missing configuration properties

Some configurations distinguish “the property is absent” from “the property exists but its value is `undefined`.”
The `exists` field returned by `PropertyPath.read` preserves this distinction:

```ts
import { PropertyPath } from '@momots/core/property-path';

const config = { logging: { level: undefined } };

PropertyPath.read(config, 'logging.level');
// => { exists: true, value: undefined }
PropertyPath.read(config, 'logging.file');
// => { exists: false }

function readConfig(source: unknown, path: string, fallback: unknown) {
  const result = PropertyPath.read(source, path);
  return result.exists ? result.value : fallback;
}

readConfig(config, 'logging.level', 'info'); // => undefined
readConfig(config, 'logging.file', 'app.log'); // => 'app.log'
```

The returned `value` has type `unknown`, so check its type before using it. This example traverses only plain objects. Use numeric
indices such as `items[0]` to read array elements. See the [guide](/docs/core/guide#propertypathread) for the complete rules.

## Normalize single-value-or-array parameters

When a function accepts either one path or an array of paths, normalize the input with `asArray` so the rest of the code needs only one loop:

```ts
import { asArray } from '@momots/core/as/array';
import type { MaybeArray } from '@momots/core/types';

function watch(paths: MaybeArray<string>) {
  for (const path of asArray(paths)) {
    // Handle both 'a' and ['a', 'b'] in the same way
    console.log('watching', path);
  }
}

watch('src');
watch(['src', 'test']);
```

## Remove empty entries from a tag list

Before submitting tags, remove empty strings and nullish values to produce a new array:

```ts
import { compact } from '@momots/core/compact';

const tags = ['react', '', null, 'bun', undefined, 'momo'];
compact(tags); // => ['react', 'bun', 'momo']
```

The original array is unchanged. `compact` also removes `false` and empty containers such as empty arrays and objects, but preserves `0` and `NaN`.

## Adapt snake_case API responses

When the backend uses `user_name` and your application uses `userName`, convert property names at request and response boundaries:

```ts
import { toCamelCasedProperties } from '@momots/core/casing/toCamelCasedProperties';
import { toSnakeCasedProperties } from '@momots/core/casing/toSnakeCasedProperties';

// Inbound: snake_case -> camelCase
const user = toCamelCasedProperties({ user_name: 'Momo', is_admin: true });
// => { userName: 'Momo', isAdmin: true }

// Outbound: camelCase -> snake_case
const payload = toSnakeCasedProperties({ userName: 'Momo', isAdmin: true });
// => { user_name: 'Momo', is_admin: true }
```

## Interpolate localized text

Fill a template with a name and a message count. `name|Guest` in the template uses “Guest” when the name is missing:

```ts
import { substitute } from '@momots/core/substitute';

const t = {
  greeting: 'Hello, {{name|Guest}}! You have {{count}} new messages.',
};

substitute(t.greeting, { name: 'Momo', count: 3 });
// => 'Hello, Momo! You have 3 new messages.'

substitute(t.greeting, { count: 0 });
// => 'Hello, Guest! You have 0 new messages.'
```

## Reuse a cache in the same global scope

When several modules need the same in-memory cache, agree on a key and let `singleton` create the cache on the first call.
Subsequent calls using the same scope and key retrieve the stored value:

```ts
import { singleton } from '@momots/core/singleton';

const cacheKey = Symbol.for('example:core:cache');

function getCache() {
  return singleton(cacheKey, () => new Map<string, number>());
}

getCache().set('visits', 1);
getCache().get('visits'); // => 1
getCache() === getCache(); // => true
```

The default cache is stored on `globalThis`; separate processes, workers, or pages each have their own cache. Reuse during hot module replacement
also requires both the global scope and key to persist. `pass: true` bypasses the cache. On the server, do not store request-specific state
such as user tokens in the default scope.

## Render an organization table as a tree

The data table represents reporting relationships through `id` and `parent`. Use `unflat` to build a tree with `children`,
then traverse it by level with `visit`. Root nodes have a depth of `0`:

```ts
import { unflat } from '@momots/core/tree/unflat';
import { visit } from '@momots/core/tree/visit';

const employees = [
  { id: 'ceo', parent: null, name: 'Zhang' },
  { id: 'cto', parent: 'ceo', name: 'Li' },
  { id: 'dev1', parent: 'cto', name: 'Wang' },
  { id: 'dev2', parent: 'cto', name: 'Zhao' },
];

const org = unflat(employees);

visit(org, (node, depth) => {
  console.log('  '.repeat(depth) + node.name);
});
// Zhang
//   Li
//     Wang
//     Zhao
```

## Sum the digits of a number

Use `sumdig` to add a sequence of digits:

```ts
import { sumdig } from '@momots/core/sumdig';

sumdig(2026); // => 10, i.e. 2 + 0 + 2 + 6
sumdig('00129'); // => 12
sumdig('12x'); // => NaN
```

Inputs should be digit-only strings or ordinary nonnegative integers. `sumdig` does not validate the input format: whitespace contributes `0`,
and characters that cannot be converted to numbers produce `NaN`, including minus signs, decimal points, and letters in scientific notation.
