title: Class names and style variants

`cx` merges class names and resolves Tailwind conflicts, `cva` defines reusable style variants, and `asClass` combines static classes with state callbacks. Use them to wrap application components while retaining momo theme tokens.

## Imports

```tsx
import { cva, cx } from "@momots/design/tailwind";
import { asClass } from "@momots/design/shared";
import type { VariantProps } from "cva";
```

## cx: merge class names

`cx` accepts strings, conditional objects, and nested arrays, ignores inactive conditional entries, and resolves conflicting utilities in input order. Caller-supplied overrides usually belong last.

```tsx
cx("px-2", "px-4");
// "px-4"

cx(
  "px-2 text-momo-body-md",
  [false, undefined, "px-4"],
  { "text-momo-fg-danger": true, hidden: false },
);
// "text-momo-body-md px-4 text-momo-fg-danger"
```

momo's merge configuration registers semantic typography tokens such as `text-momo-body-md` as font-size classes, allowing them to coexist with color classes such as `text-momo-fg-danger`. Conflicts within font-size or color groups are still resolved.

```tsx
cx("text-momo-body-sm", "text-momo-body-md");
// "text-momo-body-md"

cx("text-momo-body-md", "text-momo-fg-danger");
// "text-momo-body-md text-momo-fg-danger"
```

Modifiers such as `hover:` distinguish conflicts in different states. The merger uses configured Tailwind class groups rather than browser computed styles; it does not automatically understand override relationships between arbitrary custom CSS classes.

## cva: define style variants

`cva` uses the same class merging configuration. `base` provides base styles, `variants` defines variants, `defaultVariants` specifies defaults, and `compoundVariants` adds styles to combinations meeting multiple conditions.

```tsx
const label = cva({
  base: "text-momo-body-md text-momo-fg-default",
  variants: {
    size: {
      sm: "text-momo-body-sm",
      md: "text-momo-body-md",
    },
    invalid: {
      true: "text-momo-fg-danger",
    },
  },
  defaultVariants: { size: "sm" },
  compoundVariants: [
    { size: "sm", invalid: true, className: "font-semibold" },
  ],
});

type LabelVariants = VariantProps<typeof label>;

label({ invalid: true });
// "text-momo-body-sm text-momo-fg-danger font-semibold"

label({ invalid: true, className: "text-lg text-momo-fg-muted" });
// "font-semibold text-lg text-momo-fg-muted"
```

A caller's `className` can override conflicting classes in base styles and variants. All classes must be discoverable by the application's Tailwind scanner; these functions organize class names but do not generate CSS.

## asClass: compose state styles

Some components accept either a string or a state callback for `className`. `asClass` converts multiple inputs into one `(state) => string`, evaluates each with the same state, and merges the results through `cx`.

```tsx
type FieldState = { disabled: boolean; invalid: boolean };

const className = asClass<FieldState>(
  "px-3 text-momo-body-md",
  (state) => (state.disabled ? "opacity-50" : undefined),
  (state) => (state.invalid ? "text-momo-fg-danger" : undefined),
);

className({ disabled: true, invalid: false });
// "px-3 text-momo-body-md opacity-50"
```

Each input has type `string | undefined | ((state: S) => string | undefined)`. Conditional objects and arrays accepted by `cx` are not accepted directly; call `cx` inside a callback to use them. The returned function suits components supporting state callbacks; for native DOM elements, call it first to obtain a string.

## asData: generate data attributes

When wrapping components, use `asData` from the same `shared` entry point to generate data attributes consistently:

```tsx
import { asData } from "@momots/design/shared";

asData("label");
// { "data-slot": "label" }

asData({ slot: "label", state: "invalid" });
// { "data-slot": "label", "data-state": "invalid" }

<span {...asData("label")} className={label({ invalid: true })} />;
```

Do not include the `data-` prefix in object keys. The function only adds that prefix; it does not convert camelCase to kebab-case. Values may be strings or `undefined`; omitting the argument returns an empty object. These attributes provide selectors and debugging markers without adding interaction behavior.
