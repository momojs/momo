Content Slots 是组件配置内容节点的通用约定：内容属性提供要显示的内容，`slots` 配置承载内容的节点。Drawer、Popover、Sheet 与 Dialog 支持标题、说明、正文和页脚；Alert、Toast 和 Tooltip 按各自结构提供对应的内容与 slots。

## 内容与节点

`title`、`description`、`children`、`footer` 都表示内容。`header` 是标题与说明的容器，通过 `slots.header` 配置；正文容器使用 `slots.content`。

Drawer、Popover、Sheet 和 Dialog 的 header、正文与 footer 容器默认渲染为 `div`，可通过对应 slot 的 `render` 指定元素或提供渲染回调。

```tsx
<Popover
  trigger={<Button>设置</Button>}
  title="工作区设置"
  description="修改工作区的显示方式。"
  footer={<PopoverClose render={<Button />}>完成</PopoverClose>}
  slots={{
    header: { render: <header />, className: "gap-2" },
    title: { render: <h3 />, id: "workspace-title" },
    description: { className: "text-momo-fg-muted" },
    content: { render: <section />, className: "space-y-3" },
    footer: { render: <footer />, className: "justify-end" },
  }}
>
  <Input aria-label="工作区名称" />
</Popover>
```

上面的内容字段与五个 slot 同样适用于 Drawer、Sheet 和 Dialog。各组件保留自己的开关状态、定位、手势与动画属性。

## Slot 规则

| 配置 | 行为 |
| --- | --- |
| 省略 / `undefined` | 有对应内容时使用默认节点 |
| props object | 配置节点属性、ref、事件和样式 |
| `<section />` 或 `{ render: <section /> }` | 使用指定元素，合并默认属性、样式、事件和 ref |
| `(props, state) => …` 或 `{ render: (props, state) => … }` | 自行渲染节点；必须透传 `props`，可用状态以该 slot 的类型为准 |
| `false` | 移除该节点及其子树 |

直接传元素或回调是 `{ render }` 的简写，具有相同的属性合并行为。三种形式可混合使用：

```tsx
<Popover
  title="工作区设置"
  footer={<Button>保存</Button>}
  slots={{
    header: <header />,
    title: <h3 id="workspace-title" />,
    content: {
      className: "space-y-3",
      render: (props, state) => <section {...props} />,
    },
    footer: (props, state) => <footer {...props} />,
  }}
>
  <SettingsForm />
</Popover>
```

回调的 `props` 和 `state` 从具体节点推导。普通容器的 `state` 为空对象；Toast 的 `content` 则包含 `index`、`behind`、`expanded`。简写只对已有 `render` 能力的节点开放。

slot 配置不接受 `children`、字符串、数字、`true` 或 `null`，内容统一放在顶层属性中。直接传入的元素和对象中的 `render` 元素都应保持无内容，或由回调透传 `props.children`。`0` 和空字符串是有效内容；`undefined`、`null`、`false` 不创建对应内容节点。

标题与说明继续使用各组件自己的语义节点。更改标签时保留组件提供的 ID 和 ARIA 属性；需要自定义 ID 时可放在 slot props 或 render 元素上。关闭 `slots.header` 会同时移除标题与说明；如果浮层仍需显示，应通过其 popup 属性提供 `aria-label` 等可访问名称。

render 元素上非空值的 ID 优先于 slot props 的 ID；`id={undefined}` 或 `id={null}` 按未提供处理，保留 slot props 的 ID，或由语义节点生成 ID，确保 ARIA 引用与实际节点一致。

## 支持范围

| 组件 | 内容字段 | 内容 slots |
| --- | --- | --- |
| Drawer / Popover / Sheet / Dialog | `title`、`description`、`children`、`footer` | `header`、`title`、`description`、`content`、`footer` |
| Tooltip | `children` | `content` |
| Alert | `title`、`description`、`icon`、`action` | `icon`、`content`、`title`、`description`、`action` |
| ToastOptions | `title`、`description`；操作通过 `actionProps` 提供 | 由 Provider / List 的 `slots` 配置 |
| ToastProvider / ToastList | Provider 的 `children` 是应用子树 | `content`、`text`、`title`、`description`、`icon`、`action`、`close` |

Alert 的 `content` 包裹标题、说明和操作；Toast 的 `content` 包裹整条通知，`text` 包裹标题与说明。它们没有独立正文或 footer，因此不暴露这两个内容字段。

Toast 的 `content`、`text`、`title`、`description` 支持 `render`；`icon`、`action`、`close` 保留 Motion 节点，可配置其原生 Motion 属性或传 `false`。ToastProvider 的 `children` 始终是应用子树，通知内容通过 `toast.add({ title, description })` 提供。

## 复用配置类型

需要将配置提取为变量或封装组件时，从对应组件的公开 Props 类型取得 `slots`，即可保留各节点的属性与回调状态推导：

```tsx
import type { DialogProps } from "@momots/design/components/dialog";

type DialogSlots = NonNullable<DialogProps["slots"]>;

const slots = {
  title: <h3 />,
  content: {
    className: "space-y-3",
    render: (props, state) => <section {...props} />,
  },
  footer: false,
} satisfies DialogSlots;
```

其他组件使用相同方式，例如 `PopoverProps["slots"]`、`AlertProps["slots"]` 或 `ToastProviderProps["slots"]`。组件还导出 `DialogContentSlots` 等节点类型映射；声明可直接传给组件的配置时，使用对应 Props 的 `slots` 类型。

## 从旧属性迁移

| 原写法 | 新写法 |
| --- | --- |
| Dialog / Popover `titleProps={props}` | `slots={{ title: props }}` |
| Dialog / Popover `contentClassName="…"` | `slots={{ content: { className: "…" } }}` |
| Dialog / Popover `headerClassName` 等内容区域样式 | 对应 `slots.header` / `title` / `description` / `footer` 的 `className` |
| Drawer `content={{ className: "…" }}` | `slots={{ content: { className: "…" } }}`，现在只配置正文 |
| Drawer / Sheet `title={<h3>标题</h3>}` 作为 render | `title="标题" slots={{ title: { render: <h3 /> } }}` |
| Drawer / Sheet `footer` 的 render callback | `footer={内容}`，回调放到 `slots.footer.render` |
| Alert `titleSlot={props}` 等 | `slots={{ title: props }}` 等 |
| ToastProvider `close={{ label: "关闭" }}` 等 | `slots={{ close: { label: "关闭" } }}` 等 |

部分组件属性还支持完整节点替换，例如 [Numeric 的独立插槽](/docs/design/numeric) 和 [Sheet 的遮罩与关闭节点](/docs/design/sheet)。这些属性直接接收 ReactNode 时会替换整个节点，不会像内容 `slots` 一样合并节点属性；具体配置规则见对应组件文档。
