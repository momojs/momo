Content Slots defines a shared convention: content props supply what is displayed, while `slots` configure the nodes holding it. Section, Drawer, Popover, Sheet, Dialog, and Menu support headings, descriptions, body, and footer; Alert, Toast, and Tooltip expose content and slots suited to their structures.

## Content and nodes

`title`, `description`, `children`, and `footer` represent content. `header` wraps the title and description and is configured with `slots.header`; `slots.content` configures the body container.

Header, body, and footer containers in Section, Drawer, Popover, Sheet, Dialog, and Menu default to `div`. Set the corresponding slot's `render` to an element or render callback to change it.

```tsx
<Popover
  trigger={<Button>Settings</Button>}
  title="Workspace settings"
  description="Change how the workspace is displayed."
  footer={<PopoverClose render={<Button />}>Done</PopoverClose>}
  slots={{
    header: { render: <header />, className: "gap-2" },
    title: { render: <h3 />, id: "workspace-title" },
    description: { className: "text-momo-fg-muted" },
    content: { render: <section />, className: "space-y-3" },
    footer: { render: <footer />, className: "justify-end" },
  }}
>
  <Input aria-label="Workspace name" />
</Popover>
```

The content fields and five slots above also apply to Section, Drawer, Sheet, Dialog, Menu, and MenuSubmenu. Each retains its own layout and interaction props.

## Slot rules

| Configuration | Behavior |
| --- | --- |
| Omitted / `undefined` | Uses the default node when corresponding content exists |
| Props object | Configures node attributes, ref, events, and styles |
| `<section />` or `{ render: <section /> }` | Uses the specified element, merging default props, styles, events, and ref |
| `(props, state) => …` or `{ render: (props, state) => … }` | Renders the node manually; forward `props`. Available state depends on the slot's type |
| `false` | Removes the node and its subtree |

Passing an element or callback directly is shorthand for `{ render }`, with identical prop merging. All three forms can be combined:

```tsx
<Popover
  title="Workspace settings"
  footer={<Button>Save</Button>}
  slots={{
    header: <header />,
    title: <h3 id="workspace-title" />,
    content: {
      className: "space-y-3",
      render: (props, state) => <section {...props} />,
    },
    footer: (props, state) => <footer {...props} />,
  }}
>
  <SettingsForm />
</Popover>
```

Callback `props` and `state` are inferred from each node. Generic containers have empty state; Toast `content` includes `index`, `behind`, and `expanded`. MenuItem content state includes `highlighted` and `disabled`, checkbox/radio items add `checked`, and submenu triggers add `open`. Shorthand is available only for nodes already supporting `render`.

Slot configuration does not accept `children`, strings, numbers, `true`, or `null`; supply content through top-level props. Direct elements and `render` elements should have no content, or callbacks should forward `props.children`. `0` and empty strings are valid content; `undefined`, `null`, and `false` create no content node.

Titles and descriptions retain each component's semantic nodes. Preserve provided IDs and ARIA attributes when changing elements; custom IDs can be set on slot props or render elements. Disabling `slots.header` removes both title and description; give remaining popups an accessible name, such as `aria-label`, through their popup props.

A non-null ID on a render element takes priority over the slot props ID. `id={undefined}` and `id={null}` count as absent, preserving the slot ID or allowing the semantic node to generate one so ARIA references match the actual node.

Some component props allow full node replacement, including [Numeric's independent slots](/docs/design/numeric) and [Sheet's backdrop and close nodes](/docs/design/sheet). Passing ReactNode directly replaces the whole node without the prop merging provided by content `slots`. Consult each component's rules.

## Supported components

| Component | Content fields | Content slots |
| --- | --- | --- |
| Section / Drawer / Popover / Sheet / Dialog / Menu / MenuSubmenu | `title`、`description`、`children`、`footer` | `header`、`title`、`description`、`content`、`footer` |
| Tooltip | `children` | `content` |
| Combobox | `emptyText`; option content comes from `options` | `control`, `input`, `trigger`, `clear`, `item`, `itemIndicator`, `chip`, `chipRemove`, `empty` |
| MenuItem / MenuLinkItem | `children`、`description`、`icon`、`extra`、`shortcut` | `icon`、`content`、`description`、`extra`、`shortcut` |
| MenuCheckboxItem / MenuRadioItem | Same as above | Same as above, plus `indicator` |
| MenuSubmenu.triggerProps | Trigger content comes from `label`, `icon`, and triggerProps `description`, `extra`, `shortcut` | `icon`, `content`, `description`, `extra`, `shortcut`, `arrow` |
| Alert | `title`、`description`、`icon`、`action` | `icon`、`content`、`title`、`description`、`action` |
| ToastOptions | `title`, `description`; actions use `actionProps` | Configured through Provider / List `slots` |
| ToastProvider / ToastList | Provider `children` is the application subtree | `content`, `text`, `title`, `description`, `icon`, `action`, `close` |

Alert `content` wraps its title, description, and action. Toast `content` wraps the entire notification, and `text` wraps title and description. Neither has a separate body or footer, so those content fields are not exposed.

Toast `content`, `text`, `title`, and `description` support `render`. `icon`, `action`, and `close` retain Motion nodes and accept native Motion props or `false`. ToastProvider `children` always means the application subtree; supply notifications through `toast.add({ title, description })`.

## Reusing configuration types

To extract configuration into a variable or wrapper component, read `slots` from its public Props type, preserving node props and callback-state inference:

```tsx
import type { DialogProps } from "@momots/design/components/dialog";

type DialogSlots = NonNullable<DialogProps["slots"]>;

const slots = {
  title: <h3 />,
  content: {
    className: "space-y-3",
    render: (props, state) => <section {...props} />,
  },
  footer: false,
} satisfies DialogSlots;
```

Other components work the same way, such as `PopoverProps["slots"]`, `AlertProps["slots"]`, and `ToastProviderProps["slots"]`. Components also export node type maps such as `DialogContentSlots`; use the Props `slots` type for configuration passed directly to a component.
