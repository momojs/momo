`Section` represents a related group of content, such as settings or a dashboard overview. It renders a native `<section>` by default, using momo surface, radius, typography, and spacing tokens. Its content API matches Drawer, Popover, Sheet, and Dialog: `title`, `description`, `children`, and `footer` supply content; `slots` configure the nodes.

## Basic usage

```tsx
import { Button } from '@momots/design/components/button';
import { Section } from '@momots/design/components/section';

<Section
  title='Notifications'
  description='Choose what you want to be reminded about.'
  footer={<Button size='sm'>Save</Button>}
>
  <NotificationSettings />
</Section>
```

Only areas with content are rendered. Without a title or description there is no header; omitted body or footer nodes leave no gaps. As with other content slots, `0` and an empty string are valid content; `undefined`, `null`, and `false` mean absent.

## Appearance and spacing

| Property | Default | Description |
| --- | --- | --- |
| `variant` | `muted` | `muted`: subdued borderless surface for groups; `raised`: themed surface, border, and light shadow; `outline`: transparent background and border; `ghost`: transparent and borderless, retaining semantics and spacing |
| `size` | `md` | `sm` / `md` / `lg` control padding and spacing, using `momo-space-sm` / `md` / `lg` |
| `className` | — | Root styles for width, layout, and other customization |
| `render` | — | Root element or `(props, state) => JSX` callback |
| `slots` | — | Node configuration for header, title, description, body, and footer |

`size` does not constrain width or height. Set width with layout classes in `className`. The body grows with content and footer actions may wrap.

## Content slots

```tsx
<Section
  title='Workspace settings'
  description='Edit the information shown publicly.'
  footer={<Button>Save</Button>}
  slots={{
    header: <header />,
    title: { render: <h2 />, id: 'workspace-title' },
    description: <p />,
    content: { className: 'grid gap-momo-sm' },
    footer: (props, _state) => <footer {...props} />,
  }}
>
  <SettingsForm />
</Section>
```

Each slot accepts a props object, element shorthand, render callback, or `false`. Elements and callbacks can also be provided in an object's `render` field. Forward `props`, including ref and children, to preserve styles, events, and content.

| Slot | Default node | Content source |
| --- | --- | --- |
| `header` | `div` | Container for title and description |
| `title` | `h3` | `title` |
| `description` | `div` | `description`; supports rich text and block content |
| `content` | `div` | `children` |
| `footer` | `div` | `footer` |

`slots.header=false` removes both title and description. Set heading level with `slots.title={{ render: <h2 /> }}`, keeping content in `title`. Do not put `children` in slot configuration. See [Content Slots](/docs/design/content-slots).

## Semantics and accessible names

The root defaults to `<section>`. When a title is rendered, Section generates its `id` and sets `aria-labelledby` on the root, creating a named `region` landmark. This association is already present in server-rendered markup.

| Condition | Result |
| --- | --- |
| A title is rendered | `aria-labelledby` references the title, reusing its existing `id` if supplied |
| No title, or `slots.header` / `slots.title` is `false` | No `aria-labelledby`; an unnamed `<section>` is not a landmark |
| Explicit `aria-label` or `aria-labelledby` | Uses the explicit value instead of automatic association |

```tsx
<Section title='Privacy' slots={{ title: { id: 'privacy-title' } }}>
  Photo access and data export.
</Section>
// <section aria-labelledby="privacy-title">…<h3 id="privacy-title">Privacy</h3>…

<Section aria-label='Account' title='Sign-in information'>
  …
</Section>
```

The root render callback receives `SectionState` with `slot: 'section'`, `variant`, and `size`, also exposed as `data-slot`, `data-variant`, and `data-size`. Content node render state is an empty object.

Section adds no click semantics, tab stop, or live region. It describes page structure; its buttons and links handle interaction. Independent repeated items, such as records or products, belong in `<article>` or `<li>`. To reuse Section's appearance for them, change the root with `render={<article />}` or `render={<li />}`.

## Manual composition

Use individual nodes for a custom header or different content order:

```tsx
import {
  SectionRoot, SectionHeader, SectionTitle, SectionDescription,
  SectionContent, SectionFooter,
} from '@momots/design/components/section';

<SectionRoot size='lg'>
  <SectionHeader>
    <SectionTitle render={<h2 />}>Team workspace</SectionTitle>
    <SectionDescription>Members and projects at a glance.</SectionDescription>
    <Badge>Pro</Badge>
  </SectionHeader>
  <SectionContent><ProjectList /></SectionContent>
  <SectionFooter className='justify-between'>
    <span>8 members</span>
    <Button>Manage members</Button>
  </SectionFooter>
</SectionRoot>
```

All primitives support native props, ref, and `render`. `SectionTitle` registers its `id` with the nearest `SectionRoot`, automatically naming manually composed sections after mounting. Use `Section` or explicit `aria-labelledby` when this association must exist in server markup. Use only one `SectionTitle` per `SectionRoot`.

`SectionRoot` provides surface and area spacing and renders children directly; `Section` generates the structure from content props. Nested sections use their own `size`, and each heading names only its own section.
