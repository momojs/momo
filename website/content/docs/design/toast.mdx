`Toast` 适合在不打断当前任务的情况下反馈操作结果。组件内置独立的通知 manager、计时器、焦点与播报逻辑；`motion/react` 直接管理进场、退场、堆叠重排、Pointer drag 和按钮按压，不依赖 Base UI 的 Toast 状态机。

## 安装 Provider

在应用根布局附近挂载一次 `ToastProvider`。触发通知的组件必须位于 Provider 的 React 子树中；通知默认通过 Portal 显示在页面右下角。

```tsx
import { ToastProvider } from "@momots/design/components/toast";

export function App() {
  return (
    <ToastProvider timeout={5000} limit={4}>
      <AppRoutes />
    </ToastProvider>
  );
}
```

`timeout={0}` 会关闭默认自动移除。Provider 默认使用 `bottom-right`，也支持 `top-right`、`top-center` 与 `bottom-center`；`portal={false}` 可把 Viewport 留在当前 React 位置。

## 创建通知

`useToast()` 返回响应式 controller。`add()` 会返回通知 id，后续可用于更新或关闭同一条通知。

```tsx
import { useToast } from "@momots/design/components/toast";

function SaveButton() {
  const toast = useToast();

  return (
    <button
      type="button"
      onClick={() => {
        toast.add({
          type: "success",
          title: "保存成功",
          description: "最新内容已同步。",
        });
      }}
    >
      保存
    </button>
  );
}
```

### 语义类型

| Type               | 用途               |
| ------------------ | ------------------ |
| `default`          | 中性反馈           |
| `info`             | 新信息或非阻塞更新 |
| `success`          | 操作完成           |
| `warning`          | 需要关注的情况     |
| `danger`           | 失败或风险         |
| `loading`          | Promise 进行中     |

`type` 使用上述内建类型。消息必须通过标题或说明表达含义，不能只依赖颜色和图标。

## 动作与关闭

通过 `actionProps` 创建通知动作；属性会合并到内建的 Motion button：

```tsx
toast.add({
  type: "warning",
  title: "项目已归档",
  actionProps: {
    children: "撤销",
    onClick: restoreProject,
  },
});
```

每条通知都提供带可访问名称的关闭按钮。`toast.close(id)` 关闭指定通知，`toast.close()` 关闭全部通知。使用 `timeout: 0` 的持久通知时，不应移除关闭入口。

`onClose(reason)` 在通知离开 manager 时触发，reason 为 `close`、`escape`、`programmatic`、`swipe` 或 `timeout`；`onRemove()` 在 Motion 退场结束、DOM 真正卸载时触发。

## 更新、去重与 Promise

保存 `add()` 返回的 id，即可原位更新通知；使用同一个显式 id 再次 `add()` 也会合并现有通知并刷新计时器。

更新导致内容高度变化时，Toast 会平滑调整高度；宽度保持由 viewport 决定。开启减少动态效果时，高度立即更新。

默认状态图标共用 `Spinner` 的 Morphicons 入口：loading 完成时从当前圆弧平滑变成结果图标，其他状态之间也会继续变形，沿用 [Icon](/docs/design/icon) 的 `snap` 主题和减少动态效果策略。自定义图标仍可通过 `slots.icon.children` 提供。

```tsx
const id = toast.add({
  type: "loading",
  title: "正在上传",
  timeout: 0,
});

toast.update(id, {
  type: "success",
  title: "上传完成",
  timeout: 5000,
});
```

异步流程可以交给 `promise()`：

```tsx
try {
  await toast.promise(uploadFile(file), {
    loading: { title: "正在上传" },
    success: { title: "上传完成" },
    error: { title: "上传失败", priority: "high" },
  });
} catch (error) {
  // promise() 保留原 Promise 的 rejected 语义。
}
```

Promise 的 loading 通知默认不会自动关闭；成功和失败分别默认使用 `success` 与 `danger` 类型，并恢复 Provider 的默认关闭时间。`success` 与 `error` 也支持接收结果或异常的函数；如果这些函数本身抛错，组件会关闭对应通知并把异常交给调用方，成功结果的处理异常不会再调用 `error`。失败若会阻塞流程，还应在页面内保留可恢复的错误状态，不能只依赖短暂通知。

## 队列与 Motion

这套实现以一个 manager 数组作为唯一状态源，队列增删后由 `AnimatePresence` 和同一组 Motion targets 完成卸载与重排，没有第二套 CSS transition 或组件库生命周期参与动画。

- 新通知从空间来源进入；右侧 placement 默认沿 x 轴进入，居中 placement 沿 y 轴进入。
- 紧凑堆叠默认每层偏移 `10px`、缩小 `0.06`、降低 `0.2` opacity；响应间隔沿用主题的 `stagger.tight`。
- 进场、退出与队列重排沿用 `useFeel('ui')` 的主题 spring，透明度使用主题的淡入淡出配置；拖动回弹沿用 `snap` spring。
- 默认保留四层可见队列，只有最前面的通知可交互和被辅助技术访问。DOM 只保留可见层与两条透明缓冲项，长队列不会让所有通知同时参与每一帧动画；关闭前项后，后项通过 spring 连续接位。
- `stackOffsetY`、`stackScale`、`stackOpacity`、`staggerInterval` 和 `toastSpring` 可调整整套堆叠手感。

Motion drag 以 1:1 比例跟随 Pointer。右侧通知默认向右滑动关闭；顶部居中的通知向上关闭，底部居中的通知向下关闭。释放时会同时考虑位移和速度，达到阈值后把速度交给退场 spring，否则从当前位置回弹。

鼠标停留、键盘焦点、页面失焦或切到后台时，自动关闭计时器会暂停；也可通过 `paused` 手动暂停。所有暂停原因都解除后，计时器才从剩余时间继续；更新通知会刷新完整计时。按 `F6` 可在当前焦点与通知区域之间切换；聚焦通知后按 `Escape` 将其关闭。

系统开启 reduced motion 或使用 `calm` 模式时，自动进出场和重排不再使用位移、缩放与 spring，仅保留短 opacity 反馈；`off` 模式立即更新。用户直接拖动仍保持 Pointer 1:1 跟随。

## Priority 与可访问性

默认 `priority="low"` 使用 `role="status"`；只有真正紧急且需要立即关注的信息才使用 `priority="high"`，它会改用 `role="alert"`。

```tsx
toast.add({
  priority: "high",
  type: "danger",
  title: "连接已中断",
  description: "未保存的更改可能丢失。",
});
```

Viewport 提供命名的通知区域，Root 自动关联标题和说明；后方队列会设为 `inert` 与 `aria-hidden`，退出后尝试把焦点交给下一条通知或进入 Viewport 前的元素。不要再叠加冲突的 `aria-live`、`aria-modal` 或第二套拖动处理。

## Slots 与 primitives

`ToastProvider` 暴露以下配置：

- `portal`：配置 `container` 或 `disabled`；也可直接传 `false`。
- `viewport`：追加承载层的原生 div props、class 与 ARIA 属性。
- `root`：追加每条 Motion Root 的 class、事件与 ARIA；`animate`、`initial`、`exit`、`style` 和 drag 生命周期由封装保留。
- `slots.content`、`slots.text`、`slots.title`、`slots.description`：配置内容节点，支持 `render` 更改标签或用 `false` 移除。
- `slots.icon`、`slots.action`、`slots.close`：配置 Motion 节点属性，或用 `false` 移除。

通知的 `title`、`description` 内容统一放在 `ToastOptions`，Provider 的 `children` 仍是应用子树。完整约定见 [Content Slots](/docs/design/content-slots)。

```tsx
<ToastProvider
  placement="top-center"
  viewport={{ "aria-label": "系统通知" }}
  root={{ className: "max-w-sm" }}
  slots={{ close: { label: "关闭" } }}
>
  <App />
</ToastProvider>
```

同一入口导出 `ToastPortal`、`ToastViewport`、`ToastRoot`、`ToastContent`、`ToastIcon`、`ToastText`、`ToastTitle`、`ToastDescription`、`ToastAction`、`ToastClose` 和 `ToastList`。依赖通知或 manager 上下文的 primitives 必须位于 `ToastProvider` 中。

## Props

### ToastProvider

| Prop                                    | 类型                                                               | 说明                                                |
| --------------------------------------- | ------------------------------------------------------------------ | --------------------------------------------------- |
| `children`                              | `ReactNode`                                                        | 使用 controller 的业务组件                          |
| `timeout`                               | `number`                                                           | 默认 `5000`；`0` 表示不自动关闭                     |
| `paused`                                | `boolean`                                                          | 手动暂停自动关闭，默认 `false`                      |
| `limit`                                 | `number`                                                           | 可见堆叠层数，默认 `4`                              |
| `toastManager`                          | `ToastManager`                                                     | 可选的外部独立 manager                              |
| `placement`                             | `"top-right" \| "top-center" \| "bottom-right" \| "bottom-center"` | 位置，默认 `"bottom-right"`                         |
| `swipeDirection`                        | 方向或方向数组                                                     | 自定义可滑动关闭方向；空数组关闭拖动                |
| `stackOffsetY`                          | `number`                                                           | 每层 y 偏移，默认 `10`                              |
| `stackScale`                            | `number`                                                           | 每层缩放差，默认 `0.06`                             |
| `stackOpacity`                          | `number`                                                           | 每层透明度差，默认 `0.2`                            |
| `staggerInterval`                       | `number`                                                           | 队列响应间隔（秒），默认取主题的 `stagger.tight`      |
| `toastSpring`                           | `{ stiffness; damping; mass? }`                                    | 覆盖进出场与重排 spring；刚度和阻尼也用于回弹         |
| `portal`、`viewport`、`root` | primitive config                                                   | 配置结构层                                          |
| `slots`                        | slot config                                                        | 配置内容节点或移除可选节点                            |

### useToast

`useToast()` 默认使用 `strict: true`，要求组件位于 `ToastProvider` 内。允许独立使用的组件可以调用 `useToast({ strict: false })`：有 Provider 时返回同一个响应式 controller，没有时返回 `null`，由调用方选择备用展示方式。

```tsx
const toast = useToast({ strict: false });

function showHelp() {
  if (toast) toast.add({ description: "用于接收工作区通知。" });
  else setHelpOpen(true);
}
```

| 方法                      | 说明                                |
| ------------------------- | ----------------------------------- |
| `add(options)`            | 创建或按固定 id 更新通知，并返回 id |
| `update(id, options)`     | 原位更新通知并刷新计时器            |
| `close(id?, reason?)`     | 关闭一条或全部通知                  |
| `promise(value, options)` | 管理 loading、success 与 error 状态 |
| `toasts`                  | 当前 Provider 管理的响应式通知数组  |

`createToastManager()` 可用于 React 组件之外；把返回值传给 `ToastProvider.toastManager`，即可让外部调用与界面共享同一队列。
