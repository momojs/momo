## Installing the Provider

Mount one `ToastProvider` near the application root. Notification-triggering components must belong to its React subtree. Notifications portal to the bottom-right of the page by default.

```tsx
import { ToastProvider } from "@momots/design/components/toast";

export function App() {
  return (
    <ToastProvider timeout={5000} limit={4}>
      <AppRoutes />
    </ToastProvider>
  );
}
```

`timeout={0}` disables default automatic removal. Placement defaults to `bottom-right`, with `top-right`, `top-center`, and `bottom-center` also supported. `portal={false}` retains Viewport at its current React position.

## Creating notifications

`useToast()` returns a reactive controller. `add()` returns a notification ID for later updates or dismissal.

```tsx
import { useToast } from "@momots/design/components/toast";

function SaveButton() {
  const toast = useToast();

  return (
    <button
      type="button"
      onClick={() => {
        toast.add({
          type: "success",
          title: "Saved successfully",
          description: "The latest content has synced.",
        });
      }}
    >
      Save
    </button>
  );
}
```

### Semantic types

| Type | Purpose |
| --------- | ------------------ |
| `default` | Neutral feedback |
| `info` | New information or non-blocking updates |
| `success` | Completed actions |
| `warning` | Situations needing attention |
| `danger` | Failure or risk |
| `loading` | Pending Promise |

`type` uses these built-in values. Messages must communicate through title or description, not solely color and icons.

## Actions and dismissal

Create notification actions through `actionProps`, merged into the built-in Motion button:

```tsx
toast.add({
  type: "warning",
  title: "Project archived",
  actionProps: {
    children: "Undo",
    onClick: restoreProject,
  },
});
```

Every notification includes a named close button. `toast.close(id)` closes one; `toast.close()` closes all. Do not remove dismissal controls from persistent notifications using `timeout: 0`.

`onClose(reason)` fires when the notification leaves the manager, with `close`, `escape`, `programmatic`, `swipe`, or `timeout`. `onRemove()` fires after Motion exit completes and the DOM actually unmounts.

## Updates, deduplication, and Promises

Save the ID returned by `add()` to update in place. Calling `add()` again with the same explicit ID merges into the existing notification and refreshes its timer.

Content-height changes animate smoothly, while viewport determines width. Reduced motion updates height immediately.

Default status icons share Spinner's Morphicons integration: loading morphs from its current arc into the result icon, and other status changes also morph. They follow [Icon](/docs/design/icon)'s `snap` theme and reduced-motion policy. Supply custom icons through `slots.icon.children`.

```tsx
const id = toast.add({
  type: "loading",
  title: "Uploading",
  timeout: 0,
});

toast.update(id, {
  type: "success",
  title: "Upload complete",
  timeout: 5000,
});
```

Use `promise()` for asynchronous workflows:

```tsx
try {
  await toast.promise(uploadFile(file), {
    loading: { title: "Uploading" },
    success: { title: "Upload complete" },
    error: { title: "Upload failed", priority: "high" },
  });
} catch (error) {
  // promise() preserves rejection semantics of the original Promise.
}
```

Promise loading notifications do not auto-close by default. Success and failure default to `success` and `danger`, restoring the Provider's default timeout. `success` and `error` may be functions receiving the result or exception. If those functions throw, the notification closes and the exception propagates; a success-handler exception does not invoke `error`. For blocking failures, also retain recoverable error state on the page instead of relying only on transient notifications.

## Queue and Motion

A manager array is the single state source. After additions/removals, `AnimatePresence` and one set of Motion targets handle unmounting and reordering, without a second CSS transition or component-library animation lifecycle.

- New notifications enter from their spatial origin: right-side placement uses the x axis; centered placement uses y.
- Compact stacking defaults to `10px` offset, `0.06` scale reduction, and `0.2` opacity reduction per layer; response spacing uses theme `stagger.tight`.
- Entry, exit, and reordering use the `useFeel('ui')` spring; opacity uses theme fade settings. Drag return uses the `snap` spring.
- Four layers remain visible by default; only the front notification is interactive and accessible. DOM retains visible layers and two transparent buffers, keeping long queues from animating every notification each frame. Closing the front allows following items to spring continuously into place.
- Tune stacking with `stackOffsetY`, `stackScale`, `stackOpacity`, `staggerInterval`, and `toastSpring`.

Motion drag follows the pointer 1:1. Right-side notifications dismiss rightward, top-center upward, and bottom-center downward. Release considers both displacement and velocity; beyond threshold it passes velocity into the exit spring, otherwise springs back from the current position.

Auto-close timers pause during hover, keyboard focus, page blur, or backgrounding; `paused` also pauses manually. Timers resume from remaining time only after all pause causes clear; updates reset the full timeout. `F6` switches between current focus and notifications; `Escape` closes a focused notification.

With system reduced motion using `calm`, automatic entry, exit, and reordering omit translation, scale, and springs, retaining brief opacity feedback; `off` updates immediately. Direct user dragging still tracks the pointer 1:1.

## Priority and accessibility

Default `priority="low"` uses `role="status"`. Reserve `priority="high"`, which uses `role="alert"`, for urgent messages needing immediate attention.

```tsx
toast.add({
  priority: "high",
  type: "danger",
  title: "Connection interrupted",
  description: "Unsaved changes may be lost.",
});
```

Viewport provides a named notification region; Root associates title and description. Notifications behind the front are `inert` and `aria-hidden`. After exit, focus attempts to move to the next notification or the element focused before entering Viewport. Do not add conflicting `aria-live`, `aria-modal`, or another drag handler.

## Slots and primitives

`ToastProvider` exposes:

- `portal`: configure `container` or `disabled`, or pass `false` directly.
- `viewport`: add native div props, classes, and ARIA attributes to the host layer.
- `root`: add classes, events, and ARIA to each Motion Root; the wrapper reserves `animate`, `initial`, `exit`, `style`, and drag lifecycle.
- `slots.content`, `slots.text`, `slots.title`, `slots.description`: configure content nodes, change elements with `render`, or remove with `false`.
- `slots.icon`, `slots.action`, `slots.close`: configure Motion node props or remove with `false`.

Notification `title` and `description` belong in `ToastOptions`; Provider `children` remains the application subtree. See [Content Slots](/docs/design/content-slots).

```tsx
<ToastProvider
  placement="top-center"
  viewport={{ "aria-label": "System notifications" }}
  root={{ className: "max-w-sm" }}
  slots={{ close: { label: "Close" } }}
>
  <App />
</ToastProvider>
```

The same entry exports `ToastPortal`, `ToastViewport`, `ToastRoot`, `ToastContent`, `ToastIcon`, `ToastText`, `ToastTitle`, `ToastDescription`, `ToastAction`, `ToastClose`, and `ToastList`. Primitives depending on notification/manager context must be inside `ToastProvider`.

## Props

### ToastProvider

| Prop | Type | Description |
| ---------------------------- | ------------------------------------------------------------------ | ------------------------------------------------ |
| `children` | `ReactNode` | Application components using the controller |
| `timeout` | `number` | Defaults to `5000`; `0` disables auto-close |
| `paused` | `boolean` | Manually pauses auto-close; defaults to `false` |
| `limit` | `number` | Visible stack layers; defaults to `4` |
| `toastManager` | `ToastManager` | Optional independent external manager |
| `placement` | `"top-right" \| "top-center" \| "bottom-right" \| "bottom-center"` | Position; defaults to `"bottom-right"` |
| `swipeDirection` | Direction or direction array | Custom swipe-dismissal directions; an empty array disables dragging |
| `stackOffsetY` | `number` | Per-layer y offset; defaults to `10` |
| `stackScale` | `number` | Per-layer scale difference; defaults to `0.06` |
| `stackOpacity` | `number` | Per-layer opacity difference; defaults to `0.2` |
| `staggerInterval` | `number` | Queue response spacing in seconds; defaults to theme `stagger.tight` |
| `toastSpring` | `{ stiffness; damping; mass? }` | Overrides entry/exit/reorder spring; stiffness and damping also affect drag return |
| `portal`, `viewport`, `root` | Primitive config | Configures structural layers |
| `slots` | Slot config | Configures content or removes optional nodes |

### useToast

`useToast()` defaults to `strict: true`, requiring `ToastProvider`. Components supporting standalone usage can use `useToast({ strict: false })`: it returns the same reactive controller with a Provider, otherwise `null`, allowing the caller to choose fallback presentation.

```tsx
const toast = useToast({ strict: false });

function showHelp() {
  if (toast) toast.add({ description: "Used for workspace notifications." });
  else setHelpOpen(true);
}
```

| Method | Description |
| ------------------------- | ----------------------------------- |
| `add(options)` | Creates or updates by fixed ID and returns the ID |
| `update(id, options)` | Updates in place and refreshes the timer |
| `close(id?, reason?)` | Closes one or all notifications |
| `promise(value, options)` | Manages loading, success, and error states |
| `toasts` | Reactive notification array managed by the current Provider |

Use `createToastManager()` outside React components. Pass it to `ToastProvider.toastManager` to share one queue between external calls and the UI.
