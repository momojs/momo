`@momots/design` is momo's component layer for **React 19.2+**. It combines **Base UI** headless interactions, **Motion** transitions, and **Tailwind CSS** styling to create reusable, debuggable, tree-shakeable components.

## Installation

The React API compatibility baseline is **19.2+**; hooks directly use native `useEffectEvent`. Published
`react` and `react-dom` peer ranges are both `^19.2.7` (`>=19.2.7 <20.0.0`). Install matching React and React DOM versions.

```bash
bun add @momots/design@alpha @momots/core@beta @momots/host@beta
bun add @base-ui/react @hugeicons/react @hugeicons/core-free-icons
bun add react@^19.2.7 react-dom@^19.2.7
bun add cn cva date-fns motion remeda tailwindcss type-fest
```

Applications provide `@momots/core`, `@momots/host`, `@base-ui/react`, `motion`, `react`, `react-dom`, `remeda`, `type-fest`, `cn`, `cva`, `date-fns`, and Hugeicons as peer dependencies, avoiding duplicate React, utilities, icons, or animation runtimes in the library bundle.

`@ncdai/react-wheel-picker`, `morphicons`, and `motion-plus` install as ordinary dependencies alongside
`@momots/design`. Other runtime dependencies remain peers so applications can coordinate versions.

## Debugging first

This site's design docs load components directly from `packages/design/src`. While developing, source edits appear in the documentation through Vite hot updates.

## Packaging conventions

Publish the library with multiple ESM entries, keeping React, Base UI, Motion, and momo foundation packages external:

```ts
await Bun.build({
  entrypoints,
  format: "esm",
  packages: "external",
  target: "browser",
});
```

Preserve `sideEffects` and subpath `exports` so consuming bundlers can safely remove unused components:

```json
{
  "sideEffects": ["**/*.css"],
  "exports": {
    "./components/toggle-group": {
      "types": "./dist/components/toggle-group.d.ts",
      "import": "./dist/components/toggle-group.js"
    },
    "./tailwind.css": "./src/styles/tailwind.css",
    "./picker.css": "./src/styles/picker.css",
    "./themes/semantic.css": "./src/themes/semantic.css",
    "./themes/neutral.css": "./src/themes/neutral.css",
    "./themes/anthropic.css": "./src/themes/anthropic.css"
  },
  "files": ["dist", "src/styles", "src/themes"]
}
```

Component JS entries do not import theme files; themes are exposed only through `./themes/*` for manual application imports.

## Tailwind CSS

This site's `app.css` extends Tailwind scanning to design sources, generating styles immediately while debugging `className` in `packages/design/src`. External applications should import `@momots/design/tailwind.css`, which registers package `dist` through `@source` so Tailwind v4 generates component utilities.

## Themes

Component entries do not import themes automatically. Import them explicitly in application CSS:

```css
@import "tailwindcss";
@import "@momots/design/tailwind.css";
@import "@momots/design/themes/neutral.css";
@import "@momots/design/themes/anthropic.css";
```

When using `PickerCore`, `PickerDate`, or `PickerTime`, explicitly import wheel picker styles:

```css
@import "@momots/design/picker.css";
```

Then switch theme classes on the root or a local container:

```tsx
<div className="theme-anthropic">
  <Button>Action</Button>
</div>

<div className="theme-neutral dark">
  <Button>Action</Button>
</div>
```

Components consume only `momo`-prefixed semantic tokens, such as `bg-momo-bg-canvas`, `text-momo-fg-default`, `border-momo-border-default`, and `ring-momo-ring-focus`. New themes reuse these names and switch by replacing the root class. See [Themes and tokens](/docs/design/theme) for token layers and meanings.
