`@momots/design` 是 momo 面向 **React 19.2+** 的组件层。它把 **Base UI** 的无样式交互能力、**motion** 的过渡动画、以及 **Tailwind CSS** 的样式表达组合起来，用来沉淀项目中可复用、可调试、可 tree-shaking 的组件。

## 安装

React API 兼容基线为 **19.2+**，Hooks 直接使用原生 `useEffectEvent`。当前发布的
`react` 与 `react-dom` peer 范围均为 `^19.2.7`（`>=19.2.7 <20.0.0`），请安装版本一致的 React 与 React DOM。

```bash
bun add @momots/design@alpha @momots/core@beta @momots/host@beta
bun add @base-ui/react @hugeicons/react @hugeicons/core-free-icons
bun add react@^19.2.7 react-dom@^19.2.7
bun add cn cva date-fns motion remeda tailwindcss type-fest
```

`@momots/core`、`@momots/host`、`@base-ui/react`、`motion`、`react`、`react-dom`、`remeda`、`type-fest`、`cn`、`cva`、`date-fns` 与 Hugeicons 应作为 peer dependencies 由应用侧提供，避免组件库把 React、基础工具、图标或动画运行时重复打进产物。

`@ncdai/react-wheel-picker`、`morphicons` 与 `motion-plus` 会作为普通 dependencies 随
`@momots/design` 安装；其余运行时依赖保持为 peer dependencies，由应用统一版本。

## 调试优先

当前网站的 design 文档会直接加载 `packages/design/src` 中的源码组件。这样在开发组件时，改动源码即可通过 Vite 热更新反映到文档页面。

## 打包约定

组件库应以 ESM 多入口发布，并把 React、Base UI、motion 和 momo 的基础包保持 external：

```ts
await Bun.build({
  entrypoints,
  format: "esm",
  packages: "external",
  target: "browser",
});
```

同时保留 `sideEffects` 标记与子路径 `exports`，让消费端 bundler 可以安全地移除未使用组件：

```json
{
  "sideEffects": ["**/*.css"],
  "exports": {
    "./components/toggle-group": {
      "types": "./dist/components/toggle-group.d.ts",
      "import": "./dist/components/toggle-group.js"
    },
    "./tailwind.css": "./src/styles/tailwind.css",
    "./picker.css": "./src/styles/picker.css",
    "./themes/semantic.css": "./src/themes/semantic.css",
    "./themes/neutral.css": "./src/themes/neutral.css",
    "./themes/anthropic.css": "./src/themes/anthropic.css"
  },
  "files": ["dist", "src/styles", "src/themes"]
}
```

组件 JS 入口不 import 主题文件；主题只通过 `./themes/*` 暴露给应用侧手动引入。

## Tailwind CSS

本网站已经在 `app.css` 中把 Tailwind 扫描范围扩展到 design 源码目录，因此调试 `packages/design/src` 里的 className 时会即时生成样式。外部应用应导入 `@momots/design/tailwind.css`；该入口通过 `@source` 注册包内 `dist`，让 Tailwind v4 生成组件使用的 utility。

## 主题

主题文件不会被组件入口自动引入，应用侧需要在自己的 CSS 中手动 import：

```css
@import "tailwindcss";
@import "@momots/design/tailwind.css";
@import "@momots/design/themes/neutral.css";
@import "@momots/design/themes/anthropic.css";
```

使用 `PickerCore`、`PickerDate` 或 `PickerTime` 时，再显式导入滚轮组件样式：

```css
@import "@momots/design/picker.css";
```

然后在根元素或局部容器上切换主题类：

```tsx
<div className="theme-anthropic">
  <Button>Action</Button>
</div>

<div className="theme-neutral dark">
  <Button>Action</Button>
</div>
```

组件只消费带 `momo` 前缀的 semantic token，例如 `bg-momo-bg-canvas`、`text-momo-fg-default`、`border-momo-border-default` 与 `ring-momo-ring-focus`。新增主题只需复用同一套命名即可通过替换根元素 class 完成切换。token 的分层结构与每个 token 的具体语义见 [主题与 Token](/docs/design/theme)。
