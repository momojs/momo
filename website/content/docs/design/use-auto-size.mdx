`useAutoSize` continuously measures the current content's layout dimensions and provides stable `width` and `height` animation targets. Animate width, height, or both; Motion moves from the currently displayed size to the new target. It suits compact content-sized panels, floating surfaces, and height-only transitions for Tabs, dynamic details, and calendars.

## Why use it

Suppose a details panel initially has a two-line summary, then gains images and descriptions after an API response. The user narrows the window, causing more text wrapping. Measuring height only when opening can clip later content, while hardcoding a height for each content variation can leave large gaps.

Panel switching adds another issue: the old panel has unmounted while the new one has not yet mounted. Having no measurement does not mean the content has zero height. Resetting height to zero would make the container collapse before expanding again.

| Problem | Hook behavior |
| --- | --- |
| Switching a brief status to details requires both width and height changes | One measurement updates both targets for `animate={{ width, height }}` |
| Loaded content becomes taller than the original height | Continuously observe the active target's natural size and update the numeric height |
| A width change causes wrapping without changing dependencies | `ResizeObserver` detects the size change without a manually maintained content dependency list |
| Panels have different heights, causing jumps when switching | Register and activate panels by key, passing the target height to one Motion container |
| The new panel has not mounted and the container must not collapse | Enter `pending` and preserve the previous width and height targets |
| Empty content really has zero height, or the application needs to collapse | Valid zero height returns `0`; explicitly collapse with `clear()` |
| The user interacts again before the animation finishes | Update the same container's target so Motion continues from the currently displayed height |

For a one-time expand/collapse transition with fixed content, use Motion's `height: 0` and `height: "auto"` directly. Use this hook when you need to respond continuously to size changes or manage multiple measurement targets. It handles measurement and target selection; callers decide the animation parameters.

## Observe measurement state and animation targets

The default scenario shows a compact panel changing both width and height. Other scenarios demonstrate height-only animation. Switching scenarios or clicking “Restart” recreates the demo; reduced motion causes immediate size updates.

Start each operation below from its scenario's initial state. Exact pixels depend on fonts and available width; focus on how values change:

| Scenario and operation | Measurement and target changes | UI behavior |
| --- | --- | --- |
| Compact panel → Show sync details → Show brief status | Width and height update together; `ready` | The outer container follows intrinsic content dimensions and can reverse mid-transition |
| Compact panel → `clear()` → Reactivate | Both targets first become zero, then return to valid measurements | The inner content remains mounted and can expand again |
| Content changes → Add extra content → Remove extra content | `ready`; height increases, then decreases | The container expands and contracts with its content |
| Content changes → Narrow content | More wrapping increases measured height | No additional `activate` call is needed |
| Panel switching → Show details → Immediately show summary | The target changes from the details height to the summary height | The same container reverses during animation |
| Panel switching → Reject switch requests → Show details | The active target remains `summary` | Both content and height stay on the summary |
| Waiting for mount → Wait for new content → Mount new content | `ready → pending → ready` | Keep the old height while waiting, then move to the new height after mounting |
| Waiting for mount → Real zero height | `ready`; valid measured height and animation target are both `0` | Collapse to zero height while the outer border remains |
| Waiting for mount → `clear()` → Reactivate | `idle → ready`; target is first `0`, then restored | Registered content can still be reactivated |
| Multiple-month layout → Stack vertically | Measure the entire region's new height | Months, spacing, heading, and footer all contribute |

## Scenario 1: resizing a compact panel on both axes

The following status card uses the content's intrinsic width. The inner `w-max` corresponds to `width: max-content`, so its width does not follow each animated frame of the container and can provide a stable endpoint. Put decoration outside and content padding inside the measured region.

```tsx
import { useLayoutEffect } from "react";
import { useAutoSize } from "@momots/design/hooks";
import { motion, useReducedMotion } from "motion/react";

function CompactStatus({ expanded }: { expanded: boolean }) {
  const { register, activate, width, height } = useAutoSize();
  const reduced = useReducedMotion();

  useLayoutEffect(() => {
    activate("content");
  }, [activate]);

  return (
    <div className="inline-block align-top rounded-lg border">
      <motion.div
        initial={false}
        animate={{ width, height }}
        transition={reduced ? { type: "tween", duration: 0 } : undefined}
        className="overflow-hidden"
      >
        <div ref={register("content")} className="grid w-max gap-2 p-4">
          <p>{expanded ? "All content saved" : "Saved"}</p>
          {expanded && (
            <>
              <p>Images, descriptions, and tags are synchronized.</p>
              <p>You can keep editing.</p>
            </>
          )}
        </div>
      </motion.div>
    </div>
  );
}
```

For width-only animation, use `animate={{ width }}`; height continues to follow natural layout. For height-only animation, use `animate={{ height }}`. The hook does not set element styles or require using both axes.

### Width needs an independent layout basis

A normal block's `width: auto` usually follows its parent. Writing that measured width back to the parent can freeze fluid width at a pixel value or let intermediate animation widths repeatedly affect measurements. Merely separating the outer and inner elements does not remove this dependency.

Width animation works well with short content's intrinsic width, an explicit target width, or an independently measured region. The `max-content` example suits compact status cards. For long text, callers should determine the target width from available space, then measure the wrapped height. Do not derive available width from the animated container itself; percentage constraints such as `max-width: 100%` can also reintroduce the dependency.

Width and height animation affects layout. Tabs and calendars that stretch with their parent should continue to use only the height target, as the following scenarios demonstrate.

## Scenario 2: adding or removing details

Import the hook from `@momots/design/hooks`. The animation container and measurement target must be separate elements:

```tsx
import type { ReactNode } from "react";
import { useLayoutEffect } from "react";
import { useAutoSize } from "@momots/design/hooks";
import { motion, useReducedMotion } from "motion/react";

function HeightRegion({ children }: { children: ReactNode }) {
  const { register, activate, height } = useAutoSize();
  const reduced = useReducedMotion();

  useLayoutEffect(() => {
    activate("content");
  }, [activate]);

  return (
    <div className="rounded-lg border p-3">
      <motion.div
        initial={false}
        animate={{ height }}
        transition={reduced ? { type: "tween", duration: 0 } : undefined}
        className="overflow-hidden"
      >
        <div ref={register("content")} className="flow-root">
          {children}
        </div>
      </motion.div>
    </div>
  );
}
```

The three layers have distinct roles: the outermost handles borders, background, and extra spacing; the middle handles only height animation and clipping; the inner keeps natural layout and supplies measurements. Before the first measurement, including during SSR, `height` is `"auto"` so content is not initially compressed to zero height.

Later `HeightRegion` examples reuse the implementation above. As long as added content participates in the inner element's normal layout, height continues to track it:

```tsx
import { useState } from "react";

function ProductDetails() {
  const [expanded, setExpanded] = useState(false);

  return (
    <>
      <button onClick={() => setExpanded((previous) => !previous)}>
        {expanded ? "Collapse details" : "Expand details"}
      </button>
      <HeightRegion>
        <p>Product summary.</p>
        {expanded && (
          <div className="grid gap-3">
            <p>Additional usage instructions.</p>
            <p>More specifications and shipping details.</p>
          </div>
        )}
      </HeightRegion>
    </>
  );
}
```

When expanded, the inner content first grows naturally, the hook publishes the new height, and Motion makes the outer container follow. Collapsing follows the same process. Content inserted after an API response or images expanding the layout after loading use the same update path, with no additional measurement call.

If image dimensions or `aspect-ratio` already reserve space and loading does not change layout size, the hook does not publish another size update.

## Scenario 3: narrowing the container and rewrapping text

An unchanged content string does not imply unchanged height. An expanded sidebar, narrower window, or different font can add lines. The hook measures actual browser layout, so these factors do not need individual entries in its dependency array:

```tsx
function ResponsiveDetails() {
  const [narrow, setNarrow] = useState(false);

  return (
    <>
      <button onClick={() => setNarrow((previous) => !previous)}>
        Toggle available width
      </button>
      <div style={{ width: narrow ? 220 : 360, maxWidth: "100%" }}>
        <HeightRegion>
          <p>The same description wraps naturally at different widths, and the height target follows the actual layout.</p>
        </HeightRegion>
      </div>
    </>
  );
}
```

If only width changes, `state.rect.width` and the `width` animation target update while `height` stays unchanged. This example passes only `animate={{ height }}`, so the actual width remains controlled by external layout. Identical width and height values do not produce duplicate measurements.

## Scenario 4: switching between summary and details mid-transition

Register logical targets with different keys and select the current target with `activate`. Registration only says that a node exists; it does not automatically select it.

In the following component, the parent decides which panel is shown. Buttons only request a switch, and an effect activates measurement based on the committed `value`:

```tsx
type Panel = "summary" | "details";

function PanelRegion({
  value,
  onChange,
}: {
  value: Panel;
  onChange: (next: Panel) => void;
}) {
  const { register, activate, height } = useAutoSize();
  const reduced = useReducedMotion();

  useLayoutEffect(() => {
    activate(value);
  }, [value, activate]);

  return (
    <>
      <button onClick={() => onChange("summary")}>Show summary</button>
      <button onClick={() => onChange("details")}>Show details</button>
      <motion.div
        initial={false}
        animate={{ height }}
        transition={reduced ? { type: "tween", duration: 0 } : undefined}
        className="overflow-hidden"
      >
        <div key={value} ref={register(value)} className="flow-root">
          {value === "summary" ? (
            <p>A summary.</p>
          ) : (
            <div className="grid gap-3">
              <p>First details paragraph.</p>
              <p>Second details paragraph.</p>
              <p>Third details paragraph.</p>
            </div>
          )}
        </div>
      </motion.div>
    </>
  );
}
```

When switching from a short panel to a tall one and back before animation completes, the hook supplies only a new target height. Motion continues from the current displayed height on the same container. `height` is the endpoint, not the height displayed in each animation frame.

Here, `key={value}` belongs only on the content node. Putting it on `motion.div` would recreate the animated container on every switch and prevent continuation of the previous animation.

### When the parent rejects a switch

```tsx
<PanelRegion
  value={panel}
  onChange={(requested) => {
    if (locked) return;
    setPanel(requested);
  }}
/>
```

If the parent rejects `details`, `value` remains `summary` and measurement should continue following the summary. Do not call `activate(requested)` early in the `onChange` request handler, or the UI will show old content while waiting for or measuring the new panel. This follows the same convention as [controlled requests in useControllableValue](/docs/design/use-controllable-value).

The existing [Tabs](/docs/design/tabs) component already uses this height strategy, so using Tabs does not require another wrapper with the same measurement logic.

## Scenario 5: the new panel has not mounted

For asynchronous loading, conditional rendering, or multi-step flows, you can declare the next target before it mounts. The following `ready` value comes from data loading state:

```tsx
function DeferredPanel({
  selected,
  ready,
}: {
  selected: "summary" | "details";
  ready: boolean;
}) {
  const { register, activate, height } = useAutoSize();
  const reduced = useReducedMotion();

  useLayoutEffect(() => {
    activate(selected);
  }, [selected, activate]);

  return (
    <motion.div
      initial={false}
      animate={{ height }}
      transition={reduced ? { type: "tween", duration: 0 } : undefined}
      className="overflow-hidden"
    >
      {selected === "summary" && (
        <div ref={register("summary")} className="flow-root">
          <p>The loaded summary.</p>
        </div>
      )}
      {selected === "details" && ready && (
        <div ref={register("details")} className="flow-root">
          <p>Asynchronously loaded details.</p>
          <p>More content.</p>
        </div>
      )}
    </motion.div>
  );
}
```

Suppose the measured summary height is `80px` and the mounted details height is `240px`:

| Moment | Current target | `state.status` | `state.rect` | `height` |
| --- | --- | --- | --- | --- |
| Summary displayed | `summary` | `ready` | Summary dimensions | `80` |
| Details selected, but `ready` is `false` | `details` | `pending` | `null` | Keep `80` |
| `ready` becomes `true`; details mount and are measured | `details` | `ready` | Details dimensions | `240` |
| Details temporarily unmount afterward | `details` | `pending` | `null` | Keep `240` |

The preserved value is the previous **target height**, not a paused animation frame. An unfinished animation may continue toward that target. Without any earlier measurement, the height during `pending` remains `"auto"`.

The hook preserves space, not unmounted content, and does not display a loading state automatically. Callers arrange skeletons, retained old content, or transition placeholders. Registering a skeleton as the current target measures the skeleton's own height.

When switching targets, observation of the old target stops, and late notifications cannot overwrite the new target. Remounting the same key attaches the new node; cleanup from the old mount cannot remove its replacement.

## Scenario 6: real zero height and explicit collapse

Waiting for new content, content being genuinely empty, and having no selected item are three different states:

| Intent | How to express it | State and result |
| --- | --- | --- |
| New content has not mounted | `activate("details")`, then register the target later | `pending`; keep the previous target height |
| Current content really has zero height | Activate a mounted node without content or spacing | `ready`; both `state.rect.height` and `height` are `0` |
| The application clears selection and the container should collapse | `clear()` | `idle`; `state.rect` is `null` and `height` is `0` |

For example, if a controlled step selection permits no selected item, explicitly distinguish selection from clearing:

```tsx
// selected has type string | undefined.
useLayoutEffect(() => {
  if (selected === undefined) clear();
  else activate(selected);
}, [selected, activate, clear]);
```

`clear()` cancels activation intent without deleting registrations that remain mounted. Calling `activate` later measures them again; an unmounted target reenters `pending`. Waiting for a target immediately after clearing preserves `0` for both dimensions. Callers using only `height` still collapse only vertically.

Keys support `string`, `number`, and `null`; `0`, `"0"`, and `null` identify three different targets. `activate(null)` selects the target keyed by `null` and is not a replacement for `clear()`.

A height of `0` describes only the animated container. It does not remove outer borders or padding, unmount content, or manage keyboard focus. When collapsing an area with interactive controls, callers should also manage content visibility and accessibility.

## Scenario 7: measuring the full layout across multiple months

Calendars and card groups often support both horizontal and vertical layouts. Summing child heights works only for some vertical structures. A horizontal layout requires the full row height, including headings, spacing, and footer content.

The most direct approach is to measure the entire region as one natural-layout target. The following `months` prop can contain month nodes generated by an existing calendar:

```tsx
function MonthLayout({
  months,
  stacked,
}: {
  months: { id: string; content: ReactNode }[];
  stacked: boolean;
}) {
  return (
    <HeightRegion>
      <div className="grid gap-4">
        <header>Select a date</header>
        <div
          className="grid gap-4"
          style={{
            gridTemplateColumns: stacked
              ? "1fr"
              : `repeat(${Math.max(months.length, 1)}, minmax(0, 1fr))`,
          }}
        >
          {months.map((month) => (
            <div key={month.id}>{month.content}</div>
          ))}
        </div>
        <footer>Select dates across different months.</footer>
      </div>
    </HeightRegion>
  );
}
```

Horizontally, both months determine the row height together; vertically, months and gaps each contribute height. After changes to layout, month count, or weeks per month, the hook reads the entire wrapper's actual dimensions. With an existing calendar such as DayPicker, measure the natural-layout region around the whole calendar rather than summing months or measuring just one.

## Scenario 8: following content with reduced motion

Separating measurement from animation lets you keep the same sizing logic while changing only the transition strategy:

```tsx
const reduced = useReducedMotion();

<motion.div
  initial={false}
  animate={{ height }}
  transition={
    reduced
      ? { type: "tween", duration: 0 }
      : { type: "spring", bounce: 0, duration: 0.45 }
  }
>
  {/* Independent node measuring natural content size */}
</motion.div>
```

With reduced motion enabled, content changes, target switching, and waiting for mounts follow the same rules; only height updates become immediate. The demo's “Update size immediately” option uses this path too.

## Current measurements and animation targets

`state` describes whether the current target has a valid measurement, while `width` and `height` describe the animation destination. While waiting for a new target to mount, the current measurement is invalid but the animation targets are retained:

| Scenario | `state.status` | `state.rect` | `width` / `height` |
| --- | --- | --- | --- |
| Initial render, before activation | `idle` | `null` | `"auto"` |
| Activated, but not yet mounted or temporarily unmounted | `pending` | `null` | Each retains its previous target dimension, or `"auto"` if none exists |
| Activated, but using an unsupported layout | `pending` | `null` | Each retains its previous target dimension; invalid measurements are not treated as `0` |
| Current target dimensions obtained | `ready` | `{ width, height }` | Current measured dimensions, including genuine `0` values |
| Explicit `clear()` call | `idle` | `null` | `0` |

`pending` and `ready` also include the activated `value`. Current dimensions are available only through `state.rect`: it is `null` in `idle` and `pending`, meaning no valid measurement, and `{ width, height }` in `ready`, where zero width or height is still valid. Check `state.status === "ready"` before reading dimensions; do not substitute zero for measurements that are not yet available.

When a valid measurement is accepted, the current dimensions and targets retained for future `pending` states are determined in the same state update. Width and height update atomically as one snapshot. Switching targets or invalidating a measurement clears only the current measurement; `clear()` also sets both targets to `0`. Stale notifications cannot update current dimensions or overwrite either retained dimension.

The retained value is the latest valid **target size**, not the size currently displayed on screen. Motion still manages live displayed values and animation continuity.

Do not use `state.rect?.height || "auto"`: real zero height is not an absent measurement, and switching targets should not restore natural height. Use the corresponding `width` / `height` animation targets directly for each axis. When a target changes mid-transition, Motion continues from the current displayed value.

## API

```ts
function useAutoSize<T extends HTMLElement = HTMLDivElement>(): AutoSizeApi<T>;
```

The hook takes no content dependencies, axis options, or animation parameters. It always measures both dimensions; callers choose `animate={{ width }}`, `animate={{ height }}`, or `animate={{ width, height }}`. It returns:

| Return value | Type | Purpose |
| --- | --- | --- |
| `register` | `(value: ControlValue) => React.RefCallback<T>` | Register an observable natural-layout box; returns a stable callback ref for the same key |
| `activate` | `(value: ControlValue) => void` | Select a measurement target, including before it mounts |
| `clear` | `() => void` | Cancel activation and set both dimension targets to `0` |
| `width` | `number \| "auto"` | Width animation target: initially `"auto"`, retained while waiting, and `0` after clearing |
| `height` | `number \| "auto"` | Height animation target; follows the same rules as `width` |
| `state` | `AutoSizeState` | Distinguishes `idle`, `pending`, and `ready` with a valid measurement |

Related exported types include `AutoSizeApi<T>` and `AutoSizeState`. `ControlValue` is `string | number | null`.

### Registration and activation conventions

- `register(value)` returns a stable React callback ref that registers DOM nodes without selecting them.
- `activate(value)` declares which target to measure. Activation may precede mounting; while waiting, the old target stops being observed and its notifications cannot overwrite the new target.
- `clear()` cancels activation intent and sets animation targets to zero without discarding mounted registrations. They can be reactivated directly afterward.
- Keys support `string`, `number`, and `null`; `0`, `"0"`, and `null` are different targets. Do not use `activate(null)` to clear selection.
- A new registration replaces an old registration with the same key; cleanup from the old mount cannot delete the replacement. Coexisting logical targets should use different keys.

Controlled components should activate targets from the **committed value**, not early inside a change-request callback: the parent may reject that request. Call `clear()` when the application has no selected item; retain `pending` only while waiting for a target to mount.

## Measurement boundaries and multi-month layouts

Dimensions use the layout **border box**, unaffected by CSS transform scaling. They include the target's own padding and border but exclude its margin. `ResizeObserver` responds to size changes caused by content, padding, border, and width; unchanged width and height do not publish a new measurement.

### Targets must be observable layout boxes

A layout box is an element's own region participating in layout with measurable width and height. Use layouts whose dimensions can be observed normally, such as `block`, `inline-block`, `flow-root`, `flex`, or `grid`; `inline-flex` and `inline-grid` are also supported.

**Non-replaced inline elements**, such as an ordinary `span`, do not satisfy this constraint: their visible dimensions are not valid ResizeObserver measurements. `display: contents` is also unsupported because the element creates no layout box of its own. Attach the ref to a separate wrapper instead of asking the hook to change caller-owned CSS:

```tsx
<div ref={register("content")} className="flow-root">
  <span>Content to measure</span>
</div>
```

**Replaced elements** such as `img` and `video`, whose image or media content establishes independent dimensions, are not subject to the ordinary inline restriction. Their observable inline boxes can be registered directly. The constraint concerns actual layout, not the `span` tag itself: a `span` with `inline-block` or `block` is also a valid target.

The hook checks target layout during the initial measurement and later ResizeObserver notifications. Unsupported layout invalidates the current measurement and keeps or moves `state` to `pending`; `width` and `height` retain their previous targets, or `"auto"` if no earlier values exist. Development builds warn at most once per observation cycle. Production builds also reject invalid measurements but omit the warning. Observation remains active, and fixing the layout restores measurement on the next size notification without registering or activating again.

Callers should keep targets in a supported layout while measuring. **Real zero height remains valid**: empty content or temporarily applying `display: none` to a target or ancestor can produce `ready` with zero dimensions. Do not ignore every `0` as a workaround for unsupported layouts.

### Multi-month layouts and other constraints

Tabs measures the selected panel; Calendar measures the natural-layout region around the entire DayPicker. Multi-month calendars neither sum months individually nor substitute a single month for the whole layout. Vertically stacked months, spacing, horizontal row height, navigation, footer, and root padding all follow actual browser layout.

Follow these layout constraints:

- Do not attach the ref to the animated container whose dimensions are being set. On every animated axis, the measurement target must be independent of that container; for example, it must not follow it through `height: 100%` or `width: 100%`, which would create a measurement feedback loop.
- Put no padding or border on the animated container itself. Keep decoration outside and content spacing inside the measured region.
- Content that should be measured must participate in the target's natural layout. Absolutely positioned content, shadows, and visual overflow after transforms are not measured; a `flow-root` wrapper can contain child margins.
- When multiple panels coexist during exit and enter, callers organize their in-flow layout. The hook does not take over Presence or application selection state.
