`Select` uses Base UI Select for keyboard navigation, form submission, and accessibility semantics. By default, it renders Base UI's recommended `Trigger`, `Value`, `Icon`, `Portal`, `Positioner`, `Popup`, `List`, `ScrollArrow`, `Item`, `ItemIndicator`, and `ItemText` structure, adapting to the current theme through momo semantic tokens.

## Usage

```tsx
import { Select } from "@momots/design/components/select";

<Select
  value={fruit}
  onChange={setFruit}
  placeholder="Select a fruit..."
  options={[
    { value: "apple", label: "Apple" },
    { value: "banana", label: "Banana" },
    { value: "cherry", label: "Cherry" },
  ]}
/>;
```

## Controlled opening

```tsx
<Select
  open={open}
  onOpenChange={setOpen}
  value={fruit}
  onValueChange={(next) => {
    if (next) setFruit(next);
  }}
  options={options}
/>
```

`onChange` is momo's simplified callback, triggered only when a non-null option value changes. Use `onValueChange` for complete Base UI event information or to handle `null` values.
`open` is handled by momo's `useControllableValue`; Base UI manages selection through `value` / `defaultValue`.

## Option layout

Options follow the same column order as Menu: `[icon or spacer] [title] [optional supporting information] [indicator]`. `options[].icon` appears at the logical start; `options[].extra` sits between the title and indicator. The icon and indicator columns retain fixed widths, so missing icons, selection changes, and `itemIndicator={false}` do not shift the title's start position. A trailing checkmark indicates selection without changing font weight.

```tsx
<Select
  options={[
    { value: 'personal', label: 'Personal workspace', extra: 'Free' },
    { value: 'team', label: 'Team workspace', icon: <TeamIcon />, extra: 'Pro' },
  ]}
/>
```

Long titles and supporting text are truncated. Supporting information takes at most 40% of the available row width. `extra` remains accessible text, while decorative icons and checkmarks are hidden from assistive technology; Base UI's `aria-selected` expresses selection. The selected trigger text still comes from `label` and excludes `extra`.

For RTL, use Base UI's `DirectionProvider direction='rtl'` and set `dir='rtl'` on the application container. Portal content inherits the provider direction, mirroring icons and checkmarks along start / end.

## Customizing the popup

```tsx
<Select
  options={options}
  positioner={{
    alignItemWithTrigger: false,
    sideOffset: 8,
  }}
  popup={{ className: "min-w-64" }}
  list={{ className: "p-1" }}
/>
```

All slots are enabled by default. A props object configures the default Base UI primitive while preserving interactions, state parameters, and accessibility semantics. Passing `false` removes a slot; passing a ReactNode replaces it entirely. Prefer props objects for structural slots such as Trigger, Popup, and Item, and use the corresponding Base UI `render` prop to customize the underlying element.

Configurable slots include `trigger`, `valueSlot`, `icon`, `portal`, `positioner`, `popup`, `list`, `item`, `itemText`, `itemIndicator`, `scrollUpArrow`, and `scrollDownArrow`. `valueSlot` is deliberately named separately from `value`, which represents the selected value.

The default Popup preserves Motion enter/exit animations and respects reduced motion through `MotionConfig`. Only this default animation path lets `Select` call `unmount` after exit completes. Removing structural slots or overriding `popup.render` returns the unmount lifecycle to Base UI, or to the caller when `actionsRef` is explicitly supplied.

Additional Base UI behavior is forwarded through Select root props and slot configuration without separately exposing underlying primitives. `Select` does not rewrite the Portal mount point automatically. Put the momo theme class on `html` / `:root` so popups mounted to `body` inherit `--momo-*` tokens. Use `portal={{ container }}` for a custom mount point.

Option hover backgrounds use `useHighlightLayer`, `useHighlightTrigger`, and `Highlight`. `highlightItemOnHover` defaults to `true`, enabling both Base UI pointer highlight state and momo motion highlighting. Setting it to `false` still preserves keyboard navigation.

## Multiple selection

```tsx
const [fruits, setFruits] = useState<Fruit[]>(["apple", "cherry"]);

<Select<Fruit, true>
  multiple
  value={fruits}
  onChange={setFruits}
  options={options}
/>
```

With `multiple={true}`, values for `value`, `defaultValue`, and `onChange` are `T[]`. In single-selection mode, `value` / `defaultValue` may be `T` or `null`. `onChange` skips only `null` when clearing a single selection; clearing multiple selections to `[]` still invokes the callback.

## Props

| Prop | Type | Description |
| --- | --- | --- |
| `value` | `T \| null`; `T[]` for multiple selection | Current selected value |
| `defaultValue` | `T \| null`; `T[]` for multiple selection | Uncontrolled initial value |
| `options` | `ControlOption<T>[]` | Simplified option list supporting `label`, `icon`, `extra`, `disabled`, `className`, `style`, and `textValue` |
| `items` | Base UI Root `items` | Value-label mapping passed to the internal Root; defaults to `options` |
| `children` | `ReactNode` | Custom `List` content, useful for groups or custom items |
| `size` | `"sm" \| "md" \| "lg"` | Control size |
| `placeholder` | `ReactNode` | Placeholder content when nothing is selected |
| `disabled` | `boolean` | Whether interaction is disabled |
| `readOnly` | `boolean` | Whether the control is read-only |
| `multiple` | `boolean` | Whether multiple selection is allowed |
| `highlightItemOnHover` | `boolean` | Enable pointer hover highlighting; defaults to `true` |
| `open` / `defaultOpen` | `boolean` | Controlled / uncontrolled popup open state |
| `name` | `string` | Form field name |
| `form` | `string` | Associate an external form |
| `autoComplete` | `string` | Browser autofill hint |
| `required` | `boolean` | Whether a value is required |
| `modal` | `boolean` | Whether opening enters modal interaction mode |
| `actionsRef` | Base UI actions ref | Imperative actions forwarded to the internal Root; built-in Motion calls `unmount` through it after exit completes |
| `trigger` | slot config | Trigger configuration; enabled by default |
| `valueSlot` | slot config | Value configuration; enabled by default |
| `icon` | slot config | Icon configuration; enabled by default |
| `portal` | slot config | Portal configuration; enabled by default |
| `positioner` | slot config | Positioner configuration; enabled by default |
| `popup` | slot config | Popup configuration; enabled by default |
| `list` | slot config | List configuration; enabled by default |
| `item` | slot config | Shared configuration for each generated Item; enabled by default |
| `itemText` / `itemIndicator` | slot config | ItemText / ItemIndicator configuration; enabled by default |
| `scrollUpArrow` / `scrollDownArrow` | slot config | Scroll arrow configuration; enabled by default |
| `indicator` | `ReactNode` | Custom selection icon |
| `onChange` | `(value: T) => void`; `(value: T[]) => void` for multiple selection | Simplified selection change callback, excluding `null` |
| `onValueChange` | Base UI callback | Complete value change callback, including event details |
| `onOpenChange` | Base UI callback | Popup open state change callback |
