`@momots/design` uses three token layers:

| Layer | Prefix | Description |
| --- | --- | --- |
| Primitive | No `momo` prefix | Tailwind palette by default; theme-specific colors use Tailwind-like names in the theme CSS `@theme` |
| Semantic | `--momo-bg-*`, `--momo-fg-*`, `--momo-border-*`, `--momo-ring-*` | Consumed directly by components, with consistent names across themes |
| Base | `--momo-font-*`, `--momo-radius-*`, `--momo-space-*`, `--momo-shadow-*`, `--momo-text-*` | Fonts, radii, spacing, shadows, and type scales |

Two themes are currently included:

- `neutral`: the shadcn `neutral` theme, with values from the official `shadcn@4.13.0` registry.
- `anthropic`: a warm Claude / Anthropic theme based on `packages/design/DESIGN.md`.

Backgrounds use `--momo-bg-*`; text and icons use `--momo-fg-*`. Their Tailwind utilities are `bg-momo-bg-*` and `text-momo-fg-*`.

## Importing themes

```css
@import "tailwindcss";
@import "@momots/design/tailwind.css";
@import "@momots/design/themes/neutral.css";
@import "@momots/design/themes/anthropic.css";
```

Apply the momo theme class to the application root, `html` / `:root`, so overlays that portal to `body`, such as Select, Popover, and Menu, inherit the same `--momo-*` tokens:

```tsx
<html className="theme-neutral">
  <body>
    <App />
  </body>
</html>

<html className="theme-neutral dark">
  <body>
    <App />
  </body>
</html>
```

To switch themes, replace the theme class on `html`:

| Class | Description |
| --- | --- |
| `theme-neutral` | Neutral light |
| `theme-neutral dark` | Neutral dark |
| `theme-anthropic` | Anthropic light |
| `theme-anthropic dark` | Anthropic dark |

`dark` may also be set on an ancestor: both `.dark .theme-neutral` and `.dark .theme-anthropic` work.

Theme classes can be placed on local containers for isolated previews or embedded content without portals. Local tokens do not automatically reach overlays mounted to `body`; prefer setting the theme on `html`, or explicitly supply the component's portal container.

Components do not import theme files automatically; applications must explicitly import the required theme CSS.

## Base Tokens

### Typography

| Token | Utility | Meaning |
| --- | --- | --- |
| `--momo-font-display` | `font-momo-display` | Display headings |
| `--momo-font-body` | `font-momo-body` | UI and body text |
| `--momo-font-mono` | `font-momo-mono` | Code / monospace text |

Each type size has companion `-leading`, `-tracking`, and `-weight` variables, registered as Tailwind `text-momo-*` utilities through `@theme inline`:

| Utility | Meaning |
| --- | --- |
| `text-momo-display-xl` / `-lg` / `-md` / `-sm` | Display headings |
| `text-momo-title-lg` / `-md` / `-sm` | Card and list headings |
| `text-momo-body-md` / `-sm` | Body text and supporting descriptions |
| `text-momo-caption` / `text-momo-caption-uppercase` | Badges, captions, and category labels |
| `text-momo-code` | Code text |
| `text-momo-button` | Button text |
| `text-momo-nav-link` | Navigation links |

### Shape, Spacing, Shadow

| Token | Utility | Meaning |
| --- | --- | --- |
| `--momo-radius-xs` ~ `--momo-radius-full` | `rounded-momo-xs` ~ `rounded-momo-full` | Radius scale |
| `--momo-space-xxs` ~ `--momo-space-section` | `p-momo-md`, `gap-momo-lg`, etc. | Spacing scale |
| `--momo-shadow-sm` | `shadow-momo-sm` | Subtle elevation shadow |

## Adding a theme

1. Copy `packages/design/src/themes/neutral.css` or `anthropic.css`.
2. Use native or Tailwind-like names for private primitives, without a `--momo` prefix.
3. Provide the exact same semantic and base token names.
4. Import `./semantic.css` to enable utilities such as `bg-momo-bg-*`, `text-momo-fg-*`, and `border-momo-border-*`.
5. Do not add CSS animation tokens; component animations use Motion by default.


## Motion theme

`@momots/design/motion` includes the `@motion/ui-theme` source obtained through the official Motion+ MCP.
Components read animation parameters from the same theme, without installing another npm package of that name.
Color and motion themes are independent: switching `theme-neutral` / `theme-anthropic` does not change motion.

```tsx
// motion.theme.ts
import { defineTheme } from '@momots/design/motion';

export default defineTheme({
  transitions: {
    ui: { stiffness: 350, damping: 35 },
    gentle: { stiffness: 110, damping: 22 },
  },
  stagger: { tight: 0.04 },
  travel: { enter: 24, section: 48 },
  reducedMotion: 'calm',
});
```

```tsx
import { MotionUIThemeProvider } from '@momots/design/motion';
import motionTheme from './motion.theme';

export function App() {
  return (
    <MotionUIThemeProvider theme={motionTheme}>
      <YourApp />
    </MotionUIThemeProvider>
  );
}
```

`defineTheme` merges partial configuration into defaults, preserving omitted fields. The Provider receives a complete
resolved theme; nested Providers replace it without implicitly merging the parent theme. Without a Provider,
components use the same defaults. Components inside React portals inherit their React tree's motion theme.

| Token | Purpose |
| --- | --- |
| `transitions.snap` | Immediate feedback for presses, toggles, and indicators |
| `transitions.ui` | Regular controls, menus, Toast, and state changes |
| `transitions.gentle` | Larger surfaces, including Dialog and dimension changes |
| `transitions.lively` | Emphasized feedback, such as numbers |
| `transitions.ambient` | Looping animations such as loading; `duration` sets the cycle |
| `stagger` | Delay between children, in seconds |
| `travel` | Decorative entry displacement in pixels; does not change interaction geometry such as drag distance |
| `inView` | Default viewport entry settings for application sections |

Each transition includes `stiffness` / `damping` for spatial motion and
`duration` / `ease` for fades. Changing the spring does not recalculate fade duration; configure both when needed.
With normal motion, explicit component parameters such as `transition`, `duration`, and `toastSpring` take priority.

### Reduced motion

`reducedMotion` defines behavior when the system enables `prefers-reduced-motion`:

- `calm`: spatial and dimension changes complete immediately, opacity fades remain, and decorative loops stop.
- `off`: managed animations complete immediately, preserving state updates and exit/unmount sequencing.

Without the system preference, both configurations use full motion. For momo-managed animation targets, reduced-motion
policy takes priority over explicit transition parameters. Custom `animate`, `variants`, and `render`
content must still respect the system preference themselves.

### Custom components

`useMotionUITheme` and `useMotionUITransition` retain the official API.
`useFeel` is momo's adapter hook, returning three additional transitions with reduced-motion policy applied:

```tsx
import { pose, useFeel } from '@momots/design/motion';
import { motion } from 'motion/react';

function Panel() {
  const { theme, reduced, mode, transition } = useFeel('gentle');
  return (
    <motion.div
      initial={{ opacity: 0, y: reduced ? 0 : theme.travel.enter }}
      animate={pose({ opacity: 1, y: 0 }, mode)}
      transition={transition}
    />
  );
}
```

`transition` for mixed targets, `spatial` for position, dimensions, or imperative numeric animation, and `fade`
for opacity. When `reduced` is true, components must also remove decorative translation, scale, and blur targets;
setting a transition alone does not rewrite those targets. `pose` generates fixed-endpoint keyframes for reduced-motion
mode, allowing a system preference change to interrupt motion already in progress.

This theme covers momo-owned Motion animations. Drawer/Sheet Base UI gestures and CSS
transitions, Field.Error, and CSS color/border feedback retain their existing implementations.
`themeToCssVars` / `cssVarsToStyleString` generate theme variables on demand; the Provider does not inject CSS automatically.

### Exporting the theme to CSS

Import these utilities from `@momots/design/motion` to share motion theme parameters with custom CSS:

| Function | Input and output |
| --- | --- |
| `themeToCssVars(theme)` | Takes a complete theme and returns CSS variables prefixed with `--motion-ui-` |
| `cssVarsToStyleString(theme)` | Takes a complete theme and returns `:root { ... }` CSS containing those variables |
| `transitionToLinear(token)` | Takes a transition token and returns `{ easing, duration }`; easing is a CSS `linear(...)` string and duration is in seconds |

`themeToCssVars` exports transition easing, durations, spring-derived curves, stagger, and travel, excluding `inView` and reduced-motion policy. Each transition includes ordinary easing variables and spring variables ending in `-spring` and `-spring-duration`.

`transitionToLinear` generates its spring curve and duration only from `stiffness` and `damping`, without using the fade channel's `duration` or `ease`.

```ts
import {
  cssVarsToStyleString,
  defineTheme,
  themeToCssVars,
  transitionToLinear,
} from "@momots/design/motion";

const theme = defineTheme();
const variables = themeToCssVars(theme);
const stylesheet = cssVarsToStyleString(theme);
const { easing, duration } = transitionToLinear(theme.transitions.snap);
```

These functions return data or text without injecting styles or observing system preferences. Applications write the stylesheet and handle `prefers-reduced-motion` in custom CSS. There is no need to regenerate the entire theme CSS on every component render.
