`Skeleton` and `SkeletonText` reserve the space that asynchronous content will occupy, handling only shape and animation. `SkeletonReveal` wipes away the placeholder when data arrives to expose the real content underneath. None of them determine loading state or own data: the component that owns the data decides whether it is loading, and the skeleton responds.

## Basic usage

```tsx
import { Skeleton, SkeletonText } from '@momots/design/components/skeleton';

function ProfileCard({ profile }: { profile?: Profile }) {
  if (!profile) {
    return (
      <div aria-busy='true' className='grid gap-momo-sm'>
        <Skeleton shape='circle' className='size-14' />
        <SkeletonText lines={2} lastLineRatio={0.5} className='text-momo-body-sm' />
        <Skeleton className='h-40 w-full' shape='lg' />
      </div>
    );
  }

  return <ProfileContent profile={profile} />;
}
```

Specify dimensions, radius, and spacing through `className`, using momo's Tailwind tokens. Skeletons have no preset width or height because they do not know the content's dimensions; callers must supply these according to the final layout.

## Animation

| `variant` | Effect |
| --- | --- |
| `shimmer` | Default. A highlight sweeps left to right, suitable for larger placeholders such as cards and lists |
| `pulse` | A gentle transition between the base and highlight colors, resembling the natural rhythm of text blocks |
| `solid` | Static background with no looping animation |

`duration` sets the length of one loop in seconds and defaults to `2`. Non-finite or non-positive values fall back to the default instead of stopping the animation. The shimmer changes only the inner highlight layer's `transform`, running on the compositor without layout or repaint, so it remains stable even in long mobile lists.

When the system enables `prefers-reduced-motion: reduce`, all three animation modes become static backgrounds while preserving their dimensions. This uses the motion posture resolved by `MotionUIThemeProvider` and requires no additional configuration.

## Shape

| `shape` | Radius |
| --- | --- |
| `sm` | `momo-radius-xs` |
| `md` | Default. `momo-radius-sm` |
| `lg` | `momo-radius-lg` |
| `pill` | `momo-radius-pill` |
| `circle` | `momo-radius-full`; use with equal width and height |
| `none` | No rounded corners |

`shape` is a shortcut for common radii. For other values, use a class such as `className='rounded-momo-xl'`; it comes after `shape` and overrides the default.

## Text placeholders

```tsx
<SkeletonText lines={3} lastLineRatio={0.6} className='text-momo-body-sm' />
```

`SkeletonText` generates placeholders by line. Each line inherits the host's line height (`1lh`), matching the real text's font size and line height when you apply the same font-size class through `className`. `lines` below 1 renders one line, and fractional values are rounded down. `lastLineRatio` affects only the final line and is clamped between 0 and 1, preventing the paragraph from looking like a solid rectangle.

Each row occupies one line box (`1lh`). The gray bar itself is `0.7lh` tall and vertically centered, so line spacing follows naturally from the line height. As a result, `n` placeholder lines are as tall as `n` real text lines, avoiding paragraph resizing during the transition.

## Transitioning to real content

Replacing a skeleton directly with content when data arrives can cause an abrupt visual jump. `SkeletonReveal` keeps the real content mounted beneath a placeholder layer, then wipes that layer away from left to right when the data is ready.

```tsx
<SkeletonReveal pending={!data} fallback={<Skeleton className='h-40 w-full' />}>
  <CardContent data={data} />
</SkeletonReveal>
```

| Prop | Description | Default |
| --- | --- | --- |
| `pending` | Whether content is still loading | — |
| `fallback` | Placeholder content; when omitted, a `Skeleton` fills the host | `<Skeleton className='size-full' />` |
| `reveal` | `wipe` removes the placeholder left to right; `fade` crossfades it | `wipe` |
| `duration` | Transition duration in seconds; `0` completes immediately | `0.6` for wipe; `0.3` for fade |
| `delay` | Delay before revealing, in seconds | `0` |

The transition uses complementary masks. A soft-edged gradient mask on the placeholder moves from right to left, gradually revealing the occupied area. It does not depend on View Transitions, so behavior is consistent in Safari and with React concurrent rendering. The `wipe` mask has a gradient edge rather than a hard line.

While loading, the real content remains `inert` and `aria-hidden`: it cannot receive keyboard focus, and screen readers do not read it before the placeholder. Both attributes are removed when the transition completes, restoring interaction. The content layer has a mask complementary to the placeholder's: it is fully hidden during loading, and the soft edges of the two masks remain exactly complementary during the wipe. Even sparse gray placeholder bars therefore do not expose the content between them. Once revealed, the content mask is removed so it does not clip shadows or overflow. Because content stays mounted, the host takes the greater height of the content and placeholder, preventing the list from collapsing when placeholders appear. To avoid resizing afterward, do not make the placeholder taller than the real content. The default placeholder automatically fills the content box; custom placeholders should match the real content's dimensions. Loading again restores the placeholder and repeats the process.

When reduced motion is enabled, `SkeletonReveal` skips the mask animation and removes the placeholder immediately.

## Examples

The following examples simulate requests with a timer. Click “Reload” on the right to replay loading and the transition.

### Profile card

Split the card into its cover, avatar, name, bio, and statistics. Wrap each part in `SkeletonReveal` and use increasing `delay` values to stagger reveals. When `fallback` is omitted, the default placeholder fills the content's own box, naturally matching its dimensions. Supply custom placeholders only where special shapes are needed, such as the avatar and bio.

<SkeletonProfileDemo />

```tsx
<article aria-busy={pending || undefined}>
  <SkeletonReveal pending={pending}>
    <Cover />
  </SkeletonReveal>
  <SkeletonReveal
    pending={pending}
    delay={0.08}
    fallback={<Skeleton shape='circle' className='size-full' />}
  >
    <Avatar />
  </SkeletonReveal>
  <SkeletonReveal
    pending={pending}
    delay={0.24}
    fallback={<SkeletonText lines={2} lastLineRatio={0.6} className='text-momo-body-sm' />}
  >
    <p className='text-momo-body-sm'>{profile.bio}</p>
  </SkeletonReveal>
</article>
```

Since content stays mounted during loading, it needs values that can establish the layout. Before data arrives, render placeholder data with the same structure, such as `profile ?? placeholderProfile`. It remains under `inert` and `aria-hidden`, invisible and inaccessible to the user.

### Message list

Stagger rows from the same request by their index to make the list appear to be written line by line. Each row uses a custom avatar and two-line text placeholder with the same height as the real row.

<SkeletonListDemo />

```tsx
{messages.map((message, index) => (
  <li key={message.id}>
    <SkeletonReveal pending={pending} delay={index * 0.08} fallback={<MessageRowSkeleton />}>
      <MessageRow message={message} />
    </SkeletonReveal>
  </li>
))}
```

Keep staggered delays around 50–100 milliseconds per item and the whole list's delay within half a second. For longer lists, delay only the first few visible rows.

### Article body

Long text works well with `reveal='fade'`. A directional wipe reinforces the reading direction and can feel excessive across a large passage. Apply the same font-size classes to the heading and body `SkeletonText` as to the real text so their line heights match.

<SkeletonArticleDemo />

```tsx
<SkeletonReveal
  pending={pending}
  reveal='fade'
  fallback={<SkeletonText lines={4} lastLineRatio={0.45} className='text-momo-body-md' />}
>
  <p className='text-momo-body-md'>{article.body}</p>
</SkeletonReveal>
```

### Image grid

Determine image dimensions before loading. Reserve space with `aspect-*` or fixed width and height so placeholders do not collapse when images arrive. Calculate delays by row and column to reveal the grid from the upper left to the lower right.

<SkeletonGalleryDemo />

```tsx
<SkeletonReveal
  pending={!loaded}
  delay={(index % 3) * 0.06 + Math.floor(index / 3) * 0.12}
  fallback={<Skeleton shape='lg' className='size-full' />}
>
  <img src={src} alt={alt} className='aspect-square rounded-momo-lg object-cover' onLoad={onLoad} />
</SkeletonReveal>
```

### Values within a section

The page structure is already known: the heading, description, and metric labels do not need to wait; only the values come from the API. Limit `SkeletonReveal` to the small region actually waiting for data so users can still read “This month” and understand each metric while loading.

<SkeletonSectionDemo />

```tsx
<Section title='This month' aria-busy={pending || undefined}>
  <dl className='grid grid-cols-3'>
    {metrics.map((metric, index) => (
      <div key={metric.label}>
        <dt>{metric.label}</dt>
        <SkeletonReveal pending={pending} delay={index * 0.08} className='w-fit'>
          <dd>{metric.value}</dd>
        </SkeletonReveal>
      </div>
    ))}
  </dl>
</Section>
```

Smaller placeholder regions let the page communicate more information during loading. Cover an entire region with one skeleton only when its content shape is genuinely unknown.

## Semantics and accessibility

The skeleton root, each line, and animation layers all have `aria-hidden`. Placeholders carry no information, so screen readers should not announce an empty block. Express loading state on the outer element:

```tsx
<section aria-busy='true' aria-label='Profile'>
  <Skeleton className='h-40 w-full' />
</section>
```

The appropriate location for `aria-busy` depends on which part is loading; the component does not guess. A `role='status'` container can announce “Loading” for a whole page, but remove it after loading to avoid duplicate focus or announcements.

## Native props

`Skeleton` and `SkeletonText` accept native `div` attributes, `ref`, and `render`. `render` receives `SkeletonState`, containing `slot: 'skeleton'`, `variant`, and `shape`:

```tsx
<Skeleton
  render={(props, state) => (
    <span {...props} data-shape={state.shape} />
  )}
  shape='circle'
/>
```

These values are also exposed through `data-slot`, `data-variant`, and `data-shape`; `SkeletonText` additionally exposes `data-lines`. To use a different surrounding tag, place `SkeletonText` inside the host rather than replacing its root: the component generates each line itself.
