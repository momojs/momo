`Input` wraps Base UI Input and renders a native `input` by default. It preserves controlled and uncontrolled values, native form attributes, `render` composition, and refs, while using momo semantic tokens for consistent sizing, focus, disabled, and validation states.

## Usage

`Input` does not render a label automatically. When used independently, provide an accessible name through a native `label`:

```tsx
import { Input } from "@momots/design/components/input";

<label htmlFor="account-email">Email</label>
<Input
  id="account-email"
  name="email"
  type="email"
  placeholder="name@example.com"
/>
```

## Controlled and uncontrolled values

Use `value` and `onValueChange` to manage a controlled value:

```tsx
const [email, setEmail] = useState("");

<Input
  value={email}
  onValueChange={setEmail}
  type="email"
/>
```

Use `defaultValue` when the component only needs to manage its initial value:

```tsx
<Input defaultValue="Momo workspace" />
```

Native `onChange` is still forwarded. `onValueChange` directly provides the new string value and Base UI event details, making it suitable for controlled state. Avoid performing the same application update in both callbacks.

## Field integration

Input integrates automatically with momo Field. Field associates labels, descriptions, and errors and passes `valid`, `invalid`, `dirty`, `touched`, `filled`, and `focused` states to Input:

```tsx
import { Field } from "@momots/design/components/field";
import { Input } from "@momots/design/components/input";

<Field
  name="email"
  label="Email"
  variant="stacked"
  description="Used for workspace notifications."
  error="Enter a valid email address."
  validationMode="onBlur"
>
  <Input type="email" required />
</Field>
```

Without Field, express external validation state through `aria-invalid` and associate error text with `aria-describedby`.

## Component boundaries

`Input` handles only an atomic single-line input. It does not include a label, description, error, prefix, suffix, clear button, or password visibility button. Compose these outside it using Field or application code.

Use `Numeric` for step buttons, number formatting, or dragging to adjust values. Use native `textarea` or a suitable multiline component for multiline content. Native input types such as `type="file"` can still be forwarded directly.

## Props

| Prop | Type | Description |
| --- | --- | --- |
| `size` | `"sm" \| "md" \| "lg"` | Visual size; defaults to `"md"` |
| `nativeSize` | `number` | Maps to the native `size` character-width hint; prefer CSS width for page layout |
| `value` | Native input value | Controlled value |
| `defaultValue` | Native input default value | Uncontrolled initial value |
| `onValueChange` | `(value: string, details) => void` | Base UI value change callback |
| `onChange` | Native input change handler | Native change event callback |
| `type` | Native input type | Input type, such as `"text"`, `"email"`, `"search"`, or `"file"` |
| `name` / `form` / `autoComplete` | Native input props | Form field name, associated form, and autofill hint |
| `disabled` / `readOnly` / `required` | `boolean` | Disabled, read-only, and required states |
| `aria-invalid` | `boolean \| "true" \| "false"` | External validation state when used independently |
| `className` | `string \| ((state: InputState) => string \| undefined)` | Additional styles; the callback can read Base UI Field state |
| `render` | Base UI render prop | Compose or replace the underlying element |
| `ref` | React ref | Access the underlying element |
| `...props` | Base UI Input props | Other Base UI and native input attributes |
