`usePrevious` records the current value in an effect and returns that record on subsequent renders. It suits comparing page numbers, dates, or selected items across adjacent commits.

## Comparing the current and previous pages

```tsx
import { usePrevious } from "@momots/design/hooks";

function PageDirection({ page }: { page: number }) {
  const previous = usePrevious(page);
  const direction = previous === null ? 0 : Math.sign(page - previous);

  return (
    <p>
      Current page: {page};
      {direction > 0 ? "Moving forward" : direction < 0 ? "Moving backward" : "Page unchanged"}
    </p>
  );
}
```

## What the returned value represents over time

The first render returns `null`. The effect saves the current value only after commit; saving the record does not itself trigger a render.

Assuming the effect has run after each commit, behavior is as follows:

| Render reason | Current `page` | Return value |
| --- | --- | --- |
| Initial mount | `1` | `null` |
| Page changes to 2 | `2` | `1` |
| Parent renders again due to other state | `2` | `2` |
| Page changes to 3 | `3` | `2` |

It does not retain the last distinct value or a complete history. If transition direction must remain fixed throughout an animation, record direction as separate state when the page changes rather than relying on this hook to keep returning the old page across every later render.

Objects and arrays are stored by reference, without snapshots or deep copies. In-place mutations also affect the recorded reference, so use immutable updates.

## API

```ts
function usePrevious<T>(value: T): T | null;
```

Server rendering does not run effects, so the return value is `null`. Since an actual input may also be `null`, the returned value alone cannot distinguish no record from a previously recorded null value. Model that distinction explicitly if needed.
