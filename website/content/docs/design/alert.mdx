## Usage

```tsx
import { InformationCircleIcon } from "@hugeicons/core-free-icons";
import { HugeiconsIcon } from "@hugeicons/react";

import { Alert } from "@momots/design/components/alert";

<Alert
  variant="info"
  icon={<HugeiconsIcon icon={InformationCircleIcon} />}
  title="New sync policy"
  description="Local settings will sync automatically on the next launch."
/>;
```

The built-in `AlertIcon` treats icons as decorative and sets `aria-hidden`. Titles and descriptions must communicate the message without relying solely on color or icons.

## Semantic variants

| Variant | Use case |
| --------- | ------------------------------ |
| `default` | Neutral information and general reminders |
| `info` | New information, feature hints, and non-blocking updates |
| `success` | Completed actions, successful saves, and restored state |
| `warning` | Situations needing attention or with potential consequences |
| `danger` | Failed actions, data risks, or blocking issues |

```tsx
<Alert variant="success" title="Import complete" description="24 records added." />
```

## Actions

`action` can contain a button or link. Describe its result instead of using ambiguous text such as “OK”:

```tsx
<Alert
  variant="warning"
  title="Connection expiring soon"
  description="Reauthorize to continue syncing."
  action={<Button size="sm">Reauthorize</Button>}
/>
```

Alert does not disappear or render a close button. Control mounting with application state for dismissible feedback. Use Dialog when a flow must pause for a decision; Alert is not an AlertDialog.

## Live region

The default `role="alert"` suits important dynamic messages needing immediate announcement after mounting. Use `role="status"` for ordinary asynchronous progress or non-urgent results. Static descriptions present on initial load generally need no live region; pass `role={null}`:

```tsx
<Alert role="status" title="Syncing" />

<Alert role={null} title="This setting affects only the current workspace" />
```

Do not add conflicting `aria-live` values to the same message. Avoid assertive alerts for frequently changing content, which can interrupt assistive-technology users.

## Slots

Alert's `title` and `description` supply content. `slots.icon`, `slots.content`, `slots.title`, `slots.description`, and `slots.action` follow [Content Slots](/docs/design/content-slots): omitted slots use default nodes when content exists; props objects configure nodes; `render` changes elements; `false` removes nodes.

```tsx
<Alert
  variant="danger"
  title="Upload failed"
  description="Check your connection and try again."
  action={<button type="button">Retry upload</button>}
  slots={{
    title: { render: <h3 />, className: "uppercase" },
    description: { id: "upload-error" },
  }}
/>
```

The same entry exports `AlertRoot`, `AlertIcon`, `AlertContent`, `AlertTitle`, `AlertDescription`, and `AlertAction` for manual composition:

```tsx
<AlertRoot variant="info" role={null}>
  <AlertIcon>{icon}</AlertIcon>
  <AlertContent>
    <AlertTitle>Note</AlertTitle>
    <AlertDescription>This is a static description.</AlertDescription>
  </AlertContent>
</AlertRoot>
```

## Accessibility

- Use `role="alert"` only for important dynamic messages requiring immediate announcement; use `status` for polite updates and remove the role for static content.
- Titles and descriptions must express status in text; color and icons only support it.
- The default icon wrapper is decorative. Compose it manually with an accessible name if the icon carries independent information.
- Actions should use real `button` or `a` elements with text that makes sense outside its context.
- Alert provides inline feedback, without focus trapping, confirmation flow, or modal semantics.

## Props

### Alert

| Prop | Type | Description |
| ------------- | ----------------------------------------------------------- | -------------------------------------------- |
| `variant` | `"default" \| "info" \| "success" \| "warning" \| "danger"` | Semantic/visual variant; defaults to `"default"` |
| `icon` | `ReactNode` | Optional decorative icon |
| `title` | `ReactNode` | Short heading |
| `description` | `ReactNode` | Additional context or suggested action |
| `action` | `ReactNode` | Optional button or link |
| `role` | `AriaRole \| null` | Defaults to `"alert"`; `null` removes the live-region role |
| `slots` | `AlertProps['slots']` | Configures content nodes; supports `render` or `false` |
| `className` | `string` | Additional root styles |
| `...props` | `React.ComponentProps<"div">` | Other native div props |

### Primitives

All primitives accept their native element props and `className`. Content primitives also support `render`, merging default styles, events, and ref. `AlertRoot` additionally accepts `variant` and nullable `role`; other parts provide consistent layout, typography, and `data-slot` metadata.
