`Field` wraps Base UI Field to combine an accessible label, control, and validity state. `cell` exposes descriptions or errors through a hint button; `stacked` displays them inline. Field works independently; inside `ToastProvider`, `cell` hints automatically use Toast. It preserves native submission, controlled/uncontrolled validation, `actionsRef`, `render`, and ref, while momo semantic tokens unify visual states.

## Usage

Without `children`, Field renders a native input with momo styles. Configure it through the `control` slot:

```tsx
import { Field } from "@momots/design/components/field";

<Field
  name="email"
  label="Email"
  variant="stacked"
  description="Used for workspace notifications."
  control={{
    type: "email",
    placeholder: "name@example.com",
    required: true,
  }}
/>
```

`label` always renders through Base UI `Field.Label`. Both variants retain description and error semantics inside the field, automatically associated with the control's `aria-describedby`. A placeholder is an input hint, not a replacement for a label.

## Composing custom controls

`children` replaces the built-in native input instead of becoming its child. momo `Input` and Base UI controls that understand Field context automatically receive disabled, focused, dirty, touched, filled, and valid states:

```tsx
import { Field } from "@momots/design/components/field";
import { Input } from "@momots/design/components/input";

<Field
  name="workspace"
  label="Workspace name"
  variant="stacked"
  description="Team members can see this name."
>
  <Input required minLength={3} placeholder="Momo Studio" />
</Field>
```

When `children` exists, the `control` slot is not rendered, preventing two controls from registering with the same Field.

Button-triggered controls such as Select should not use native `<label>` behavior. For this configuration, compose exported primitives and disable `nativeLabel`:

```tsx
import { Field as BaseField } from "@base-ui/react/field";
import {
  FieldDescription,
  FieldLabel,
} from "@momots/design/components/field";

<BaseField.Root name="region">
  <FieldLabel nativeLabel={false}>Region</FieldLabel>
  <Select options={regions} />
  <FieldDescription>Used to determine data residency.</FieldDescription>
</BaseField.Root>
```

## Validation

### Native constraints

The built-in Control supports native constraints including `required`, `minLength`, `pattern`, and `type`. `validationMode` controls when validation runs; Base UI Form determines the default behavior:

```tsx
<Field
  name="username"
  label="Username"
  variant="stacked"
  validationMode="onBlur"
  control={{ required: true, minLength: 3 }}
  error="The username must contain at least 3 characters."
/>
```

Omitting `error` or passing `undefined` uses error text from the browser, `validate`, or Base UI Form, including `cell` hints. Explicit `null` retains empty content in both variants without falling back or changing validity. The `cell` error icon follows actual validity; preset error text does not mark a valid field invalid. To match an individual `ValidityState`, such as `tooShort`, use the `FieldError` primitive's `match` prop.

### Custom validation

`validate` can synchronously or asynchronously return a string, an array of strings, or `null`:

```tsx
<Field
  name="slug"
  label="Project slug"
  validationMode="onChange"
  validationDebounceTime={250}
  validate={async (value) => {
    if (typeof value !== "string" || value.length < 3) {
      return "Enter at least 3 characters.";
    }

    return (await isSlugAvailable(value)) ? null : "This slug is already in use.";
  }}
  control={{ required: true }}
/>
```

When an external form library controls errors, pass `invalid` to Root and set `match: true` for fixed error text:

```tsx
<Field
  name="email"
  label="Email"
  variant="stacked"
  invalid
  error="This email is already registered."
>
  <Input type="email" />
</Field>
```

For custom feedback, `validity` receives the full Base UI validity state without adding DOM:

```tsx
<Field
  label="Password"
  control={{ type: "password", required: true, minLength: 8 }}
  validity={({ validity, value }) => (
    <PasswordStrength value={String(value ?? "")} invalid={validity.tooShort} />
  )}
/>
```

## Visual variants

- `cell` is the default compact two-column layout, with a description/error hint button beside the label.
- `stacked` uses a surface, border, and shadow and displays descriptions and errors. Base UI state callbacks map focus and error states to CVA without relying on `data-*` selectors.

```tsx
<Field
  variant="stacked"
  label="Type DELETE to continue"
  control={{ required: true, pattern: "DELETE" }}
/>
```

### Automatic Toast integration

The `cell` hint button reads the nearest `ToastProvider` through `useToast({ strict: false })`, requiring no additional Field configuration:

```tsx
import { Field } from "@momots/design/components/field";
import { ToastProvider } from "@momots/design/components/toast";

<ToastProvider>
  <Field
    label="Email"
    description="Used for workspace notifications."
    control={{ type: "email", required: true }}
  />
</ToastProvider>
```

Without `ToastProvider`, Field still renders normally; activating the hint button only logs a missing-provider `console.warn` without expanding content. With a provider, it displays a Toast. Errors depend on actual validity and take priority over descriptions; notifications do not automatically appear on every validation.

The hint button's `onTap` follows Motion tap gestures: completed pointer/touch taps and Enter on a focused button. Canceled gestures do not show a Toast. Native Space-generated clicks and `HTMLElement.click()` are not converted into taps.

The hint button retains native button semantics. The current hint's semantic nodes stay in their Field and remain associated with the control; Toast receives only the resolved display content. `stacked` always uses inline feedback.

## Control slot

`control` follows the momo slot convention:

- `undefined` uses the default slot.
- A props object configures the default primitive, retaining Base UI state callbacks and accessibility semantics.
- ReactNode replaces the entire slot.
- `false` removes the slot.

```tsx
<Field
  label="Email"
  variant="stacked"
  control={{ size: "lg", type: "email" }}
  description="Used only for sign-in."
/>
```

`children` always takes priority over `control`. To configure underlying Label, Description, or Error props, compose the exported primitives below.

## Standalone primitives

The same entry exports `FieldLabel`, `FieldControl`, `FieldDescription`, `FieldError`, `FieldItem`, and `FieldValidity`. `FieldItem` represents one checkbox/radio-group option and is not automatically rendered by the high-level `Field`.

```tsx
import { CheckboxGroup } from "@base-ui/react/checkbox-group";
import { Field as BaseField } from "@base-ui/react/field";
import { Fieldset } from "@base-ui/react/fieldset";
import {
  Checkbox,
  FieldDescription,
  FieldItem,
  FieldLabel,
} from "@momots/design";

<BaseField.Root>
  <Fieldset.Root render={<CheckboxGroup />}>
    <Fieldset.Legend>Backup schedule</Fieldset.Legend>
    <FieldItem>
      <Checkbox value="daily" />
      <div>
        <FieldLabel>Daily</FieldLabel>
        <FieldDescription>Runs every day at 00:00.</FieldDescription>
      </div>
    </FieldItem>
  </Fieldset.Root>
</BaseField.Root>
```

These primitives require Base UI Field context. Prefer the high-level `Field` for ordinary single fields.

## Props

### Field

| Prop | Type | Description |
| --- | --- | --- |
| `label` | `ReactNode` | Accessible label; if omitted, give the control `aria-label` or `aria-labelledby` |
| `children` | `ReactNode` | Custom control that replaces the built-in Control |
| `size` | `"sm" \| "md" \| "lg"` | Visual size of the label and built-in Control; defaults to `"md"` |
| `description` | `ReactNode` | Automatically associated description; shown on demand by `cell`, inline by `stacked` |
| `error` | `ReactNode` | Validation error content; defaults to Base UI-generated errors; shown on demand by `cell` |
| `variant` | `"cell" \| "stacked"` | Visual variant; defaults to `"cell"` |
| `control` | Slot config | Configures, replaces, or removes the built-in Control |
| `validity` | `(state) => ReactNode` | Access to full validity state |
| `name` | `string` | Form field name; takes priority over the inner control's name |
| `disabled` / `invalid` / `dirty` / `touched` | `boolean` | Controls or overrides Field state |
| `validate` | Base UI validate callback | Synchronous or asynchronous custom validation |
| `validationMode` | `"onSubmit" \| "onBlur" \| "onChange"` | Validation timing |
| `validationDebounceTime` | `number` | Debounce duration in milliseconds for onChange validation |
| `actionsRef` | Base UI Field actions ref | Calls imperative `validate()` |
| `className` | `string \| ((state) => string)` | Additional root styles with access to Field state |
| `render` / `ref` | Base UI props | Replaces or accesses the Root element |

### FieldControl

| Prop | Type | Description |
| --- | --- | --- |
| `size` | `"sm" \| "md" \| "lg"` | Visual size; defaults to `"md"` |
| `nativeSize` | `number` | Native input character-width hint |
| `onValueChange` | `(value, details) => void` | Base UI value change callback |
| `className` | `string \| ((state) => string)` | Additional styles with access to Field state |
| `...props` | Base UI Field Control props | Other input, form, render, and ref props |

## Accessibility

- Do not replace labels with placeholders. For visually hidden labels, use `FieldLabel` with `className="sr-only"`.
- Both variants automatically register descriptions and errors with the control's `aria-describedby`, including when `cell` hides content or uses Toast.
- Prefer `disabled` on Field Root so the label, description, and control share state.
- `stacked` changes layout and visual hierarchy without changing validation rules or error severity.
- To announce dynamic server errors immediately, explicitly add `role="alert"` or `aria-live="polite"` through `FieldError`. The component does not force announcements for every keystroke validation.
