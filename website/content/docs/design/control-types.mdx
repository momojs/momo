`@momots/design/shared` provides lightweight types for common data shapes across controls. These are structural conventions, not runtime models: components read only the fields they need and do not automatically implement every capability in `ControlOption`.

<ControlTypesPlayground />

## Imports

```tsx
import type {
  ControlAxis,
  ControlDirection,
  ControlOption,
  ControlSize,
  ControlValue,
} from "@momots/design/shared";
```

## Basic types

| Type | Definition | Current use |
| --- | --- | --- |
| `ControlValue` | `string \| number \| null` | Select, Accordion, RadioGroup, and keys for Highlight / AutoSize registrars |
| `ControlSize` | `"sm" \| "md" \| "lg"` | Shared size vocabulary; component `size` types are currently mostly inferred from their own variants and do not directly reference this alias |
| `ControlAxis` | `"x" \| "y"` | Internal Drawer layout and measurement axis |
| `ControlDirection` | `"up" \| "down" \| "left" \| "right"` | Direction input for `asAxis`; Drawer's public direction type is currently inferred from Base UI |

These types are structurally compatible. For example, a `ControlSize` variable can be passed to a component accepting `"sm" | "md" | "lg"`, but this does not mean every component directly depends on that type alias.

### asAxis: convert a direction to an axis

The same entry point exports `asAxis`, which converts a direction to the axis needed for layout or measurement:

```ts
import { asAxis } from "@momots/design/shared";

asAxis("left");  // "x"
asAxis("right"); // "x"
asAxis("up");    // "y"
asAxis("down");  // "y"
asAxis();        // undefined
```

It accepts `ControlDirection | undefined` and returns `ControlAxis | undefined`. It only determines the axis, without encoding positive or negative movement or converting logical directions for RTL.

## ControlOption

```ts
type ControlOption<TValue extends ControlValue, TMeta = unknown> = {
  value: TValue;
  label: React.ReactNode;
  style?: React.CSSProperties;
  icon?: React.ReactNode;
  extra?: React.ReactNode;
  textValue?: string;
  className?: string;
  disabled?: boolean;
  href?: string;
  meta?: TMeta;
};
```

`value` and `label` are required. `TMeta` gives application metadata a precise type, but momo components do not read or modify `meta`; the caller must use it explicitly.

```tsx
type PlanMeta = { seats: number };

const plans: ControlOption<"starter" | "team", PlanMeta>[] = [
  {
    value: "starter",
    label: "Starter",
    textValue: "Starter plan",
    meta: { seats: 1 },
  },
  {
    value: "team",
    label: "Team",
    disabled: false,
    meta: { seats: 5 },
  },
];
```

### Fields consumed by components

| Component | Standard fields explicitly read | Extra fields / notes |
| --- | --- | --- |
| `Select` | `value`, `label`, `style`, `icon`, `textValue`, `className`, `disabled` | `textValue` supplies the accessible name for non-text labels |
| `ToggleGroup` | `value`, `label`, `style`, `icon`, `textValue`, `className`, `disabled` | `textValue` is the fallback for the button's `aria-label` |
| `Tabs` | `value`, `label`, `style`, `icon`, `className`, `disabled` | `TabOption` also adds `content` |
| `Accordion` | `value`, `label` | `AccordionOption` also adds `content`; other standard fields are not currently passed to Item |
| `PickerCore` | `value`, `label`, `textValue`, `disabled` | `textValue` supplies the accessible name for wheel options |
| `RadioGroup` | `value` | The current wrapper does not automatically render `label`; provide an accessible name separately |

No component currently consumes `extra`, `href`, or `meta` automatically. A field's presence in the shared type does not imply that a component renders a badge, creates a link, or performs navigation. Compose those behaviors at the call site, or first add an explicit API to the relevant component.

## Reusing an option array

An array can safely be shared when the intersection of fields consumed by two components meets your needs:

```tsx
const options: ControlOption<"grid" | "list">[] = [
  { value: "grid", label: "Grid", textValue: "Grid view" },
  { value: "list", label: "List", textValue: "List view" },
];

<ToggleGroup options={options} value={view} onChange={setView} />
<Select options={options} value={view} onChange={setView} />
```

If a field matters to only one consumer, the other component ignores it. Sharing the array does not supply missing behavior to either component.
