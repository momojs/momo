`useMergedRefs` 把多个 ref 合并为一个稳定的回调 ref，让组件内部和调用方获得同一个节点。它适用于需要内部测量、聚焦或第三方库绑定，同时又向外暴露节点的组件。

## Playground

输入一些文字，通过对象 ref 聚焦，再切换回调 A / B。事件记录会显示旧回调的清理和新回调的绑定，输入框仍保留原来的内容。卸载后再挂载，则会创建新的输入框。

对象 ref 用于聚焦，回调 ref 负责监听焦点事件；两者通过同一个合并 ref 绑定节点。清空事件记录只重置演示日志，不会重新绑定 refs。

## 内部 ref 与外部 ref

下面的输入框用内部 ref 实现聚焦，同时保留调用方传入的 ref：

```tsx
import type { ComponentPropsWithRef } from "react";
import { useRef } from "react";
import { useMergedRefs } from "@momots/design/hooks";

function SearchInput({
  ref,
  ...props
}: ComponentPropsWithRef<"input">) {
  const inputRef = useRef<HTMLInputElement>(null);
  const mergedRef = useMergedRefs(inputRef, ref);

  return (
    <div>
      <input {...props} ref={mergedRef} />
      <button type="button" onClick={() => inputRef.current?.focus()}>
        聚焦输入框
      </button>
    </div>
  );
}

function Search() {
  const ref = useRef<HTMLInputElement>(null);
  return <SearchInput ref={ref} aria-label="搜索项目" />;
}
```

也可以从 `@momots/design/hooks/use-merged-refs` 独立导入。以上示例使用 React 19 的 ref prop，不需要额外包裹 `forwardRef`。

## 挂载与清理

**回调 ref** 是接收节点的函数；它可以返回一个清理函数，在节点脱离绑定时释放资源。

| 输入 ref | 绑定节点时 | 解除绑定时 |
| --- | --- | --- |
| 对象 ref | 将节点写入 `.current` | 将 `.current` 设为 `null` |
| 返回清理函数的回调 ref | 调用回调，保存清理函数 | 调用清理函数，不再额外调用 `ref(null)` |
| 没有返回清理函数的回调 ref | 调用 `ref(node)` | 调用 `ref(null)` |
| `null` / `undefined` | 忽略 | 忽略 |

例如，可以把原生事件监听的生命周期交给回调 ref：

```tsx
import { useCallback, useRef } from "react";
import { useMergedRefs } from "@momots/design/hooks";

function FocusProbe() {
  const localRef = useRef<HTMLInputElement>(null);
  const observe = useCallback((node: HTMLInputElement | null) => {
    if (!node) return;
    const onFocus = () => console.log("输入框获得焦点");
    node.addEventListener("focus", onFocus);
    return () => node.removeEventListener("focus", onFocus);
  }, []);
  const ref = useMergedRefs(localRef, observe);

  return <input ref={ref} aria-label="焦点示例" />;
}
```

## 输入 refs 变化时

返回的合并回调在同一次组件挂载期间保持稳定。输入 refs 的数量、顺序或引用发生变化时，Hook 会在提交阶段清理旧的一组 refs，再把当前节点绑定到新的一组 refs；即使 DOM 节点没有变化，也会同步。

因此，稳定的合并回调不代表输入回调永远只执行一次。内联创建的回调 ref 每次渲染都不同，会触发旧绑定清理和新绑定建立；需要避免这种重复工作时，用 `useCallback` 保持输入回调稳定。开发环境的 StrictMode 也可能额外执行绑定和清理。

## API

```ts
function useMergedRefs<Value>(
  ...refs: Array<React.Ref<Value> | undefined>
): React.RefCallback<Value>;
```

所有输入 refs 应指向同一个值类型。一次调用返回的合并 ref 应只绑定一个节点；需要绑定多个节点时，为每个节点分别调用 Hook，或使用专门的节点注册机制。
