`Tooltip` adds brief visual hints beside controls. It shares Popover's themed surface, positioning, arrow, and Motion animation; provide content through `children` and a trigger through `trigger`.

## Playground

<TooltipPlayground />

Hover or Tab-focus a button to open its tooltip; Escape closes it. The two buttons share a `TooltipProvider`, so moving from an open tooltip to its neighbor skips the full delay.

## Basic usage

```tsx
import { Button } from '@momots/design/components/button';
import { Tooltip } from '@momots/design/components/tooltip';

<Tooltip trigger={<Button variant='outline'>Save</Button>} showArrow>
  Save changes to the current workspace
</Tooltip>
```

`trigger` preserves the original element's events, styles, and ref. Custom components must forward received props and ref to a real DOM node. A `(props, state) => JSX` callback is also supported:

```tsx
<Tooltip
  trigger={(props, state) => (
    <button {...props} type='button' data-hint-open={state.open}>
      View history
    </button>
  )}
>
  View recent changes
</Tooltip>
```

## Delays and groups

```tsx
import { Tooltip, TooltipProvider } from '@momots/design/components/tooltip';

<TooltipProvider delay={500} closeDelay={100} timeout={400}>
  <Tooltip trigger={<button type='button'>Copy</button>}>Copy content</Tooltip>
  <Tooltip trigger={<button type='button'>Paste</button>}>Paste content</Tooltip>
</TooltipProvider>
```

Tooltip also works without a Provider. Default hover delay is `600ms` and close delay is `0ms`; keyboard focus skips hover delay. The Provider's default `timeout` is `400ms`, defining how long after leaving one tooltip adjacent tooltips can skip delay.

Individual `delay` and `closeDelay` override Provider settings. `closeOnClick` defaults to enabled; set it to `false` to retain the hint after clicking. By default, the pointer may move onto the hint without closing it; `disableHoverablePopup` disables this behavior.

## State and events

```tsx
const [open, setOpen] = useState(false);

<Tooltip
  open={open}
  onChange={setOpen}
  onOpenChange={(next, details) => {
    if (!next && details.reason === 'trigger-press') details.cancel();
  }}
  trigger={<button type='button'>Save</button>}
>
  Save changes
</Tooltip>
```

`open` controls state and `defaultOpen` supplies uncontrolled initial state. `onOpenChange` receives full Base UI event details first. After `details.cancel()`, internal state does not update and the simplified `onChange` is not called.

`disabled` disables only the tooltip, not its trigger. Set `disabled` on the button separately when needed.

## Positioning and styling

| Property | Default | Description |
| --- | --- | --- |
| `side` | `top` | Preferred side, adjusted by Base UI near boundaries |
| `align` | `center` | Alignment along the trigger |
| `sideOffset` | `8` | Distance from the trigger |
| `alignOffset` | `0` | Offset along the alignment axis |
| `showArrow` | `false` | Whether to show an arrow |
| `className` | — | Tooltip surface styles |
| `triggerClassName` / `positionerClassName` / `arrowClassName` | — | Styles for their respective nodes |

`triggerProps`, `portalProps`, `positionerProps`, `popupProps`, and `arrowProps` forward native props to each layer. For example, `positionerProps={{ collisionPadding: 12 }}` sets boundary clearance, and `portalProps={{ container }}` sets the mount container. Positioning and delay settings in underlying props override same-name top-level settings.

Portal defaults to `body`. Apply the theme class to an ancestor covering the Portal, or mount it inside the themed container with `portalProps.container`.

## Custom content nodes

As with Popover [Content Slots](/docs/design/content-slots), `slots.content` accepts a props object, element, render callback, or `false`. `children` still supplies content:

```tsx
<Tooltip
  trigger={<button type='button'>Formatting help</button>}
  slots={{ content: { render: <span />, className: 'block' } }}
>
  Markdown formatting is supported
</Tooltip>

<Tooltip
  trigger={<button type='button'>Keyboard shortcuts</button>}
  slots={{ content: (props, _state) => <span {...props} /> }}
>
  ⌘ K
</Tooltip>
```

Element shorthand is `slots={{ content: <span /> }}`. Generic container `state` is an empty object; trigger `state` includes `open`. `slots={{ content: false }}` removes the content node. Tooltip stays brief and has no `title`, `header`, or `footer`; use [Popover](/docs/design/popover) for forms, links, actions, or longer content.

## Animation and accessibility

Animation uses `useFeel('ui')`, scaling and fading around the computed positioning origin, then unmounting after exit. Reduced-motion preferences follow the shared theme's `calm` / `off` policy and stop spatial scaling.

Following [Base UI Tooltip semantics](https://base-ui.com/react/components/tooltip), hints are supplementary visual information and do not automatically become a trigger's accessible name or description. Give triggers visible text and icon buttons an `aria-label`. Show essential instructions directly on the page. Tooltips do not take keyboard focus, and touch interactions should not depend on hover hints.
