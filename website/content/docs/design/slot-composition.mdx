`SlotBaseConfig` 与 `render` 为 Numeric、Sheet、Drawer 等封装提供统一的 slot 契约：调用方既可以保留默认组件并追加 props，也可以用任意 ReactNode 完整替换它。

<SlotCompositionPlayground />

## 导入

```tsx
import {
  render,
  type SlotBaseConfig,
  type SlotBaseProps,
} from "@momots/design/shared";
```

## 四种配置值

假设组件内部这样渲染插槽：

```tsx
render(DefaultSlot, config, {
  children: "内部内容",
  "aria-label": "Status",
});
```

`config` 的运行时含义如下：

| `config` | 结果 |
| --- | --- |
| `undefined` | 直接返回 `undefined`，不渲染 slot |
| `true` | 渲染 `DefaultSlot`，只使用第三个参数提供的 props |
| props object | 渲染 `DefaultSlot`，先展开 config，再展开第三个参数；后者的同名 prop 优先 |
| ReactNode | 原样返回这个节点，忽略 `DefaultSlot` 和第三个参数 |

这里的 ReactNode 不只指 React element。当前运行时 guard 还识别 `null`、`undefined`、布尔值、字符串、数字、`bigint`，以及只包含这些值或合法 React element 的数组。因此 `null` / `false` 同样表示用该值完整替换默认 slot，最终不会产生可见内容。

`true` 是唯一的特殊布尔值：虽然它通常也是 ReactNode，但 `render` 把它保留为“启用默认 slot”的哨兵。

## 组件作者用法

```tsx
import type { SlotBaseConfig, SlotBaseProps } from "@momots/design/shared";
import { render } from "@momots/design/shared";

interface StatusProps extends SlotBaseProps {
  className?: string;
  role?: React.AriaRole;
}

function Status({ children, ...props }: StatusProps) {
  return <div {...props}>{children}</div>;
}

interface ResultProps {
  status?: SlotBaseConfig<StatusProps>;
}

function Result({ status = true }: ResultProps) {
  return render(Status, status, {
    role: "status",
    children: "Saved",
  });
}
```

默认值是否应为 `true` 由组件作者决定。如果 prop 没有默认值，省略它就会走 `undefined` 分支，不会渲染任何内容。

## 调用方用法

### 配置默认 slot

传 props object 时，默认组件及其既有行为仍然存在：

```tsx
<Numeric
  input={{
    className: "text-end tabular-nums",
    "aria-describedby": "amount-help",
  }}
/>
```

内部通过第三个参数注入的 props 最后展开。它适合保留组件必须控制的 `children`、状态或可访问属性，但也意味着调用方提供的同名值可能被覆盖。

### 完整替换 slot

传 React element 时，元素会被原样返回：

```tsx
<Numeric
  increment={
    <button type="button" onClick={incrementManually}>
      Add
    </button>
  }
/>
```

此时 `render` 不会克隆节点，也不会合并内部 props、事件、ref 或状态。调用方需要自行恢复键盘交互、可访问语义和组件逻辑。仅调整 class 或原生属性时，应优先使用 props object。

## 第三个参数也可以是 ReactNode

`render` 的第三个参数如果是 ReactNode，会先转换为 `{ children: node }`：

```tsx
render(Status, true, "Saved");
// 等价于渲染 <Status>Saved</Status>
```

如果第三个参数是 props object，它会直接参与合并。该参数只在 `config === true` 或 config 为 props object 时生效；config 是 ReactNode 时会被忽略。

需要留意一个当前实现细节：省略第三个参数时，`undefined` 也会转换成 `{ children: undefined }`。如果 config 是 props object，这会覆盖 config 自己的 `children`。组件作者需要保留 config 中的 children 时，应显式决定第三个参数的合并方式，而不要依赖省略参数。
