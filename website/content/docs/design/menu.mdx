`Menu` presents actions in a floating surface beside a trigger, suitable for project actions, user menus, and view settings. It follows the library's floating-surface positioning, theming, and motion conventions, reuses `Highlight` for continuously moving item highlights, and configures content nodes through shared content props and `slots`. Base UI handles focus, keyboard navigation, and menu semantics.

## Basic usage

```tsx
import { Button } from '@momots/design/components/button';
import { Menu, MenuItem, MenuSeparator } from '@momots/design/components/menu';

<Menu trigger={<Button variant='outline'>Project actions</Button>}>
  <MenuItem onClick={editProject}>Edit project</MenuItem>
  <MenuItem onClick={copyLink} shortcut='⌘C'>Copy link</MenuItem>
  <MenuItem disabled>Archive project</MenuItem>
  <MenuSeparator />
  <MenuItem variant='danger' onClick={confirmDelete}>Delete project</MenuItem>
</Menu>
```

Compose content from menu subcomponents. Regular items execute actions through `onClick`; `variant='danger'` only expresses a destructive action visually, leaving confirmation to the caller. `icon` accepts an icon node, `extra` displays supporting information such as the current value, and `shortcut` is a visual hint without registering a global shortcut. Set `aria-keyshortcuts` separately to declare shortcuts to assistive technology.

Menu items follow Select's column order: `[icon or spacer] [title / description] [optional supporting information] [indicator]`. Fixed-width icon and trailing indicator columns align titles across regular items, selectable items, submenus, and group labels. Column widths remain even when icons are absent, items are unchecked, or an indicator is hidden through a slot. Body text can wrap; long supporting information is truncated and limited to 40% of the available row width so it cannot consume the title area.

Checkbox and radio items can show both `shortcut` and a trailing `✓`. Submenu triggers show only `›`; display the current child value through `triggerProps.extra` without adding a `✓`. Both `extra` and `shortcut` may be supplied and are arranged in sequence in the supporting-information column.

## Container props

| Property | Default | Description |
| --- | --- | --- |
| `title` / `description` / `children` / `footer` | — | Heading, description, menu items, and footer; shares `ContentProps` with components such as Popover |
| `slots` | — | Node configuration for `header`, `title`, `description`, `content`, and `footer` |
| `trigger` | — | Trigger element or `(props, state) => JSX`; state includes `open` and `disabled` |
| `open` / `defaultOpen` | — / `false` | Controlled or uncontrolled open state |
| `onChange` | — | Non-cancelled open state change requests |
| `onOpenChange` | — | Full Base UI event; call `details.cancel()` to cancel the request |
| `size` | `md` | `sm` / `md` / `lg` adjusts item density; submenus inherit it |
| `side` / `align` | `bottom` / `start` | Popup direction and alignment, adjusted automatically at boundaries |
| `sideOffset` / `alignOffset` | `8` / `0` | Trigger spacing and alignment offset |
| `showArrow` | `false` | Show an arrow pointing to the trigger |
| `disabled` | `false` | Disable trigger interactions |
| `modal` | `true` | Restrict pointer interactions outside the menu and lock page scrolling; `false` allows external interactions |
| `className` | — | Popup styles, such as `w-56` for width |

Use `triggerProps`, `portalProps`, `positionerProps`, `popupProps`, and `arrowProps` for native attributes, refs, and Base UI configuration on the corresponding nodes. The trigger and positioner also accept `triggerClassName` and `positionerClassName`. Long menu bodies scroll automatically, with dimensions constrained by the available viewport.

## Content and nodes

`Menu` and `MenuSubmenu` inherit the same `ContentProps` and `ContentSlotsProps`, following the [Content Slots](/docs/design/content-slots) convention: content goes in top-level props, while `slots` configure the nodes holding it.

```tsx
<Menu
  trigger={<Button variant='outline'>Project actions</Button>}
  title='Workspace'
  description='Manage the current project.'
  footer={<MenuItem variant='danger' onClick={confirmDelete}>Delete project</MenuItem>}
  slots={{
    header: <header />,
    title: { render: <h3 />, id: 'workspace-menu-title' },
    content: (props, state) => <section {...props} />,
    footer: { render: <footer />, className: 'p-momo-xs' },
  }}
>
  <MenuItem onClick={editProject}>Edit project</MenuItem>
</Menu>
```

The five content nodes default to `div` and accept props objects, render elements, `(props, state) => JSX` callbacks, and `false`. Their `state` is an empty object. Callbacks must forward `props` to preserve content, refs, events, and default styles. `0` and empty strings are valid content; `undefined`, `null`, and `false` do not create content nodes.

Titles and descriptions automatically associate with the popup's `aria-labelledby` and `aria-describedby`. A nonempty ID on a render element takes precedence over the slot ID. `slots.header=false` hides both title and description. Without a visible title, the trigger continues to name the menu by default, or you can provide an accessible name through `popupProps`.

Long bodies scroll independently while the header and footer remain visible. The footer can contain explanatory text or `MenuItem` elements, which continue participating in keyboard navigation and highlighting. Use Popover for inputs or forms.

## Groups and links

```tsx
import {
  Menu, MenuGroup, MenuGroupLabel, MenuItem, MenuLinkItem, MenuSeparator,
} from '@momots/design/components/menu';

<Menu trigger={<button type='button'>Workspace</button>}>
  <MenuGroup>
    <MenuGroupLabel>Projects</MenuGroupLabel>
    <MenuItem onClick={createProject}>Create project</MenuItem>
    <MenuItem onClick={importProject}>Import project</MenuItem>
  </MenuGroup>
  <MenuSeparator />
  <MenuLinkItem href='/docs/design'>Component docs</MenuLinkItem>
</Menu>
```

`MenuGroupLabel` automatically associates with the nearest `MenuGroup` or `MenuRadioGroup`, providing an accessible name. `MenuLinkItem` defaults to `a`, preserving native link features such as `href` and `target`; use `render` to integrate a router link.

Regular items and links close the menu on click by default. Set `closeOnClick={false}` to keep it open.

## Radio and checkbox items

```tsx
const [notifications, setNotifications] = useState(true);
const [sort, setSort] = useState('date');

<Menu trigger={<Button>View settings</Button>}>
  <MenuCheckboxItem
    checked={notifications}
    onCheckedChange={setNotifications}
    shortcut='⌘⇧N'
    aria-keyshortcuts='Meta+Shift+N'
  >
    Receive notifications
  </MenuCheckboxItem>
  <MenuSeparator />
  <MenuRadioGroup value={sort} onValueChange={setSort}>
    <MenuGroupLabel>Sort by</MenuGroupLabel>
    <MenuRadioItem value='date'>Recently updated</MenuRadioItem>
    <MenuRadioItem value='name'>Project name</MenuRadioItem>
  </MenuRadioGroup>
</Menu>
```

Checkbox and radio items keep the menu open by default and also support `closeOnClick`. The second argument of `onCheckedChange` and `onValueChange` retains Base UI cancellation semantics. Radio values use `string | number | null`, consistent with other controls.

Use `defaultChecked` and `defaultValue` for uncontrolled initial values. Menu content unmounts after its exit animation, so uncontrolled items reinitialize on the next opening. To retain selection across openings, use the controlled approach above and keep state outside `Menu`.

## Submenus

```tsx
<Menu trigger={<Button>More actions</Button>}>
  <MenuItem onClick={editProject}>Edit project</MenuItem>
  <MenuSubmenu label='Export'>
    <MenuItem onClick={exportPDF}>PDF</MenuItem>
    <MenuItem onClick={exportCSV}>CSV</MenuItem>
  </MenuSubmenu>
</Menu>
```

`MenuSubmenu` accepts `label`, `icon`, and `triggerProps`, plus the same content, slots, size, positioning, and open-state props as `Menu`. By default it opens toward the inline end, which is right in LTR, with `sideOffset=4` and `alignOffset=-4`. Size is inherited from the parent menu unless specified separately.

```tsx
<MenuSubmenu
  label='Sort order'
  triggerProps={{ extra: sort === 'date' ? 'Recently updated' : 'Project name' }}
>
  <MenuRadioGroup value={sort} onValueChange={setSort}>
    <MenuRadioItem value='date'>Recently updated</MenuRadioItem>
    <MenuRadioItem value='name'>Project name</MenuRadioItem>
  </MenuRadioGroup>
</MenuSubmenu>
```

Arrow keys enter and leave submenus, and clicking a regular submenu item closes the entire menu tree. Escape closes only the current submenu by default; `closeParentOnEsc` also closes its parent. `triggerProps` configures hover delay, `openOnHover`, or a custom `render`. `triggerProps.slots` configures the trigger item inside the parent menu, while top-level `slots` configures the submenu popup content.

## Menu item content slots

Regular, link, checkbox, and radio items share `children`, `description`, `icon`, `extra`, `shortcut`, and content slots. `content` wraps the body and description; `description` is the description node within it. `extra` remains accessible text, while `icon`, `shortcut`, and indicators are hidden from assistive technology by default. Base UI's `aria-checked` expresses checked state.

| Component | Content slots | Render state |
| --- | --- | --- |
| `MenuItem` | `icon`、`content`、`description`、`extra`、`shortcut` | `highlighted`、`disabled` |
| `MenuLinkItem` | Same as above | `highlighted` |
| `MenuCheckboxItem` / `MenuRadioItem` | Same as above, plus `indicator` | Content nodes have `highlighted`, `disabled`, and `checked`; indicator has native states such as `checked` |
| `MenuSubmenu.triggerProps` | Same as above, plus `arrow` | `highlighted`, `disabled`, `open` |

```tsx
<MenuItem
  description='Update the name and project details.'
  icon={<ProjectIcon />}
  shortcut='⌘E'
  slots={{
    icon: { className: 'text-momo-fg-brand' },
    content: (props, state) => (
      <span {...props} data-active={state.highlighted} />
    ),
    shortcut: <kbd />,
  }}
  onClick={editProject}
>
  Edit project
</MenuItem>
```

Menu item slots also accept objects, elements, callbacks, and `false`, allowing you to replace only the icon, content, shortcut, or selection-marker container. `slots.content=false` removes both body and description; provide an accessible name separately when hiding visible content. Checkbox and radio indicators retain their space by default, while the internal check icon fades and scales with state. Forward `props.children` from a custom render to preserve this animation.

## RTL

Icons, body content, and indicators follow logical start / end directions. Set interaction direction with Base UI's `DirectionProvider` and set `dir` on the application container. The popup carries the provider direction into the Portal, mirroring submenu arrows and enter/back arrow keys accordingly.

```tsx
import { DirectionProvider } from '@base-ui/react/direction-provider';

<DirectionProvider direction='rtl'>
  <div dir='rtl'>
    <Menu trigger={<Button>Actions</Button>}>
      <MenuItem>Edit project</MenuItem>
    </Menu>
  </div>
</DirectionProvider>
```

## render and node customization

```tsx
<Menu
  trigger={(props, state) => (
    <button {...props} data-active={state.open}>Project actions</button>
  )}
>
  <MenuItem
    render={(props, state) => (
      <div {...props} data-active={state.highlighted} />
    )}
    icon={<ProjectIcon />}
    onClick={editProject}
  >
    Edit project
  </MenuItem>
  <MenuGroup>
    <MenuGroupLabel render={<span />}>Help</MenuGroupLabel>
    <MenuLinkItem href='/docs/design'>Documentation</MenuLinkItem>
  </MenuGroup>
</Menu>
```

Menu items, groups, labels, and separators support Base UI `render` elements or callbacks, state-based className, and refs. Callbacks should forward all `props`, including events, children, accessible attributes, and refs. Menu items default to `div`; also set `nativeButton` when switching to a native button. Supply a plain-text `label` for complex JSX labels to support typeahead navigation.

The popup's `render` is handled by the internal Motion node; customize other attributes through `popupProps`. The popup reuses `useFeel('ui')` for fade, subtle scale, and movement. Items reuse `Highlight` and `useFeel('snap')` for moving highlights; selection markers also use `snap`. Main menus, submenus, and separate footers each manage their highlight position and remeasure after scrolling or size changes. All motion respects the theme's reduced-motion settings. Pointer interactions are disabled during exit, and content unmounts afterward.

## Keyboard and usage boundaries

- Open the menu from the trigger with Enter, Space, or arrow keys.
- Move focus with up/down arrows, Home, and End; typeahead navigation is also supported.
- Enter or Space activates the current item; disabled items cannot execute actions.
- Escape closes the current menu and returns focus to the trigger; Tab closes the menu and continues focus navigation.
- Menu items should represent actions or options. Use [Popover](/docs/design/popover) for inputs, forms, and free-form layouts.

See [Base UI Menu](https://base-ui.com/react/components/menu) for underlying behavior.
