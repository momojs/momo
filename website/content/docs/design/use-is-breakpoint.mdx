`useIsBreakpoint` checks whether viewport width matches a breakpoint and updates when the result changes. Use it when available space changes interaction or rendered structure. Prefer CSS media queries for spacing, arrangement, or display-only changes.

## Playground

Change the breakpoint or browser width to observe the result. “Set to current viewport width” demonstrates inclusive boundaries: both `min` and `max` return `true` at the same breakpoint.

## Basic usage

```tsx
import { useIsBreakpoint } from "@momots/design/hooks";

function Navigation() {
  const compact = useIsBreakpoint("max", 768);

  return compact ? (
    <details>
      <summary>Navigation</summary>
      <nav aria-label="Main navigation">
        <a href="/docs/core">Core utilities</a>
        <a href="/docs/design">Components</a>
      </nav>
    </details>
  ) : (
    <nav aria-label="Main navigation">
      <a href="/docs/core">Core utilities</a>
      <a href="/docs/design">Components</a>
    </nav>
  );
}
```

You can also import from the dedicated subpath:

```ts
import { useIsBreakpoint } from "@momots/design/hooks/use-is-breakpoint";
```

Changing rendered structure may unmount children, losing local state or focus. Keep state that must survive breakpoint changes in a shared parent.

## Inclusive breakpoint boundaries

Breakpoints use **CSS pixels** and measure the viewport, not the component container. `min` / `max` match native CSS `min-width` / `max-width`; both include the boundary:

| Call | Condition | Width 767.5 | Width 768 | Width 768.5 |
| --- | --- | --- | --- | --- |
| `useIsBreakpoint("max", 768)` | `width <= 768px` | `true` | `true` | `false` |
| `useIsBreakpoint("min", 768)` | `width >= 768px` | `false` | `true` | `true` |

The implementation queries `(min-width: 768px)` or `(max-width: 768px)` directly, supporting fractional widths without subtracting one pixel. Both match at the boundary and are not complementary. For complementary branches, call the hook once and derive the other with `!matches`.

This differs from Tailwind's exclusive `max-*` upper bounds. The hook does not read Tailwind breakpoint configuration or convert `rem` to `px` automatically.

Width breakpoints cannot identify device type, touch input, or hover capability. Do not interpret a match as “the user is on a phone.”

## Server rendering and hydration

Servers have no actual viewport width, so the default result is `false`. The first client render taking over server HTML, **hydration**, uses the same fallback, then updates to the real browser match. Client-only mounting reads the actual match on its first render.

To initially show compact navigation on the server, specify `serverMatches`:

```tsx
const compact = useIsBreakpoint("max", 768, {
  serverMatches: true,
});
```

Server and client must pass the same `serverMatches`. It is a rendering fallback, not a locked result; layout may change after measurement. Environments without `matchMedia` keep using this fallback.

By default, both `min` and `max` return `false` during SSR because the viewport has not been measured. Use one query and `!matches` when branches must remain complementary.

## API

```ts
type BreakpointMode = "min" | "max";

interface UseIsBreakpointOptions {
  serverMatches?: boolean;
}

function useIsBreakpoint(
  mode?: BreakpointMode,
  breakpoint?: number,
  options?: UseIsBreakpointOptions,
): boolean;
```

| Parameter | Default | Description |
| --- | --- | --- |
| `mode` | `"max"` | Native `min-width` / `max-width` semantics, both inclusive |
| `breakpoint` | `768` | Finite non-negative CSS pixel value, optionally fractional; invalid values throw `RangeError` |
| `options.serverMatches` | `false` | Fallback for SSR, initial hydration, and missing `matchMedia` |

Changing `mode` or `breakpoint` reads the new query and replaces the listener; unmounting removes it.

Use [useResize](/docs/design/use-resize) to measure an element container.
