`Sheet` uses Base UI Dialog to display settings, details, or forms at the viewport edge. It opens from the right by default, with modal interaction, focus management, Esc/outside-click dismissal, and focus restoration.

<SheetPlayground />

The preview lets you change direction, modal mode, backdrop, and content length. Switching Modal disables the demo backdrop for non-modal and focus-trapping-only modes; Backdrop can also be changed separately. A Done button remains at the bottom so the panel can be closed when the top-right close button is hidden.

## Usage

```tsx
import { Dialog as BaseDialog } from '@base-ui/react/dialog';
import { Button } from '@momots/design/components/button';
import { Input } from '@momots/design/components/input';
import { Sheet } from '@momots/design/components/sheet';

<Sheet
  trigger={<Button>Workspace settings</Button>}
  title='Workspace settings'
  description='Change the workspace display name.'
  close={false}
  footer={
    <BaseDialog.Close render={<Button />}>
      Done
    </BaseDialog.Close>
  }
>
  <label className='grid gap-2'>
    Workspace name
    <Input defaultValue='Design workspace' />
  </label>
</Sheet>
```

Without `open`, Sheet manages its own state; `defaultOpen` sets the initial value and defaults to `false`. `trigger` composes an element through Base UI Trigger, adding opening semantics, keyboard interaction, and ARIA attributes.

The caller supplies footer content. There is currently no exported `SheetClose`; use `BaseDialog.Close` in the body or `footer`. It shares the panel's Root and works in uncontrolled mode. The example hides the top-right close node and closes with the footer's Done button.

## Direction and dimensions

`side` chooses the viewport edge and defaults to `right`:

| `side` | Default layout |
| --- | --- |
| `right` | Right-aligned, full viewport height; 3/4 viewport width, constrained by `max-w-sm` from the `sm` breakpoint |
| `left` | Left-aligned with the same dimensions as `right` |
| `top` | Top-aligned, full viewport width, content-defined height |
| `bottom` | Bottom-aligned, full viewport width, content-defined height |

Adjust dimensions with `popup.className`. For example, widen the right settings panel:

```tsx
<Sheet
  side='right'
  trigger={<Button>View details</Button>}
  title='Project details'
  popup={{ className: 'w-full sm:max-w-xl' }}
>
  Project details content
</Sheet>
```

The body uses `min-h-0 flex-1 overflow-y-auto`, so long content scrolls inside the panel. Top and bottom panels have no default maximum height; constrain it when needed to leave room for body scrolling:

```tsx
<Sheet
  side='bottom'
  trigger={<Button>Activity log</Button>}
  title='Activity log'
  popup={{ className: 'max-h-[80dvh]' }}
  slots={{ content: { className: 'space-y-3 pb-4' } }}
>
  {Array.from({ length: 20 }, (_, index) => (
    <p key={index}>Activity {index + 1}</p>
  ))}
</Sheet>
```

`popup.side` overrides the top-level `side`; normally set only the top-level prop. Sheet uses CSS opacity and translation transitions and has no dragging, swipe dismissal, or snap points. Use [Drawer](/docs/design/drawer) for these interactions, or [Dialog](/docs/design/dialog) for a centered dialog.

## Controlled state and dismissal

Use `open` and `onOpenChange` for controlled mode. Update `open` after a successful save to close the panel:

```tsx
import { useState } from 'react';

import { Dialog as BaseDialog } from '@base-ui/react/dialog';
import { Button } from '@momots/design/components/button';
import { Sheet } from '@momots/design/components/sheet';

function WorkspaceSettings({ save }: { save: () => Promise<void> }) {
  const [open, setOpen] = useState(false);
  const [saving, setSaving] = useState(false);
  const [error, setError] = useState('');

  async function handleSave() {
    setSaving(true);
    setError('');
    try {
      await save();
      setOpen(false);
    } catch {
      setError('Could not save. Please try again.');
    } finally {
      setSaving(false);
    }
  }

  return (
    <Sheet
      open={open}
      onOpenChange={(nextOpen, details) => {
        if (!nextOpen && saving) {
          details.cancel();
          return;
        }
        setOpen(nextOpen);
      }}
      trigger={<Button>Edit settings</Button>}
      title='Workspace settings'
      close={false}
      footer={
        <>
          <Button disabled={saving} onClick={handleSave}>
            {saving ? 'Saving…' : 'Save'}
          </Button>
          <BaseDialog.Close
            disabled={saving}
            render={<Button variant='secondary' />}
          >
            Cancel
          </BaseDialog.Close>
        </>
      }
    >
      Review the settings and save them to this workspace.
      {error && <p role='alert'>{error}</p>}
    </Sheet>
  );
}
```

Sheet uses Base UI's `onOpenChange(nextOpen, details)` directly, without an `onChange` shorthand. `details.reason` distinguishes `trigger-press`, `outside-press`, `escape-key`, `close-press`, and other reasons. Return immediately after `details.cancel()` to avoid updating controlled state.

The example prevents interaction-driven closing while saving. Calling `setOpen(false)` directly bypasses `onOpenChange`, allowing the success callback to close the panel. If your application requires a shared dismissal check, also run it before programmatic updates.

Use `disablePointerDismissal` to prevent outside-click dismissal. It does not prevent Esc or the close button; in non-modal mode it also prevents dismissal when focus leaves the panel. Run work after animation in `onOpenChangeComplete`.

## Modality and focus

| `modal` | Behavior |
| --- | --- |
| `true` (default) | Traps focus, locks page scrolling, and blocks pointer interaction outside the panel |
| `false` | Allows interaction with the rest of the page |
| `'trap-focus'` | Traps focus without locking scrolling or blocking outside pointer interaction |

`backdrop` independently controls the visible overlay and is enabled by default. `backdrop={false}` removes only the overlay, leaving `modal` focus and scrolling behavior unchanged. This wrapper does not automatically remove it with `modal={false}`. For an interactive sidebar, combine:

```tsx
<Sheet
  modal={false}
  backdrop={false}
  disablePointerDismissal
  trigger={<Button>View references</Button>}
  title='References'
>
  Continue using the page while viewing references.
</Sheet>
```

The example uses `disablePointerDismissal` to keep the sidebar open when focus leaves or the page is used. Esc and the close button still dismiss it.

Opening normally focuses the first focusable element. Touch opening prefers the panel itself to avoid immediately showing the virtual keyboard. Closing restores focus to the trigger or previously focused element. Set target refs or callbacks with `popup.initialFocus` / `popup.finalFocus`. Behavior follows [Base UI Dialog](https://base-ui.com/react/components/dialog).

Provide `title` so Base UI associates an accessible name; `description` adds optional context. Visually hide a title with `slots={{ title: { className: 'sr-only' } }}`, or name the popup with `popup={{ 'aria-label': 'Workspace settings' }}`. Keep a visible, named close action in modal panels. With `close={false}`, provide a replacement in the body or footer.

## Content slots

`title`, `description`, `children`, and `footer` are ReactNode content. `slots` configure their containers, attributes, and styles, following [Content Slots](/docs/design/content-slots).

```tsx
<Sheet
  trigger={<Button>Edit workspace</Button>}
  title='Workspace settings'
  description='Change the name shown in the workspace.'
  footer={<BaseDialog.Close render={<Button />}>Done</BaseDialog.Close>}
  slots={{
    header: { render: <header />, className: 'pr-16' },
    title: { render: <h3 /> },
    description: { className: 'text-momo-fg-muted' },
    content: { render: <section />, className: 'space-y-3' },
    footer: { render: <footer />, className: 'sm:flex-row sm:justify-end' },
  }}
>
  Panel body
</Sheet>
```

| Slot | Default content and layout |
| --- | --- |
| `header` | Vertical title/description container, with `p-4` by default |
| `title` | Base UI Title, the accessible heading |
| `description` | Base UI Description, the accessible description |
| `content` | Independently scrollable body with default horizontal padding `px-4` |
| `footer` | Action container with default `mt-auto flex flex-col gap-2 p-4` |

Omitting slot configuration uses the default node. Elements and render callbacks are also accepted as shorthand. `false` removes the node and content; `slots={{ header: false }}` removes both title and description. `undefined`, `null`, and `false` content create no node; `0` and empty strings remain valid.

`slots.content` wraps only the body, excluding the heading and footer. Render callbacks must forward received props to preserve `children`, IDs, ref, and events. Do not put body content in the slot configuration's `children`.

## Backdrop and close nodes

`backdrop` and `close` configure default nodes or replace them entirely:

| Configuration | Behavior |
| --- | --- |
| Omitted / `true` | Enables the default node |
| `false` / `null` | Removes the node |
| Props object | Configures the built-in Base UI node, preserving behavior |
| ReactNode | Replaces the entire node; backdrop or close behavior is not added automatically |

For a custom close button, prefer `render` inside a props object to retain Base UI Close interaction:

```tsx
<Sheet
  trigger={<Button>Open settings</Button>}
  title='Settings'
  backdrop={{ className: 'bg-black/30' }}
  close={{
    'aria-label': 'Close settings',
    render: <Button variant='ghost' size='sm'>Close</Button>,
  }}
  slots={{ header: { className: 'pr-16' } }}
>
  Panel body
</Sheet>
```

The default close node sits at the top right and currently has screen-reader-only `Close` text with no visible icon. Add visible text or an icon with `close.render`, reserving space in the header. `close={<Button>Close</Button>}` replaces the internal Close entirely and will not automatically dismiss the panel.

## Props

| Prop | Type | Default / Description |
| --- | --- | --- |
| `open` | `boolean` | Controlled open state, updated with `onOpenChange` |
| `defaultOpen` | `boolean` | `false`; uncontrolled initial state |
| `onOpenChange` | `(open, details) => void` | Base UI state change callback; inspect the reason or cancel |
| `onOpenChangeComplete` | `(open: boolean) => void` | Called after opening or closing animation completes |
| `trigger` | `DialogTriggerProps['render']` | Element or render callback that opens the panel |
| `side` | `'top' \| 'right' \| 'bottom' \| 'left'` | `'right'`; opening direction |
| `title` / `description` | `ReactNode` | Heading and description |
| `children` / `footer` | `ReactNode` | Body and footer content |
| `slots` | `SheetProps['slots']` | Configuration for header, title, description, content, and footer nodes |
| `popup` | `SheetProps['popup']` | Base UI Popup props plus `side`, excluding `children`; includes dimensions, styling, and focus configuration |
| `backdrop` | `SheetProps['backdrop']` | `true`; backdrop configuration or replacement node |
| `close` | `SheetProps['close']` | `true`; top-right close configuration or replacement node |
| `modal` | `boolean \| 'trap-focus'` | `true`; focus, scrolling, and outside interaction policy |
| `disablePointerDismissal` | `boolean` | `false`; prevents outside-click dismissal |

Other Base UI Dialog Root props are forwarded directly. Style the panel with `popup.className` and content areas with `slots`; Sheet Root renders no DOM node. The module exports `Sheet`, `SheetTrigger`, `SheetProps`, and `SheetContentSlots`. `SheetTrigger` must belong to the corresponding Base UI Dialog Root; use `trigger` for ordinary usage.
