`Combobox` builds on Base UI Combobox with the same option structure, dimensions, and theme tokens as `Select`. Use it for predefined options filtered by typed keywords; selection and input text are managed separately.

## Basic usage

```tsx
import { Combobox } from '@momots/design/components/combobox';

const options = [
  { value: 'react', label: 'React' },
  { value: 'vue', label: 'Vue' },
  { value: 'svelte', label: 'Svelte', disabled: true },
];

<label htmlFor='framework'>Framework</label>
<Combobox
  options={options}
  defaultValue='react'
  name='framework'
  placeholder='Search frameworks…'
  clearable
  emptyText='No matching results'
  slots={{ input: { id: 'framework' } }}
/>
```

Each option needs a unique string or numeric `value`. `null` means no single selection and cannot be an option value. `label` supports JSX; provide `textValue` for complex labels to support search and input display. Options also support `disabled`, `icon`, `extra`, `className`, and `style`.

Associate the input with a `label`, `Field.Label`, or `slots.input['aria-label']`; placeholders are only hints.

## Option layout

Options use four logical columns: `[icon or placeholder] [label] [optional extra information] [trailing check]`. `icon` is at the logical start, and `extra` sits between label and check. The icon column remains without an icon, and the trailing column remains when unchecked or `slots.itemIndicator={false}`, keeping labels aligned. Checks indicate selection without increasing font weight.

```tsx
<Combobox
  options={[
    { value: 'personal', label: 'Personal workspace', extra: 'Free' },
    { value: 'team', label: 'Team workspace', icon: <TeamIcon />, extra: 'Pro workspace for team collaboration' },
  ]}
  slots={{ input: { 'aria-label': 'Choose a workspace' } }}
/>
```

Labels and long extra information truncate to one line. `extra` takes at most 40% of available row width, leaving space for the label. Assistive technology can read its complete text. Icons and checks are decorative and hidden; Base UI's `aria-selected` communicates selection. Search, single-select input, and multi-select chip text come from `textValue` / `label`, excluding `extra`.

## Controlled and multiple selection

```tsx
const [value, setValue] = useState<string | null>(null);
const [values, setValues] = useState<string[]>(['react']);

<Combobox options={options} value={value} onChange={setValue}
  slots={{ input: { 'aria-label': 'Primary framework' } }} clearable />

<Combobox options={options} multiple value={values} onChange={setValues}
  slots={{ input: { 'aria-label': 'Frameworks used' } }} clearable />
```

Clearing sends `null` to `onChange` for single selection and `[]` for multiple selection. Multi-select chips can be removed with their buttons or the keyboard. `defaultValue` initializes uncontrolled state; callers update controlled `value`. `multiple` determines the value type; remount when changing modes.

`onValueChange(value, details)` runs before `onChange`; `details.cancel()` prevents both selection and the simplified callback. `open`, `defaultOpen`, and `onOpenChange` manage the popup; canceling `onOpenChange` prevents toggling. `disabled` disables interaction; `readOnly` keeps content readable but prevents changes.

## Search

Base UI text filtering is the default. `inputValue` / `defaultInputValue` and `onInputValueChange` manage search text; `value` manages selected options. Customize matching with `filter(value, query, itemToString)`; `filter={null}` disables local filtering.

For asynchronous search, drive requests with `inputValue` and `onInputValueChange`, then update `options`. Callers handle loading and request races and should retain selected option data for chip labels. Alternatively, keep all `options` and pass the visible option values through `filteredItems`.

`itemToStringLabel` overrides default `textValue` / string-label conversion. Forms submit raw option values; `itemToStringValue` customizes serialization.

## Custom nodes

`slots` uses content-slot normalization, accepting props objects, element shorthand, and `(props, state) => JSX`:

```tsx
<Combobox
  options={options}
  slots={{
    input: { 'aria-label': 'Framework', className: 'font-medium' },
    trigger: (props, state) => (
      <button {...props} type='button' data-expanded={state.open} />
    ),
    item: <div className='tracking-wide' />,
    clear: { 'aria-label': 'Clear selection' },
  }}
  renderOption={(option) => <span>{option.label}</span>}
/>
```

Configure `control`, `input`, `trigger`, `clear`, `item`, `itemIndicator`, `chip`, `chipRemove`, and `empty`. `trigger`, `clear`, `itemIndicator`, and `chipRemove` accept `false` to hide them. Forward props and ref in render callbacks to retain semantics, interaction, and positioning. `renderOption` replaces icon, label, and extra information across the first three columns; `itemIndicator` still manages the trailing check. Callers handle custom layout, truncation, and accessible text.

The suffix has one icon position. `trigger` and `clear` are transparent buttons over it; the component renders their icon without reading their `children`, so render callbacks need no icon or text. Only one button is mounted at a time:

| State | Suffix |
| --- | --- |
| `clearable`, a selection exists, and the input group is hovered or focused | `clear` (×) |
| Otherwise | `trigger`: down arrow when closed, up arrow when open |

Single selection is present when `value` is not `null`; multiple selection requires at least one chip. Search text alone is not a selection. Touch taps are not hover; focusing the input reveals clear for touch users. `disabled`, `readOnly`, or `slots.clear={false}` always shows the arrow. With `slots.trigger={false}`, no suffix appears unless clearing is available. Icons morph through [`Icon`](/docs/design/icon), switching directly with reduced motion.

`slots` follows [Content Slots](/docs/design/content-slots); top-level props still supply content. `emptyText` supplies empty-result content and `slots.empty` configures its node. With `undefined`, `null`, or `false` text, the empty-result node remains mounted without visible text so screen readers can announce result changes.

`className` applies to the whole input group. `portalProps`, `positionerProps`, `popupProps`, and `listProps` configure their layers; Motion controls popup rendering. Portal defaults to `body`; use `portalProps.container` for a locally themed container.

## RTL

Set interaction direction with Base UI `DirectionProvider` and the matching `dir` on the application container. The popup carries provider direction into its Portal, mirroring icons, extra information, and checks logically even when mounted to `body`.

```tsx
import { DirectionProvider } from '@base-ui/react/direction-provider';

<DirectionProvider direction='rtl'>
  <div dir='rtl'>
    <Combobox
      options={options}
      slots={{ input: { 'aria-label': 'Choose a framework' } }}
    />
  </div>
</DirectionProvider>
```

## Dimensions and positioning

| Property | Default | Description |
| --- | --- | --- |
| `size` | `md` | `sm` / `md` / `lg` |
| `clearable` | `false` | Switches the suffix to a clear button on hover/focus when a selection exists |
| `side` / `align` | `bottom` / `start` | Preferred popup direction and alignment |
| `sideOffset` / `alignOffset` | `6` / `0` | Positioning offsets |
| `emptyText` | `No results found.` | Content when there are no matching options |

Popup width follows the input group and is constrained by viewport space. Arrow keys navigate, Enter selects, and Escape closes; focus stays in the input.

Animation matches `Select`: the popup uses `useFeel('ui')`, entering from the anchor with `travel.hover` displacement and slight scale, and unmounting after exit. Reduced motion retains only opacity. A shared `Highlight` layer follows both keyboard and pointer selection; `highlightItemOnHover={false}` makes it follow only the keyboard.

Combobox selects predefined values; arbitrary input text cannot be submitted as an option. See [Base UI Combobox](https://base-ui.com/react/components/combobox) for complete interaction semantics.
